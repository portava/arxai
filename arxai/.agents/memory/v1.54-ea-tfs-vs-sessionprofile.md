EA v1.54 default-streams nine timeframes (`M1,M5,M15,M30,H1,H4,H8,D1,W1`) and the
server accepts all 21 native MT5 timeframes on both ingest paths, so
`broker_candles` now holds M30/H8/W1 rows directly (older EAs streamed only six).

BUT `sessionProfile.ts` `STORED_PROFILE_TIMEFRAMES` deliberately lists only the
fine-grained set `{M1,M5,M15,H1,H4,D1}`. The presence (completeness) profile is
built ONLY from that set, optionally DERIVED for a coarser timeframe via
`PROFILE_SOURCE_TIMEFRAME` (M30 ← M15, bucketed at the M30 interval). A timeframe
that is neither directly in the set nor derivable (H8, W1) gets NO profile:
`getSessionProfile` returns null and the caller (`candleNormalization.ts`) takes
the `else if (opts.sessionExpected === true)` fail-honest branch →
`missingCandleCount` stays 0 (never fabricates weekend gaps).

**Why:** the completeness profile only needs WHICH weekly slots an instrument
trades in; M15→M30 bucketing reproduces identical slot coverage and avoids false
weekend/DST gaps. The learned (never hardcoded Fri→Sun) profile underpins the
weekend-gap completeness fix.

**How to apply:** do NOT "fix" coarse-TF behavior by adding M30/H8/W1 to
`STORED_PROFILE_TIMEFRAMES`, or by switching M30 to read its own (sparser, newer)
rows — that risks regressing the gap calc, and for H8/W1 a profile changes
nothing. Verified live 2026-06-11 (EURUSD, mt5_broker, authed): M30/H1/H4/D1/H8
read clean + aiUsable=true; W1 reads `delayed`/aiUsable=false ONLY because its
current weekly bar is still forming mid-week (a FRESHNESS verdict,
missingCandleCount=0) — NOT a profile-coverage gap, so W1 needs no profile (1
slot/week). The comment text in `sessionProfile.ts` was updated to describe this
v1.54 sourcing; any LOGIC change must re-pass `test:chart-truth-fixtures`
(F42–F46) + `test:session-profile` and a live read first. If H8/W1 ever become
chart-selectable, confirm `TIMEFRAME_THRESHOLDS` covers them or they fall back to
strict 1m staleness.
