# Contract-Drift Audit — `lib/api-spec/openapi.yaml` vs mounted Express routes

**Auditor scope:** compare every operation in `lib/api-spec/openapi.yaml` (498 operations, 23,664 lines) against the routes actually mounted through `artifacts/api-server/src/routes/index.ts`, then spot-check the highest-traffic generated hooks used by the trading dashboard.

**Snapshot root:** `/private/tmp/claude-501/-Users-areyouok/a1620dc1-92f1-4ae2-97bc-c424ed64b487/scratchpad/arxai-zip/arxai`
(all `file:line` references below are relative to this root).

## 0. Method

- **Spec side:** scripted extraction of every `path` + HTTP method + `operationId` from the `paths:` block of `lib/api-spec/openapi.yaml` (indentation-based scan; the file is machine-generated with a uniform 2/4/6-space layout, verified by sampling e.g. lines 92–139). Spec `servers.url` is `/api` (`lib/api-spec/openapi.yaml:7`), so a spec path `/x` means URL `/api/x`.
- **Server side:** parsed `artifacts/api-server/src/routes/index.ts` for every `router.use(...)` mount (240 mounts, including 4 with a path prefix: `"/paper"` at index.ts:296, `"/paper/demo-execution"` at index.ts:297, `"/api"` at index.ts:428 and index.ts:432), then scanned each mounted file for `router.<get|post|put|patch|delete|all>("path", ...)` registrations with a multi-line-aware regex (Prettier splits many registrations across lines; a single-line scan produced 17 false "missing route" positives which were all eliminated after the fix). The whole routes index is mounted at `app.use("/api", router)` (`artifacts/api-server/src/app.ts:152`); `app.ts` registers no `app.get/post/...` routes of its own (verified by grep).
- **Comparison key:** `METHOD + normalized path` where Express `:param` and OpenAPI `{param}` are both canonicalized to `{}`.
- **Result counts:** 498 spec operations, 1,635 mounted route registrations (all unique after normalization), **494 matched**, **4 spec operations with no backing route**, **1,141 mounted endpoints absent from the spec**.
- Two in-file `router.use("<path>", x)` calls were inspected and confirmed to be middleware attachments, not sub-router mounts (`routes/propChallenges.ts:22` → `requireUser`; `routes/testerData.ts:26` → `requireAdmin`), so no sub-router path was missed.
- Machine-readable outputs: `scratchpad/audit-out/drift.json` (full 1,141-entry list), `scratchpad/audit-out/spotcheck.json`, produced by `scratchpad/audit-out/extract.js` and `spotcheck.js`.
- **Spec-vs-codebase language note:** no Python/TS conflict exists on this surface — the spec is consumed by the TypeScript orval codegen (`lib/api-client-react/src/generated/api.ts:1-7`, "Generated by orval v8.5.3") and the server is TypeScript Express. The spec's `/api` server URL matches the Express mount, so the comparison is apples-to-apples.

### 1.4 `POST /admin/handshake-monitor` — opId `refreshAdminHandshakeMonitor` — **SPEC PATH WRONG**

## 2. Mounted routes ABSENT from the spec (invisible to codegen/clients)

**1,141 of 1,635 mounted endpoints (69.8%) are not in the spec.** The contract covers less than a third of the real API. Three structural findings first, then the drift inventory.

### 2.1 Double-`/api` mounts — endpoints live at `/api/api/...` and a shipped dashboard card 404s

`routes/index.ts:428` and `:432` mount two routers with an extra `"/api"` prefix *inside* the router that `app.ts:152` already mounts at `/api`:

```ts
// routes/index.ts:428
router.use("/api", userReadinessRouter);
// routes/index.ts:432
router.use("/api", opportunityRadarRouter);
```

Express semantics: a request must therefore be `/api/api/<path>` to reach these handlers. Affected endpoints (13):

| Real (double-prefixed) URL | Handler |
|---|---|
| GET `/api/api/readiness/me` | `routes/userReadiness.ts:59` |
| GET `/api/api/readiness/me/blockers` | `routes/userReadiness.ts:70` |
| GET `/api/api/onboarding/me/progress` | `routes/userReadiness.ts:92` |
| POST `/api/api/onboarding/me/accept-disclosure` | `routes/userReadiness.ts:127` |
| POST `/api/api/onboarding/me/account-mode` | `routes/userReadiness.ts:166` |
| GET `/api/api/admin/readiness/users` | `routes/userReadiness.ts:188` |
| POST `/api/api/admin/readiness/users/:userId/approve-live` | `routes/userReadiness.ts:201` |
| POST `/api/api/admin/readiness/users/:userId/revoke-live` | `routes/userReadiness.ts:249` |
| GET `/api/api/opportunities/top` | `routes/opportunityRadar.ts:30` |
| POST `/api/api/opportunities/scan` | `routes/opportunityRadar.ts:46` |

**User-visible breakage:** `artifacts/trading-dashboard/src/components/readiness/TradingSetupReadinessCard.tsx:39` fetches `/api/readiness/me` (single prefix). That path matches nothing — `routes/readiness.ts` defines only `/readiness/status|run|reports|checklist|demo|export|integration/*` (readiness.ts:64-112), not `/readiness/me`. The card is rendered on the **main dashboard** (`pages/dashboard.tsx:216`, imported at :75) and permanently shows its error branch "Couldn't load readiness right now." (`TradingSetupReadinessCard.tsx:60-63`), refetching a 404 every 60s (`:44`). The slash-collapse middleware at `app.ts:24-32` only collapses `//`, it does not strip a duplicated `/api` segment.

None of the 13 endpoints appear in the spec under any prefix (grep for `readiness/me`, `onboarding/me`, `/opportunities` in `openapi.yaml` — only unrelated ruby-scalp/missed-opportunities matches).

**Repair (route fix, not spec fix):** change `routes/index.ts:428` and `:432` to `router.use(userReadinessRouter)` / `router.use(opportunityRadarRouter)` (matching every other mount). No path-collision blocks this: `/readiness/me` does not clash with `readiness.ts`'s `/readiness/*` set, and no other file defines `/opportunities` or `/watchlist/intelligence` (`watchlists.ts` uses `/watchlists/*`). Then add the 13 operations to the spec. The per-user readiness "14-status engine" is a P1-Discovery-relevant surface; it deserves typed hooks.

## 5. Caveats

- Route extraction is static; routes registered through dynamic path variables (none observed) would be missed. All 240 mounts and both in-file `router.use` calls were resolved explicitly.
- "Calls" in §3 counts static call sites, a proxy for traffic; actual request volume may rank differently, but every hook with ≥2 call sites was verified.
- The `__qa__` directories were excluded from consumer analysis (test mocks there mask finding 1.2 from the test suite, as noted).
