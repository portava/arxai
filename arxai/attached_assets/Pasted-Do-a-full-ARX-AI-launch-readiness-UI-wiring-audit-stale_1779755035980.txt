Do a full ARX AI launch-readiness UI wiring audit, stale-code cleanup, performance cleanup, and interaction repair pass.

This is a hard detailed pass. The goal is to make the entire app faster, cleaner, correctly wired, and launch-ready.

Important:
Do NOT rebuild the app from scratch.
Do NOT create duplicate systems.
Do NOT delete working features.
Do NOT fake backend data, fake provider status, fake balances, fake trading readiness, or fake API health.
Do NOT bypass trading safety gates, kill switches, approval gates, validation gates, or audit logs.
Do NOT expose backend constants, secrets, provider tokens, internal API names, debug labels, or raw errors to normal users.
Do NOT remove code unless you have proven it is unused, stale, duplicated, or wrongly routed.

Primary mission:
Go through every single page, tab, button, toggle, menu option, search bar, filter, dropdown, selector, card, modal, drawer, accordion, wizard step, admin panel, user panel, scanner section, Ruby section, trading section, provider/API section, MT5 bridge section, dashboard widget, and mobile navigation item.

Make sure every UI element:
1. Renders correctly.
2. Calls the correct backend route/service/config.
3. Uses the correct mode: live/demo/paper/admin/user.
4. Uses the correct data source.
5. Handles loading, success, empty, stale, disabled, error, and permission states cleanly.
6. Does not show false or stale errors.
7. Does not expose internal/backend details to normal users.
8. Actually works when clicked, toggled, typed into, selected, submitted, refreshed, or revisited.

Rollback and checkpoint safety:
Before starting:
1. Check git status.
2. Create a checkpoint/commit:
   checkpoint: pre-ui-wiring-performance-cleanup

If git is unavailable:
- Use Replit checkpoint/history if available.
- If no Replit checkpoint exists, create timestamped backup copies of files before changing them.

After each meaningful fix, create a checkpoint/commit with a clear message, such as:
- fix: wire scanner filters to market data router
- fix: clean stale route and duplicate component
- fix: repair admin toggle backend action
- fix: remove unused UI folder safely
- fix: speed app by removing duplicate fetch loops
- fix: route Ruby controls to active backend config

Do not make one huge untraceable change.

4. Repeated Ruby research calls for simple prompts.
5. Duplicate market data subscriptions.

8. Stale polling loops.
9. Over-fetching on tab switch.
10. Over-fetching on every keystroke in search bars.

12. Filters that refetch unnecessarily.
13. Components that re-render too often.
14. Large debug payloads loaded into normal user UI.
15. Heavy admin diagnostics loaded for normal users.
16. Large unused imports/packages.
17. Dead code included in production bundle.
18. Console logging large payloads.
19. TTS/audio jobs not cancelled when stale.
20. Historical data requests repeated unnecessarily.

Add safe debounce/caching where appropriate:
- search bars
- scanner filters
- market symbol search
- provider health refresh
- chart/history loads
- Ruby prompt supporting data
- watchlist refresh
- account balance refresh

Do not cache live trading validation in a way that weakens safety. Live dispatch must still revalidate at execution time.

Part 9: Fix strategy when one repair breaks another
If a fix breaks another feature:
1. Stop that approach.
2. Roll back only that specific change.
3. Identify why the dependency broke.
4. Repair at the shared source of truth instead of patching both ends.
5. Prefer small, reversible changes.
6. Add guards/adapters where needed.
7. Retest both the original bug and the feature that almost broke.
8. Save a checkpoint after the safe fix.

Do not leave regressions behind.
