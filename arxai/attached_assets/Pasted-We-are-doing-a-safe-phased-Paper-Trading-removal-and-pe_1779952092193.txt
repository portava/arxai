We are doing a safe, phased Paper Trading removal and performance cleanup for ARX AI.

The goal is to remove Paper Trading as a product feature, active mode, active data source, and active runtime path while preserving Live trading, Demo trading, and all live-execution safety protections.

This cleanup should make the app lighter, faster, cleaner, and easier to maintain. It must not damage the ready-launch state.

Core rule:
ARX AI should only support two production/user-facing trading modes:

1. DEMO
2. LIVE

Paper Trading should not exist as:

* user mode
* account mode
* trade mode
* auth mode
* permission mode
* scanner mode
* Ruby mode
* allocation mode
* dashboard mode
* active database mode
* active trade-history mode
* AI learning source
* performance source
* hidden backend fallback
* live-trade prerequisite
* live-trade blocker name
* demo-trade blocker name
* route gate
* feature flag
* admin setting
* onboarding state
* invite state
* trade execution state

However:
Do not weaken or delete live-execution safety gates. If any safety gate currently uses Paper terminology, preserve the safety behavior and rename/rebuild the vocabulary so it accurately describes what it does.

Safety meaning should be:
“Live trading is blocked unless all required live-execution gates pass.”

Safety meaning should NOT be:
“User is in Paper Mode.”

Acceptable replacement vocabulary:

* LIVE_EXECUTION_LOCKED
* BROKER_EXECUTION_LOCKED
* LIVE_COMMANDS_BLOCKED
* LIVE_PLACEMENT_DISABLED
* BROKER_PLACEMENT_DISABLED
* executionHardLock
* brokerPlacementLock
* liveCommandSafetyLock
* liveExecutionReadinessLock
* brokerExecutionReadinessLock

Do not do risky deep surgery just to remove a word. If renaming a safety constant would risk breaking live-readiness, create a safe compatibility layer first:

* keep behavior unchanged
* introduce the new accurate name
* update active code to use the new name
* keep a temporary deprecated alias only if required for tests
* remove the alias only after tests pass and no runtime dependency remains

Hard constraints:

1. Do not break Live trading.
2. Do not break Demo trading.
3. Do not weaken live-execution safety.
4. Do not delete live audit history.
5. Do not delete real broker demo history.
6. Do not blindly delete database rows.
7. Do not shotgun-delete directories.
8. Do not route Paper to Live.
9. Do not silently make old Paper users live-enabled.
10. Do not leave Paper as a hidden backend fallback.
11. Do not let fake/simulated Paper data feed Ruby, scanner, AI learning, calendar, journal, or performance reports.
12. Do not place real live trades during this cleanup unless I explicitly approve a specific live test.
13. If a change risks launch readiness, stop that part and find a safer workaround.
14. If something cannot be safely deleted now, disconnect it from active runtime and mark it as legacy for later removal.

Priority order:

1. Preserve Live trading functionality.
2. Preserve Demo trading functionality.
3. Preserve live-execution safety gates.
4. Remove Paper Trading from active/user-facing/product flows.
5. Remove fake/simulated Paper data from active Ruby/scanner/AI/journal/performance usage.
6. Reduce load and speed up the app.
7. Delete or rename legacy internals only when proven safe.
