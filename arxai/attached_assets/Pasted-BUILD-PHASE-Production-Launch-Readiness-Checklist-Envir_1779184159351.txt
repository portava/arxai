BUILD PHASE — Production Launch Readiness Checklist + Environment Lockdown

Use the current codebase. Do not rebuild unrelated systems.

Goal:
Prepare ARX AI for a safe production-style launch environment by locking down environment variables, secrets, live execution flags, admin access, database migrations, feature flags, test/prod separation, deployment checks, logs, monitoring, rollback readiness, and no-live-command safety evidence.

Important:
This phase should NOT turn on public live trading.
This phase should make sure production is locked down so live execution cannot accidentally happen unless every legal, admin, user, bridge, risk, disclosure, and safety gate is intentionally approved.

1. Inspect current environment/deployment setup first
Inspect:
- Replit environment variables
- production/staging/dev mode checks
- database connection handling
- migration system
- auth/session secrets
- OpenAI/Ruby keys
- market/news/calendar API keys
- MT5 bridge tokens
- bridge base URLs
- live execution flags
- admin bootstrap config
- feature flags
- logging config
- CI/test scripts
- health check routes
- deployment scripts
- current README/docs if any

Do not create duplicate config systems.

2. Environment separation
Create or harden clear environment modes:

- development
- test
- staging
- production

Each mode should have explicit behavior.

Development:
- demo allowed
- mock services allowed only when clearly marked
- live execution disabled by default

Test:
- no real live commands
- mock bridge only
- seeded test data allowed only inside test mode

Staging:
- production-like
- demo/sandbox only unless explicitly approved
- live execution disabled by default
- admin-only testing

Production:
- no mock user-facing data
- no fake trades
- no fake balances
- no debug panels for normal users
- no raw errors
- live execution disabled unless all required flags and approvals pass

3. Live execution environment lockdown
Verify and enforce:

- ARX_LIVE_BROKER_EXECUTION_ENABLED defaults false
- shared master live disabled by default
- one-click live disabled by default
- global one-click live disable respected
- close-only / kill switch states respected
- production shared master live blocked unless compliance approval flag is true
- production shared master live blocked unless admin explicitly approves user
- production live blocked if disclosure acceptance missing
- production live blocked if bridge mapping missing
- production live blocked if bridge health unknown/stale
- production live blocked if EA is read-only or live flag false
- production live blocked if queue paused or force-review active
- production live blocked if allocation/risk profile missing
- production live blocked if risk/exposure/cooldown fails

No live command should be created during this phase.

4. Required environment variables checklist
Create or update a safe startup check that reports missing required env vars without revealing their values.

Check for categories like:

Core:
- NODE_ENV / APP_ENV
- DATABASE_URL
- SESSION_SECRET
- APP_BASE_URL

AI/Ruby:
- OpenAI/API key config if used
- model config if used

Market data:
- market data provider keys
- news provider keys
- economic calendar keys if used

Bridge:
- MT5 bridge token/secret
- allowed bridge base URL
- bridge signing secret if used

Admin:
- bootstrap admin email/id if used
- admin role config

Safety:
- ARX_LIVE_BROKER_EXECUTION_ENABLED
- global live kill switch state
- shared master compliance approval flag
- one-click global disable flag

The startup check should show:
- present / missing
- required / optional
- environment scope
- safe setup note

Never print actual secret values.

5. Secret masking and leak protection
Verify/fix:
- no secrets in frontend bundle
- no secrets in API responses
- no secrets in logs
- no secrets in Ruby prompts
- no secrets in audit exports
- no secrets in Replit console output from health checks
- bridge evidence masking uses the centralized masking chokepoint
- CI/probes fail if a route exposes bridge tokens, API keys, session secrets, token hashes, account credentials, or raw bridge payloads

6. Production startup guard
Add a production startup guard that blocks unsafe startup or shows hard warnings if:

- SESSION_SECRET missing or weak
- DATABASE_URL missing
- admin auth not configured
- live flag enabled without compliance approval
- live flag enabled without kill switch system
- live flag enabled without disclosure enforcement
- live flag enabled without audit logging
- live flag enabled without bridge secret masking
- live flag enabled in test/dev accidentally
- mock data is enabled in production
- debug mode is enabled in production

Do not expose secret values.

13. Error handling lockdown
Ensure production errors:
- show clean user-facing messages
- do not show stack traces
- do not show raw SQL errors
- do not show raw bridge payloads
- do not show env variable names with values
- are logged safely for admin review

14. Public launch blockers
Add a clear admin-only launch blocker checklist.

Block public/live launch if:
- legal/compliance review incomplete
- disclosures missing or outdated
- live safety tests failing
- no kill switch

- no reconciliation workflow
- bridge masking not verified
- admin auth not locked
