Fix ARX live-feed truth and complete end-to-end live-trade support across every live-capable function.

Problem:
The chart visually matches other charts, but ARX still says:
- “Feed not confirmed”
- “Historical data — analysis only”
- “Data incomplete — not valid for a live entry”

This means the app may be displaying candles that look correct, but the live-entry gate cannot prove they are fresh broker-confirmed MT5 data for the exact tradable symbol. The system must truthfully support live trading through every function that allows live execution, and this task must not be marked complete until live test trades have been placed and verified through every supported entry point.

Important:
Do not fake completion with UI screenshots, typechecks, mocked broker responses, or “analysis-only” chart matches. Completion requires broker-confirmed live test order lifecycle proof.

Scope:
Audit, fix, and verify the entire live-trading path for:
- Chart trade/order ticket
- Market Scanner trade button
- Trade page/manual order ticket
- Eleanor chat trade command
- AI Trading
- Profit Engine
- Scalp Machine
- Flare Machine
- Any other screen/function that can create, confirm, draft, modify, close, or dispatch a live trade

If a function is not intended to place live trades, label it clearly as ALERT-ONLY / ANALYSIS-ONLY and remove or disable misleading live execution controls.

Primary goal:
The app must be either:
1. Fully live-capable and proven with real broker order lifecycle tests, or
2. Honestly labeled as not live-capable for that function.

No vague “Trading enabled” labels are allowed when an entry point cannot actually place a live order.

Part 1 — Live feed truth audit

1. Trace the full feed path
Trace V75_1S and at least one FX symbol from:
- MT5 EA / bridge payload
- tick ingestion
- CopyRates/bar ingestion
- backend candle storage
- feed confidence resolver
- chart candle endpoint
- scanner feed resolver
- Eleanor chart read
- AI/profit/scalp/flare strategy readers
- live order preflight feed gate
- liveCommandPipeline dispatch gate

Report:
- exact broker symbol
- normalized app symbol
- account id / bridge id
- source provider
- last tick timestamp
- last candle timestamp
- candle timeframe
- missing interval count
- freshness threshold
- why the current screen says “historical” or “incomplete”
- whether the issue is missing ticks, missing bars, stale timestamp, symbol mapping, timeframe gap, provider fallback, or resolver mismatch

2. Define broker-confirmed live feed
A symbol should be considered live-entry eligible only when:
- bridge heartbeat is fresh
- symbol exists on the connected broker account
- broker symbol mapping is exact
- recent MT5 tick exists
- recent MT5 CopyRates/bar exists for the selected timeframe
- timestamp is within the expected freshness window
- source is broker/MT5, not fallback, synthetic estimate, stale cache, or analysis-only provider
- missing intervals are within allowed tolerance
- the order route sees the same feed state as the chart/scanner/Eleanor UI

3. Fix false historical classification
If MT5 is providing fresh broker candles/ticks but ARX still says historical:
- fix timestamp parsing
- fix timezone/session offset
- fix symbol normalization
- fix brokerSymbol vs appSymbol mismatch
- fix timeframe aggregation gaps
- fix feedConfidence resolver mismatch
- fix stale cache fallback
- fix chart endpoint/provider labeling
- fix order route reading a different feed source than the chart

Do not loosen the live feed gate just to get trades through. Fix the proof so true live broker data is recognized correctly.

4. Remove misleading chart confidence
If the chart is showing candles that are not broker-confirmed, label it clearly:
“Analysis chart only — not broker-confirmed.”

If it is broker-confirmed, label it clearly:
“Broker-confirmed MT5 feed.”

Never show live trade controls as ready while the order route will reject the same feed.
