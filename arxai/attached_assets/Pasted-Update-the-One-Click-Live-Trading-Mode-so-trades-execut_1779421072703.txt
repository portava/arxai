Update the One-Click Live Trading Mode so trades execute instantly from anywhere in the ARX AI app, including Ruby AI text commands and Ruby voice commands.

Goal:
Approved users/operators should be able to place and close trades instantly from any trading surface in the app without a second confirmation modal, without a required stop loss, and without repeated live-money warning popups.

This applies to:
- Trade page
- Scanner page
- Market cards
- Watchlist
- Live chart page
- Position cards
- Dashboard/Cockpit
- Alerts
- Calendar/watch alerts
- Ruby AI chat
- Ruby voice command system
- Any future trade-capable widget

Important safety boundary:
Do not bypass backend approval, server live execution flag, live readiness, kill switch, max lot, daily loss limit, account approval, symbol allowlist, or bridge freshness.
Do not enable AI autonomous trading by default.
Ruby may execute instantly only when the user gives a clear direct trade command or when the user has explicitly enabled AI command execution mode.

Build this as a global instant execution system.

1. Add global Instant Trade Router

Create one shared frontend/backend trade execution path used by all app surfaces:

Frontend:
- instantTradeRouter.executeTradeIntent(intent)

Backend:
- POST /api/trades/instant/execute
- POST /api/trades/instant/close
- POST /api/trades/instant/close-all
- POST /api/trades/instant/validate

Every trade-capable UI must call the same instant router instead of creating separate modal flows.

Trade intent shape:
- source: "trade_panel" | "scanner" | "chart" | "watchlist" | "position_card" | "dashboard" | "alert" | "ruby_text" | "ruby_voice"
- action: "BUY" | "SELL" | "CLOSE" | "CLOSE_ALL" | "MODIFY_SL_TP"
- symbol
- volume
- orderType
- stopLoss optional/null
- takeProfit optional/null
- positionId optional
- userId
- accountMode: "live" | "demo" | "paper"
- oneClick: true
- aiCommand: boolean
- rawUserCommand optional
- parsedByRuby optional

2. Instant execution behavior

When oneClickLiveTradingEnabled=true:
- BUY button executes instantly.
- SELL button executes instantly.
- CLOSE button executes instantly.
- CLOSE ALL button executes instantly if enabled.
- Scanner trade buttons execute instantly.
- Chart trade buttons execute instantly.
- Watchlist trade buttons execute instantly.
- Position-card close buttons execute instantly.
- Ruby command trades execute instantly when AI command trading is enabled.

Do not show:
- per-trade confirmation modal
- “Are you sure?” popup
- confirmation checkbox
- stop loss required message
- large repetitive real-money warning modal

Keep only small persistent status badges:
- LIVE READY
- READY TO ARM
- LIVE DISABLED
- ACCOUNT NOT APPROVED
- KILL SWITCH ACTIVE
- CLOSE ONLY

3. Ruby AI command execution

Add Ruby AI trade command support.

Ruby should understand direct commands like:
- “Buy EURUSD 0.01”
- “Sell EURUSD 0.01”
- “Open a market buy on EURUSD with 0.01 lots”
- “Close my EURUSD trade”
- “Close all open trades”
- “Close all profitable trades”
- “Close all losing trades”
- “Set take profit on my EURUSD trade to 1.0920”
- “Move stop loss to break even”
- “Buy Volatility 75 1s with 0.01”
- “Sell XAUUSD 0.02”

Ruby must convert the user command into a structured trade intent.

If the command has enough information:
- execute instantly through the global instant trade router
- no confirmation modal
- no extra “are you sure?” question

If the command is missing required information:
- use saved defaults where available:
  defaultSymbol
  defaultVolume
  defaultOrderType
- if still missing critical information, Ruby should ask only for the missing value, not show a trade warning.

Example:
User: “Ruby, buy EURUSD”
If defaultVolume is 0.01, execute immediately.
If no defaultVolume exists, ask:
“What lot size should I use?”

4. Add AI command execution setting

Add user/operator setting:
- aiInstantTradeCommandsEnabled: boolean
- defaultAiTradeVolume
- defaultAiTradeSymbol
- defaultAiOrderType
- allowRubyCloseCommands: boolean
- allowRubyOpenCommands: boolean
- allowRubyModifyCommands: boolean

Default:
- aiInstantTradeCommandsEnabled=false
- allowRubyCloseCommands=true for approved users
- allowRubyOpenCommands=false until manually enabled by approved operator
- allowRubyModifyCommands=true for approved users

Approved operator/admin can enable AI instant trade commands from live trading settings.

When enabled:
- Ruby text commands can instantly place trades.
- Ruby voice commands can instantly place trades.
- Ruby can close trades instantly by voice/text.
- Ruby must never place a trade from vague conversation.
- Ruby executes only clear direct trading instructions.

5. Prevent accidental AI trades without adding confirmation popups

Do not use confirmation modals.

Instead use command clarity rules:
Ruby may execute only if the command has clear action intent:
- buy
- sell
- open
- close
- close all
- close position
- move stop loss
- set take profit
- modify order

Ruby must not execute from vague questions like:
- “What should I trade?”
- “Is EURUSD good?”
- “Do you think I should buy?”
- “Where is this going?”
- “Find me a setup”

For vague questions, Ruby should answer/analyze only.

For clear commands, Ruby executes instantly if all backend gates pass.

6. Backend live execution requirements stay strict

The instant execute endpoint must require:
- authenticated user
- user approved for master live trading
- user.liveTradingEnabled=true
- user.oneClickLiveTradingEnabled=true
- if source is ruby_text or ruby_voice: aiInstantTradeCommandsEnabled=true
- serverLiveExecutionEnabled=true
- kill switch inactive
- real LIVE bridge, not MOCK
- fresh EA heartbeat
- EA v1.27+
- ReadOnlyMode=false
- EnableLiveExecution=true
- terminalConnected=true
- algoTradingAllowed=true
- volume <= user.maxLiveLot
- daily loss limit not breached
- symbol allowed
- order type allowed
- account approved for this bridge/shared account

Do not require:
- stop loss
- take profit
- per-order confirmation phrase
- per-order confirmation checkbox
- repeated warning modal

7. Orders without SL/TP

Allow:
- stopLoss: null
- takeProfit: null

No blocking validation if SL/TP are blank.

Keep optional SL/TP fields available for users who want them.

8. Global one-click close system

Every live position card/row must have:
- CLOSE button

POST /api/trades/instant/close

- block new/open/increase-risk orders
- allow reduce-only close orders if the backend/EA supports safe close
- show CLOSE ONLY badge
