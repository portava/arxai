Plan the ARX v2 Kernel Multi-Symbol Market Watch Streaming Upgrade.

The latest diagnostic confirms the v2 kernel is genuinely connected and broker candles are arriving. Real CANDLE events are accepted, judged LIVE-fresh, and fed into mt5Provider for USDCHF M5. So the bridge is not dead.

The real limitation is operational/design-based:
- The kernel only streams the symbol/timeframe of the chart it is attached to: _Symbol + chart period.
- Right now that means USDCHF M5 only.
- Other forex/metals/indices still fall through to assistant/third-party fallback because the kernel is not pushing their broker candles/quotes.
- Volatility works separately through Deriv WebSocket, not because MT5 is feeding all markets.
- Heartbeat/account/positions can stream every ~10s while candles only push when the attached symbol gets ticks/new bars.

We need to evolve the v2 kernel from single-chart streaming into controlled multi-symbol Market Watch streaming.

Do not rebuild live execution.
Do not change order execution behavior.
Do not weaken Risk Governor, AACI, Security Handshake, or trade command gates.
Do not fake candles.
Do not use simulator candles.
Do not let third-party feeds become execution truth.
Do not silently scan all possible broker symbols without limits.
Do not overload MT5, the backend, or provider quotas.

==================================================
PRIMARY GOAL
==================================================

Make the v2 kernel push broker-native quotes and candles for multiple approved ARX markets, not only the chart it is attached to.

Target behavior:
- MT5 broker feed becomes available for approved forex/metals/indices/crypto/stocks/commodities if broker supports them.
- Kernel uses Market Watch / approved symbol list / active app demand to decide what to push.
- Backend stores candles by symbol + timeframe.
- Router prefers mt5_broker when fresh broker data exists.
- Fallback providers remain backup only.
- User UI shows only approved Top 250 markets, and only selectable when real data exists.

STEP 2 — DESIGN A CONTROLLED SYMBOL UNIVERSE FOR THE KERNEL
==================================================

Do not stream every broker symbol blindly.

The kernel should use a controlled list:

Priority A — open-position symbols:
Always push quotes and candles for symbols with open positions.

Priority B — active UI symbols:
Symbols currently selected by users in chart/scanner/Ruby/watchlist.

Priority C — approved Top 250 core:
Only approved ARX Top 250 symbols that are broker-supported and enabled.

Priority D — admin-configured watchlist:
Admin may choose a subset for continuous streaming.

The kernel should not push markets outside approved ARX Top 250 unless admin diagnostics explicitly allow it.

==================================================
STEP 4 — KERNEL MARKET WATCH LOOP
==================================================

Modify the kernel design so it can iterate configured symbols.

For each configured broker symbol:
- verify SymbolSelect(symbol, true)
- verify symbol exists in Market Watch
- read bid/ask/spread with SymbolInfoDouble / SymbolInfoInteger
- push quote snapshot
- for each configured timeframe, call CopyRates
- push initial backfill
- push incremental candles when a new bar appears
- avoid pushing duplicate unchanged bars excessively
- track last pushed candle time per symbol/timeframe
- track push errors per symbol/timeframe

Important:
Do not rely only on OnTick for the attached chart.
Use OnTimer for multi-symbol scanning so quiet attached chart does not stop all market data.

Suggested:
- OnTimer every 1–5 seconds for quote snapshots
- candle check every 5–15 seconds depending timeframe
- new-bar detection per symbol/timeframe
- throttle by maxSymbolsPerCycle
