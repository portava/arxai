Build PP = Controlled Paper Testing Launch Mode + Session Manager.

Goal:
Create a controlled paper-testing session system that lets the trader safely start, manage, monitor, end, and review structured paper trading sessions.

The session manager should turn the app from “many powerful tools” into one clean workflow:

Preflight check →
Start paper session →
Run AA/EE/FF safely →
Monitor trades and risk →
End session →
Generate session report →
Update coach/readiness/notifications/audit

Important:
Build PP must NOT place live trades.
Build PP must NOT enable live trading.
Build PP must NOT call MT5 live execution.
Build PP must NOT modify canPlaceTrades.
Build PP must NOT expose API secrets.
Build PP must NOT recommend live trading.
Build PP is paper-session workflow, launch gating, operating discipline, and reporting only.

Before any session starts, PP must check:

OO Readiness Gate:
- overallStatus must be PASS or PASS_WITH_WARNINGS
- canProceedToPaperTesting must be true
- canProceedToLiveTrading must always be false

HH Risk Governor:
- paperTradingAllowed must be true
- liveTradingAllowed must be false
- allowedActions.canPlaceLiveTrade must be false

NN Security:
- role/permission system working
- user has permission to start paper session
- forbidden actions blocked
- secrets redacted

KK Broker/Data:
- broker mode READ_ONLY
- live trading disabled
- market data mode read_only
- no unsafe broker mode

LL Notifications:
- no unacknowledged CRITICAL alerts unless session is explicitly blocked
- safety alerts active

FF Autopilot:
- must be PAPER_ONLY
- live_trading_allowed false
- can only start if session settings permit it

If any hard block exists, return BLOCKED and explain why.

5. Session states

Support:

- READY
- ACTIVE
- PAUSED
- ENDED
- BLOCKED
- FAILED

Rules:
- Only one ACTIVE session at a time.
- Cannot start if another ACTIVE session exists.
- Cannot resume ENDED session.
- Cannot paper execute if session is BLOCKED.
- Manual paper close should still be allowed for safety.
- Session can be paused automatically by HH/OO/LL hard block.
- Session can be ended manually.

6. Integrate with FF paper autopilot

During an ACTIVE session:
- FF may run only if session allows autopilot
- FF must check PP session status before run-once/start
- if PP is not ACTIVE, FF should not open new paper trades
- if session hits limits, FF pauses/stops
- PP records autopilot cycles that happened during session

7. Integrate with EE paper execution

Before opening a paper trade:
- EE checks PP active session if session enforcement is enabled
- if no active session, reject or require explicit override setting for manual demo only
- if session trade limit hit, reject
- if session loss limit hit, reject
- if consecutive loss limit hit, reject
- if same-symbol limit hit, reject
- if active session exists and allows manual paper trades, allow only if HH/OO/NN approve

8. Integrate with BB and CC

When paper trades close inside a session:
- BB auto-debrief should still trigger
- CC learning should still process once
- PP should attach debrief/learning results to session report
- PP should track lessons and mistakes per session
