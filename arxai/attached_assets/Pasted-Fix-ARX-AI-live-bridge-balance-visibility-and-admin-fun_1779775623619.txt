Current problem:
The live MT5 account has a balance, but the app/admin allocations system is not showing the amount registered to the live bridge. Because the admin cannot see the master/live bridge balance, there is no clear way to distribute that balance to users.

This must be fixed.

Goal:
Admin should see the real live bridge/master MT5 account balance, equity, free margin, currency, and last sync time. Then admin should be able to distribute/allocate part of that available live bridge balance to approved users.

Important distinction:
1. Master/live bridge balance = actual money in the connected MT5 live account.
2. Distributable headroom = master live balance/free margin minus existing allocated/reserved exposure.
3. User allocation = the amount admin assigns to a user from the master bridge.
4. User available capacity = assigned allocation minus used/reserved exposure.
5. Paper/demo balance must not affect any of the above.

   - remaining headroom

Task 5 — Fix master.configured logic:
master.configured should not depend on hiding balance.

Correct states:
- Live bridge balance available, but no users allocated → show balance and “No users allocated yet.”
- User allocated, but risk caps incomplete → show “Risk caps required.”
- User allocated and complete → show ready state only if all other gates pass.
- Account sync stale → show balance stale warning and block actions requiring fresh data.
- No account snapshot → show “Waiting for live account sync.”
