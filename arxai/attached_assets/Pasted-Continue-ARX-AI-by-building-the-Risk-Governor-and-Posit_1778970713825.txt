Goal:
Create a central Risk Governor that decides whether a user is allowed to open, close, partial close, move stop, or modify a trade before any command reaches MT5.

Important:
Do not auto-place trades.
Do not auto-close trades.
Do not bypass backend guards.
Do not expose secrets.
All live actions still require explicit user confirmation.

PART 1 — Central Risk Governor Service

Create a central service named something like:

- riskGovernor
- tradingRiskEngine
- orderRiskValidator

It must validate every trading action before command queue insertion.

The Risk Governor should check:

1. User status
- user authenticated
- user trading enabled
- user not suspended
- user has permission for demo/live
- live disclosure accepted for live
- explicit confirmation exists for live

2. Platform status
- platform mode is not Trading Off
- emergency stop is false
- demo/live mode matches requested action
- account routing mode is valid

3. Account status
For USER_OWNED_MT5:
- user has connected MT5 account
- account type matches platform mode
- account balance/equity available
- margin data available if possible

For SHARED_MASTER_MT5:
- shared master account exists
- shared master account type matches platform mode
- user has virtual account/allocation
- master account has enough capacity
- user does not exceed allocation

4. Trade risk
- lot size within max lot size
- daily max trades not exceeded
- daily loss limit not exceeded
- max open trades not exceeded
- max symbol exposure not exceeded
- allowed symbols only
- allowed direction if configured
- duplicate command rejected
- expired command rejected

5. Market risk if data exists
- spread too high
- volatility too high
- market closed
- symbol unavailable
- high-impact news warning if available
- stale MT5 data
- stale market data

6. Position risk
- user already exposed to same symbol
- correlated exposure if available
- trade would increase drawdown risk
- trade conflicts with current open position
- shared master netting conflict if account is netting
