Correction:
Do NOT use collapsible "Why Ruby thinks this" sections.

Ruby must show one full, properly labeled reasoning block directly inside:
- Scalp Builder card
- Scanner result card
- Opportunity Map detail/card
- Ruby Chat response
- Ruby Chart Read
- Trade setup card
- Auto-bot proposed trade review

Goal:
A trader should immediately see Ruby's full reasoning without opening anything extra.

Required format:
Every Ruby buy/sell/wait/no-trade/scalp/retest answer must include one visible reasoning block with clearly labeled lines.

Standard Ruby Reasoning Block:

Decision:
- Conditional SELL scalp / BUY setup / WAIT / NO TRADE / TOO LATE / AVOID

Why:
- The main reason Ruby leans that way.

Evidence:
- Structure:
- Momentum:
- Pattern:
- Support/Resistance:
- Feed/Data:
- Risk:

Confirmation:
- The exact condition that makes the idea stronger.

Invalidation:
- The exact condition that cancels the idea.

Trader Test:
- One or two simple things the trader can check on the chart to confirm or reject Ruby's read.

Risk Note:
- The biggest reason not to force the trade.

Compact example:
Decision: Conditional SELL scalp
Why: Price is fading near resistance, but the broader chart read is low-confidence.
Evidence:
- Structure: Short-term lower highs favor sellers.
- Momentum: Upside momentum is cooling.
- Pattern: Possible continuation, not fully confirmed.
- Support/Resistance: Price is close to support, so room is limited.
- Feed/Data: Live feed confirmed.
- Risk: Selling into support can bounce fast.
Confirmation: Sell strengthens only if price stays below 1.14709 and breaks 1.1454 with momentum.
Invalidation: Cancel the sell if price reclaims and holds above 1.14709.
Trader Test: Mark 1.1454 support and watch whether the next candle breaks or rejects it. Do not chase if price stalls at support.
Risk Note: This is a conditional scalp, not a full-confidence trade.

Rules:
1. No collapsible UI.
2. No hidden reasoning behind "expand."
3. No vague answer like "BUY because bullish."
4. Use labeled lines every time.
5. Keep it compact enough for a card, but complete enough to test.
6. If data is limited, say that inside Feed/Data.
7. If chart confidence is low, say that inside Risk or Why.
8. If near support/resistance, always mention it.
9. If news/calendar provider is missing, say "news/calendar unavailable," not "low risk."
10. If answer is WAIT, explain exactly what Ruby is waiting for.
11. If answer is NO TRADE, explain what would need to change.
12. If answer is TOO LATE, explain what made it late.
13. This reasoning block does not grant live execution permission.
