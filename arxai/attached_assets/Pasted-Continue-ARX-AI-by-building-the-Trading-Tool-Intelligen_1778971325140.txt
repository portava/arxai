PART 2 — Tool Selection Engine

Build a Tool Selection Engine that decides which tools to use based on the user’s question.

Examples:

If user asks:
“Where is my trade going?”
Use:
- market context
- trend tools
- support/resistance
- momentum
- volatility
- open trade P&L
- exit plan

If user asks:
“Is this a pullback or reversal?”
Use:
- market structure
- trend alignment
- Fibonacci retracement if candle data exists
- support/resistance
- momentum divergence
- invalidation level
- fakeout/reversal score

If user asks:
“When should I close?”
Use:
- MFE/MAE
- profit giveback
- close urgency
- support/resistance
- exit plan
- event risk
- trade efficiency
- user trading style

If user asks:
“Should I enter?”
Use:
- setup quality
- strategy playbook
- trend alignment
- risk/reward
- spread
- broker rules
- news/session risk
- Risk Governor

If user asks:
“Why did I lose?”
Use:
- journal
- entry quality
- exit quality
- alerts ignored
- risk logs
- strategy performance
- market context at entry/exit

PART 3 — Indicator Calculation Engine

Add indicator calculation support using real candle data only.

Supported indicators:
- SMA
- EMA
- RSI
- MACD
- Bollinger Bands
- ATR
- Stochastic if feasible
- Pivot levels if feasible
- Fibonacci levels from real swing high/low

Rules:
- If candle data is missing, return unavailable.
- If timeframe data is stale, mark stale.
- Do not invent indicator values.
- Do not calculate indicators from fake/sample candles.
- Store data quality with every result.

PART 4 — Tool Output Explanation

Every tool result should include:
- result
- plain-English meaning
- confidence score
- data quality
- timeframe used
- why it matters
- what would invalidate it

Example:
“RSI on M15 is elevated, which means momentum is stretched. This does not mean price must reverse, but it increases pullback risk if price also rejects resistance.”

PART 5 — Confluence Engine

Build a confluence engine that combines tools.

Confluence should detect:
- trend + momentum agreement
- support/resistance + candle rejection
- Fibonacci + structure alignment
- breakout + volume/tick confirmation if available
- overextension + profit giveback
- event risk + volatility expansion
- high spread + low liquidity
- strategy setup match + risk pass

Output:
- bullish confluence score
- bearish confluence score
- exit confluence score
- risk confluence score
- setup confluence score
- data quality

Labels:
- Strong bullish confluence
- Weak bullish confluence
- Strong bearish confluence
- Weak bearish confluence
- Mixed signals
- No clear edge
- Data insufficient

PART 6 — AI Tool-Aware Responses

Update AI so it can say exactly what tools it used.

AI response format:
1. Direct answer
2. Tools used
3. What each tool showed
4. Conflicting signals
5. Key level to watch
6. Risk warning
7. Suggested review action
8. Data quality

Example:
“Based on M15 trend structure, ATR, support/resistance, and your open P&L, this looks more like a pullback than a full reversal right now. The key level is 1.08420. If price breaks below that level, reversal risk increases.”

AI must not:
- pretend it used tools it did not use
- invent indicator values
- hide missing data
- guarantee direction
- place or close trades without confirmation
