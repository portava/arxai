BUILD PHASE — Bug Fix Sprint + Launch Candidate Freeze

Use the current codebase. Do not rebuild unrelated systems.

Goal:
Turn the current ARX AI build into a stable launch candidate by fixing only confirmed bugs, safety blockers, privacy leaks, failed tests, broken routes, broken mobile layouts, broken Ruby flows, and launch-critical issues. Do not add new major features in this phase.

Important:
This is a stabilization/freeze phase.
Do not fire demo or live trades unless using safe mock/demo flows already approved by the test suite.
Do not create real live bridge commands.
Do not turn on public live trading.
Do not bypass any safety gate to make tests pass.

1. Inspect the full staging dry-run report first
Review the output from:
- full staging dry run
- production lockdown QA
- audit/export QA
- reconciliation QA
- close-only QA
- kill switch QA
- Ruby voice QA
- shared master ledger QA
- onboarding QA
- scanner/trade QA

Create a launch-blocker list grouped by:

Critical blockers:
- live safety failures
- user privacy leaks
- admin access leaks
- secret exposure
- live command created unexpectedly
- broken auth/session
- broken bridge safety
- broken kill switch
- broken queue/concurrency
- broken ownership checks

High blockers:
- failed core user flow
- failed admin flow
- failed Ruby assistant flow
- failed demo trading flow
- failed disclosure/risk acceptance
- failed audit export
- failed reconciliation workflow
- failed mobile-critical flow

Medium blockers:
- confusing UI text
- missing empty states
- mobile layout issues
- unclear error messages
- missing audit coverage
- incomplete manual test steps

Low blockers:
- polish issues
- minor copy cleanup
- non-critical warnings
- future TODOs

2. Fix only launch-critical issues
Fix:
- failing tests
- broken routes
- broken APIs
- broken UI states
- broken mobile layouts
- broken admin protection
- broken user privacy filters
- broken Ruby context scoping
- broken voice state cleanup
- broken audit masking
- broken export protection
- broken readiness checks
- broken kill switch enforcement
- broken close-only enforcement
- broken reconciliation states
- broken disclosure acceptance enforcement
- broken environment startup guards

Do not add new features.
Do not redesign unrelated sections.
Do not rewrite working systems.
Do not silence tests without fixing the cause.
Do not remove safety checks to make tests pass.

3. Freeze feature surface
After critical/high blockers are fixed:
- mark current feature set as Launch Candidate
- prevent accidental feature expansion
- create a launch candidate version identifier
- create or update release notes
- create or update known issues list
- create or update manual QA checklist
- create or update rollback notes
- create or update deployment checklist
- create or update environment checklist

Suggested version label:
ARX_AI_LAUNCH_CANDIDATE_0.1

Confirm:

- setup/status works
- live blocked unless every safety/disclosure/env gate passes

Shared Master:
- request/approval/allocation works
- normal users do not see master totals
- live blocked unless compliance/admin/allocation/risk/mapping/bridge/safety gates pass

Production:
- live execution defaults OFF
- mock data hidden
- feature flags fail closed
- secrets masked
- admin routes protected

- one-click live defaults OFF

- missing disclosure blocked

- unmapped shared master blocks live

- Ruby cannot bypass trade safety
