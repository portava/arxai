Update the ARX AI Flame Scalp system with a dedicated Run-On Candle Momentum upgrade.

The goal is to improve scalp detection for one of the strongest scalp conditions: aggressive same-direction candle movement with minimal pullbacks. These are “run-on candles” — candles that keep driving in the same direction, showing clean momentum, continuation pressure, and little hesitation.

Do not rebuild the app. Do not rewrite the entire algorithm. Do not change live broker execution settings. Do not place trades. This is a surgical upgrade to the existing Flame Scalp engine, Scanner scoring, Ruby explanation, Risk review, and Governance challenge logic.

MAIN CONCEPT

Some of the best scalps happen when candles run aggressively in one direction without too many pullbacks.

The system must recognize when price is moving like this:

- several candles pushing in the same direction
- strong candle bodies
- small opposite wicks
- limited pullbacks
- clean continuation
- little chop
- little hesitation
- not too stretched yet
- enough room before major structure/support/resistance
- spread/slippage still acceptable
- momentum still alive

This should be identified as a special scalp opportunity called:

Run-On Candle Momentum

PHASE 2 — DEFINE RUN-ON CANDLE MOMENTUM

Create or refine a clear Run-On Candle Momentum detector.

A run-on candle setup should evaluate:

1. Directional persistence
- consecutive bullish candles for buy pressure
- consecutive bearish candles for sell pressure
- direction stays consistent across the recent window
- minimal candle color flipping
- minimal alternating chop

2. Candle body strength
- strong bodies relative to recent average candle size
- bodies expanding or staying consistently strong
- close near high for bullish run
- close near low for bearish run
- limited doji/indecision candles

3. Pullback control
- pullbacks are shallow
- pullbacks do not break momentum structure
- pullbacks do not erase too much of the prior candle move
- no deep retracement against the run
- no repeated hesitation candles

4. Wick quality
- small opposing wicks
- no large rejection wick against the trade direction
- no repeated wick rejection near the entry side
- no exhaustion wick that warns the run is ending

5. Momentum cleanliness
- clean candle progression
- low chop
- no fake breakout signal
- no sudden reversal candle
- no heavy overlap between candles
- price is actually traveling, not just vibrating in place

6. Room to scalp
- enough distance before nearby support/resistance, liquidity zone, session high/low, or danger zone
- spread/slippage does not eat the scalp
- stop loss has a logical invalidation point
- take profit has a realistic target before the run stalls

PHASE 3 — RUN-ON STAGE CLASSIFICATION

Upgrade the flame stage/rating so run-on candles are clearly classified.

Use or map to existing stages if they already exist:

- NONE: no real scalp momentum
- DEVELOPING: early movement but not clean enough yet
- ACTIVE: momentum is present and tradable with caution
- RUN_ON: clean same-direction aggressive candle run
- RUNAWAY: extremely strong run but may require caution due to chase risk
- EXHAUSTED: momentum stretched too far or fading
- FAILED: setup broke down
- REVERSAL_RISK: strong warning of possible reversal
- BLIND: not enough candle data to judge honestly

If existing enum names are different, do not force a full rename. Preserve current compatibility and add display mapping where needed.

PHASE 4 — RUN-ON QUALITY SCORE

Add or improve a run-on quality score.

The score should consider:

- number of same-direction candles
- body-size consistency
- body-size expansion
- opposite wick size
- pullback depth
- candle overlap
- close position inside candle range
- momentum acceleration
- distance already traveled
- distance remaining before danger zone
- spread/slippage condition
- candle freshness
- data quality/freshness

The score must not blindly reward long moves. A move that is too stretched should start shifting from RUN_ON/RUNAWAY into EXHAUSTED or REVERSAL_RISK.

PHASE 5 — ENTRY TIMING LOGIC

Run-on candles need timing intelligence.

Classify entry timing as:

- early run: possible best entry if confirmation is enough
- active run: tradable if risk/reward still makes sense
- late run: caution, reduced confidence
- chase risk: avoid or small caution only
- exhausted: no new entry
- reversal warning: no entry or exit warning
- pullback re-entry: possible re-entry if shallow pullback holds
- continuation re-entry: possible add-on if run resumes cleanly

The system should clearly know the difference between:
- catching the run
- joining the run
- chasing the run
- stacking into exhaustion

PHASE 6 — MULTI-TRADE RUN-ON ADD-ON RULES

Upgrade multi-trade scalp logic specifically for run-on candles.

Allow add-ons only when:

- stage is RUN_ON or strong ACTIVE
- direction remains consistent
- pullbacks remain shallow
- opposite wicks remain controlled
- spread/slippage remains acceptable
- the move is not exhausted
- risk/exposure allows it
- previous add-ons remain within cap
- new candle confirms continuation

Do not allow add-ons when:

- EXHAUSTED
- FAILED
- REVERSAL_RISK
- BLIND
- late/chase-risk state
- candle flips against direction
- strong rejection wick appears
- pullback becomes too deep
- spread/slippage becomes too large
- risk/reward no longer makes sense

Keep existing usedAddOns cap. Do not bypass risk controls.

PHASE 7 — RISK / STOP LOSS / TAKE PROFIT FOR RUN-ON SCALPS

Run-on scalps should not use generic long-trade logic.

For run-on scalps, review:

- stop loss should sit beyond logical momentum invalidation
- stop loss should account for broker spread/bleed
- stop loss should not sit unrealistically right at entry
- take profit should target a realistic continuation zone
- take profit should account for nearest danger zone
- reward-to-risk must still make sense
- risk should shrink as chase/exhaustion risk increases
- if the move is too late, scanner/Ruby should recommend avoid or caution

Ruby should explain:
- why the run is strong
- whether it is early, active, late, or exhausted
- where the danger is
- what would invalidate the scalp
- whether add-ons are allowed or not
- why stop loss/take profit make sense

PHASE 8 — SCANNER RANKING IMPACT

Wire Run-On Candle Momentum into Scanner ranking.

If run-on quality is strong:
- scanner score can increase
- flame/scalp confidence can increase
- Ruby can call it a clean run-on scalp
- trade recommendation can become stronger if risk allows

If run-on quality is weak/late/exhausted:
- scanner score should decrease
- risk warning should increase
- Ruby should warn against chasing
- governance can downgrade the signal

Scanner should never rank a late/exhausted run-on move as a high-quality scalp just because candles were moving fast.

PHASE 9 — GOVERNANCE CHALLENGES

Update governance so agents can challenge run-on scalps.

- move is too late
- stop loss is unrealistic
- reward-to-risk is weak
- spread/slippage is too high
- account exposure is too high

Market Structure Agent should challenge if:
- run is heading into strong support/resistance
- move is too stretched
- structure does not support continuation

Flame Scalp Agent should challenge if:
- pullbacks are too deep
- opposite wicks are too large
- candle overlap is too heavy
- momentum is choppy
- run is exhausted

Traffic Controller should avoid calling unnecessary agents on every candle, but allow deeper review for high-score run-on opportunities.
