Build CC = Learning Feedback Engine.

Goal:
Use the learning payload created by Build BB to update future trade setup scoring. This is the part that closes the loop:

Build AA decides →
paper trade closes →
Build BB auto-debriefs →
Build CC learns from the result →
future Build AA decisions read the updated edge data.

Important:
Build CC should NOT place trades.
Build CC should NOT change live broker logic.
Build CC should NOT make unsafe automatic trading decisions.
Build CC should only update scoring intelligence, signal weights, mistake patterns, confidence calibration, and decision edges used by future AA calls.

Core requirement:
When Build BB produces a learning payload with ready_for_learning: true, Build CC should process it exactly once and update the system’s internal scoring memory.

Learning payload expected from BB:

{
  trade_id,
  decision_id,
  result,
  pnl,
  mistake_tags,
  lesson,
  confidence_before_trade,
  risk_score_before_trade,
  signals_used,
  debrief_id,
  ready_for_learning: true
}

3. Build an idempotent learning processor

Create a Build CC service that:
- accepts a BB learning payload
- checks if trade_id / debrief_id / decision_id was already processed
- if already processed, returns existing learning event
- if not processed, creates a learning event
- updates strategy edge memory
- updates mistake pattern memory
- prepares updated scoring adjustments for future AA decisions

Idempotency rule:
The same trade/debrief should never update learning twice.

4. Learning logic

For each learning payload:

If result is WIN:
- increase edge_score slightly for signals that supported the winning decision
- improve confidence_adjustment modestly
- reduce risk_adjustment if risk was controlled
- increase win_count and sample_count

If result is LOSS:
- decrease edge_score modestly for signals that supported the losing decision
- add/increase mistake pattern tags
- increase risk_adjustment if risk was high
- reduce confidence_adjustment if confidence was high but trade lost
- increase loss_count and sample_count

If result is BREAK_EVEN:
- small or neutral update
- do not overreward or overpunish
- increase break_even_count and sample_count

If result is CANCELLED:
- do not update strategy edge strongly
- log operational lesson only
- mark as low learning impact

5. Add learning safety rails

Build CC must avoid overfitting.

Rules:
- One trade can only create a small adjustment.
- Edge score must have min/max boundaries.
- Confidence adjustment must have min/max boundaries.
- Risk adjustment must have min/max boundaries.
- Small sample sizes should be marked as low confidence.
- Bad outlier trades should not destroy a strategy by themselves.
- Never convert learning directly into live trade permission.
- Never change safetyCore.canPlaceTrades.
- Never bypass Build AA safety blockers.

6. Wire Build CC into Build BB

- call the Build CC learning processor
- only if ready_for_learning === true

- if CC processing fails, BB should still preserve the debrief and log a warning
- CC errors should not crash the trade-close flow
