Feature name:
Ruby Scalp Signals

Main goal:
Ruby should automatically detect, rank, explain, and help build scalp trade opportunities inside both Focus Scan and Broad Scan.

The scanner should not only show general market analysis. It should also answer:
1. Is there a scalp opportunity here right now?
2. Is it ready, forming, late, invalid, or not clean?
3. What target profit is realistic?
4. What lot size fits the user’s target and risk amount?
5. What market gives the cleanest scalp right now?
6. Should the user enter, wait, or avoid?
7. Can Ruby build the trade with lot, entry, stop loss, and take profit?

PART 3 — SCALP STATUS LABELS
====================================================

Every scalp result must use clear status labels:

READY
- Clean setup is available now.
- Entry is not late.
- Spread is acceptable.
- TP is reachable.
- SL has logical invalidation.
- Risk/reward is acceptable.

FORMING
- Setup is close but not ready.
- User should wait for entry zone, breakout, retest, candle close, or confirmation.

WAIT_FOR_ENTRY
- Direction is valid but current price is not ideal.
- Ruby should show the exact zone to wait for.

LATE
- Price already moved too far toward TP.
- Warn user not to chase.

INVALID
- Setup broke structure.
- Do not recommend entry.

NO_CLEAN_SCALP
- No reasonable scalp exists right now.

SPREAD_TOO_WIDE
- Spread makes the scalp unattractive or dangerous.

NEWS_DANGER
- News/current event risk is too high for clean scalp entry.

MARKET_CLOSED
- Symbol cannot be traded right now.

SYMBOL_NOT_TRADEABLE
- Broker or symbol trade mode prevents trading.

INSUFFICIENT_MARGIN
- User amount/free margin cannot support recommended trade.

====================================================
PART 7 — SCALP MODE LOGIC
====================================================

Implement scalp modes with different scoring weights.

Sniper Scalp:
- highest entry quality
- waits for clean zone
- must have strong invalidation
- avoids late entries
- lower number of signals

Safer Scalp:
- prioritizes lower risk
- tighter drawdown
- better spread
- lower volatility danger
- may suggest smaller profit target

Fast Scalp:
- prioritizes immediate movement
- valid for short timer
- more sensitive to momentum
- stronger chase warnings

Momentum Scalp:
- trend continuation
- breakout/retest
- moving with current pressure

Reversal Scalp:
- rejection zones
- overextended move
- divergence/reversal candle if available
- must require clear invalidation

Any:
- engine chooses best setup based on current market

PART 8 — LOT SIZE / TP / SL GENERATION
====================================================

Ruby must generate lot size, TP, and SL using real symbol specs and account constraints.

Lot size must consider:
- user target profit
- user risk/use amount
- account balance
- account equity
- free margin
- symbol contract size
- tick value if available
- point size
- digits
- min lot
- max lot
- lot step
- broker stop distance if available
- spread
- TP distance
- SL distance
- estimated margin
- volatility

Never produce a lot size outside min/max/step.

If calculated lot is below min lot:
- explain that the target cannot be cleanly achieved with that amount on that symbol
- either suggest a different symbol or a lower target

If calculated lot exceeds max lot or margin:
- reduce lot or reject setup
- show clean explanation

TP must be based on:
- user target profit
- nearby support/resistance
- current volatility
- realistic scalp movement
- spread cost
- current price and direction

SL must be based on:
- market structure invalidation
- not directly at entry
- spread buffer
- recent swing high/low
- volatility buffer
- broker minimum stop distance

SL must not be random.
SL must not be so tight that normal spread/noise instantly hits it.

Reward-to-risk must be calculated and displayed.

If reward-to-risk is poor, Ruby should reject or label the setup as aggressive.
