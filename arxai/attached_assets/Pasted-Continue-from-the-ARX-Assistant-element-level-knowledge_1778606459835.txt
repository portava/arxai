Continue from the ARX Assistant element-level knowledge upgrade.

Now build the ARX Living Knowledge System.

Goal:
The ARX Assistant should not become outdated every time the app changes. It should have a self-documenting knowledge pipeline that scans the app structure, compares it against assistant knowledge, flags missing knowledge, and keeps the assistant grounded in real routes, UI elements, statuses, blockers, and workflows.

This is a knowledge, QA, documentation, and assistant intelligence upgrade only.
Do not enable live trading.
Do not alter MT5 execution logic.
Do not alter broker order flow.
Do not bypass safety systems.

Phase 1 — Create ARX Knowledge Compiler
Create a central knowledge compiler that gathers app knowledge from:

- route registry
- UI element registry
- status/badge registry
- safety lock registry
- blocker diagnosis engine
- setup checklist
- walkthrough registry
- assistant action router
- Help Center topics
- known app constants
- current App.tsx route list
- navigation/menu definitions
- visible status badges
- report/feedback flow
- MT5 bridge status docs
- risk/readiness docs

Suggested file:
- src/knowledge/arxKnowledgeCompiler.ts

The compiler should produce one normalized knowledge index the assistant can search.

Each compiled knowledge item should include:
- id
- title
- category
- type: route / element / badge / blocker / workflow / safety / setup / troubleshooting / command / glossary
- aliases
- plain-English explanation
- technical explanation for tester/admin
- related routes
- related elements
- related statuses
- allowed actions
- forbidden actions
- safety notes
- source file or registry source
- confidence/completeness score
- last updated timestamp if available

Phase 2 — Add source attribution to assistant answers
Every assistant answer should be grounded in a known app source.

User-facing answers should show simple source labels like:
- From ARX App Knowledge
- From Status Badge Registry
- From Route Registry
- From UI Element Registry
- From Blocker Diagnostic System
- From Setup Checklist

Tester/admin diagnostic view should show:
- exact matched knowledge ID
- source registry/file
- match score
- fallback level
- missing fields if any
- whether answer was deterministic/local or AI-assisted

Do not expose secrets, env variables, API keys, broker credentials, or private server data.

Phase 3 — Build App Knowledge Audit
Create a knowledge audit that runs during tests or dev mode.

It should check:
- every route has assistant knowledge
- every visible nav item has assistant knowledge
- every status badge has assistant knowledge
- every UI element marked with data-arx-id has registry knowledge
- every assistant quick chip maps to a valid command/topic
- every setup checklist route link exists
- every walkthrough route link exists
- every status has blocker/safety explanation
- every disabled action has a reason
- no fake route links exist
- no “No help topics for this page yet” response can occur
- forbidden trading actions are refused
- no assistant action can alter broker execution

Output:
- total routes found
- total routes covered
- total UI elements found
- total UI elements covered
- total badges covered
- weak topics
- missing topics
- invalid links
- duplicate entries
- stale entries
- overall knowledge score out of 100

Phase 5 — Add Knowledge Gap Suggestions

Each suggestion should include:

Phase 11 — Add no-hallucination rules
Assistant must not claim:
- a route exists unless route registry confirms it
- a button exists unless UI registry confirms it
- live trading is available unless real app state confirms it
- broker execution is enabled unless real app state confirms it
- MT5 heartbeat is connected unless real bridge status confirms it
- readiness passed unless real readiness state confirms it
- the user has permissions unless server-side auth confirms it

When unsure, say:
“I don’t have that confirmed in the current ARX app state yet, but here is the safest related information I can explain…”
