We are changing ARX AI bridge architecture so the app can operate from ONE centralized MT5 account/bridge instead of requiring every user to connect their own MT5 account.

Do not break the current per-user bridge system yet. Add this as a new optional architecture mode.

Feature name:
Centralized Master MT5 Bridge Mode

Goal:
Only the platform/operator connects one MT5 account with one EA. Users trade through ARX, and ARX routes approved commands through the master bridge while keeping per-user attribution, risk limits, command history, position mapping, and P/L tracking inside the app.

IMPORTANT SAFETY:
For now, build this as DEMO-FIRST and COMPLIANCE-LOCKED for LIVE.
Do not allow pooled real-money user trading through the master live account until a compliance/legal approval flag exists.

PART 1 — BRIDGE MODE SETTING

Add a platform setting:

bridgeMode:
- PER_USER_BRIDGE
- MASTER_BRIDGE_DEMO
- MASTER_BRIDGE_LIVE_LOCKED
- MASTER_BRIDGE_LIVE_ENABLED

Default:
PER_USER_BRIDGE

Add admin-only UI to switch mode.

If MASTER_BRIDGE_DEMO is selected:
- users do not need to connect MT5
- all demo trade commands route to the active platform master demo bridge

If MASTER_BRIDGE_LIVE_LOCKED:
- UI can preview master live trading
- live commands remain blocked

If MASTER_BRIDGE_LIVE_ENABLED:
- only available after compliance approval, master switch, kill switch clear, live unlock, and risk gates pass

PART 3 — ROUTING LOGIC

Create a routing layer:

resolveTradeExecutionBridge(userId, mode)

Rules:
1. If bridgeMode=PER_USER_BRIDGE:
   use the user's own MT5 bridge.
2. If bridgeMode=MASTER_BRIDGE_DEMO:
   route demo commands to the active platform demo master bridge.
3. If bridgeMode=MASTER_BRIDGE_LIVE_LOCKED:
   block live commands with:
   MASTER_LIVE_BRIDGE_LOCKED
4. If bridgeMode=MASTER_BRIDGE_LIVE_ENABLED:
   route live commands only if all compliance/risk/live gates pass.

Do not allow frontend-only routing decisions. Server must enforce this.

PART 5 — POSITION ATTRIBUTION

Every trade placed through the master bridge must be mapped back to the user.

Use:
- broker_ticket
- command_id
- user_id
- virtual_account_id
- magic number if EA supports it
- order comment containing ARX command id

EA order comment format:
ARX|user:{userId}|cmd:{commandId}|src:{source}

If MT5 broker truncates comments, still store mapping server-side by command id and ticket.

PART 6 — HEDGING VS NETTING ACCOUNT HANDLING

Detect account margin mode:

If MT5 account is HEDGING:
- allow separate positions per user where broker supports it
- map each broker ticket to one ARX command/user

If MT5 account is NETTING:
- warn admin:
  “Netting accounts merge same-symbol positions. ARX must use internal allocation accounting.”
- do not promise one broker ticket per user position
- maintain internal allocation ledger
- show users virtual allocated positions, not raw broker net position only

PART 7 — RISK CONTROLS

Add per-user risk controls even though the master account is shared:

- max lot per user
- max open trades per user
- max daily loss per user
- max symbol exposure per user
- max total platform exposure per symbol
- max total master account exposure
- stop loss required
- duplicate command protection
- cooldown after rejected/failed orders
- emergency platform kill switch

If any user exceeds risk limits, block only that user’s command, not the whole bridge.

If master account exposure limit is reached, block all new commands with:
MASTER_ACCOUNT_EXPOSURE_LIMIT_REACHED

PART 8 — COMPLIANCE LOCK FOR LIVE MASTER ACCOUNT

Add compliance gate:

masterLiveComplianceApproved=false by default

Master live trading must remain blocked unless:
- masterLiveComplianceApproved=true
- ARX_LIVE_BROKER_EXECUTION_ENABLED=true
- live kill switch inactive
- master EA v1.27+ heartbeat fresh
- AccountType REAL/LIVE
- ReadOnlyMode=false
- EnableLiveExecution=true
- user is approved for live
- user accepted live risk disclosure
- stop loss present
- max lot/risk limits pass

If master live is not compliance approved, block with:
MASTER_LIVE_COMPLIANCE_LOCK

Add admin warning:
“Using one live MT5 account for multiple users may create regulatory, custody, allocation, and managed-account obligations. Do not enable without legal/compliance approval.”
