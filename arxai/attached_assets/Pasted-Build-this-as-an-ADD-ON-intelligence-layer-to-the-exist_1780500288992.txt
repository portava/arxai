Build this as an ADD-ON intelligence layer to the existing ARX AI system. Do not rebuild the app. Do not replace Ruby, the scanner, live trade flow, MT5 bridge, live execution paths, existing database, existing users, existing admin system, or existing trading features. This task is to add a governed self-growing AI agent ecosystem on top of the current system.

IMPORTANT:
This is not a redesign.
This is not a rewrite.
This is not a separate app.
This is not paper trading.
This is not a simulation feature.
This must integrate into the current live ARX AI system and current Ruby/scanner/trade review architecture.

Goal:
Create the ARX AI Agent Ecosystem: a self-improving AI workforce where multiple AI agents work under Ruby, earn promotions, lose authority, go to Learning Camp, create new specialist agents when needed, step back when they slow the system, and improve trade decision quality over time. Ruby remains the main user-facing AI voice. The other agents can operate behind the scenes unless their output is needed.

Core principle:
Agents are rewarded for QUALITY, PROTECTION, SPEED, DISCIPLINE, and USEFULNESS — not for calling more trades.

Agents should be rewarded for:
- Finding high-quality trade opportunities
- Rejecting bad trades
- Warning Ruby about danger
- Identifying late/chase entries
- Protecting capital
- Knowing when to say “no trade”
- Being fast
- Stepping back when their input is not needed
- Creating useful child agents only when a real task gap exists
- Improving after Learning Camp

Agents should be penalized for:
- Low-quality trade calls
- Chasing candles late
- Ignoring major support/resistance
- Bad risk/reward
- Calling trades too close to danger zones
- Overconfidence
- Repeating another agent’s work
- Slowing the scanner or live execution unnecessarily
- Creating duplicate/useless agents
- Failing to step back when not needed
- Repeating mistakes after Learning Camp
- Trying to influence live recommendations before earning authority

Build the following system.

1. AGENT ECOSYSTEM FOUNDATION
====================================================================

Add an internal agent ecosystem layer with the following default core agents if they do not already exist:

1. Ruby
Role: Lead Trading Desk Manager and user-facing AI voice.
Purpose: Coordinate all agent opinions, speak clearly to the user, summarize trade logic, and present only useful information.

2. Market Structure AI
Role: Reads higher timeframe structure.
Purpose: Trend, range, support/resistance, breakout, reversal, major zones, higher timeframe bias.

3. Scalp AI
Role: Detects scalp opportunities.
Purpose: Flame candle runs, one-stick to several-stick momentum, fast continuation, pullback continuation, quick exit setups, multi-entry scalp possibilities.

4. Risk AI
Role: Safety guardian.
Purpose: Risk/reward, overexposure, late entries, bad zones, max loss risk, danger warnings, and veto power.

5. Entry Timing AI
Role: Entry quality specialist.
Purpose: Clean entry, early/late/chase detection, retest logic, candle timing, confirmation rules.

6. Exit / TP AI
Role: Exit specialist.
Purpose: Realistic take profit zones, partial TP, trailing logic, scalp exit versus hold logic, invalidation zones.

7. Scanner AI
Role: Opportunity scout.
Purpose: Search across symbols/timeframes and bring forward the best opportunities only.

8. Trade Review AI
Role: Report card and truth-review system.
Purpose: Grade all agent predictions after the market plays out.

9. Agent Traffic Controller AI
Role: Speed and workflow governor.
Purpose: Decide which agents should run for each situation so the system stays fast.

10. Agent Immune System AI
Role: Ecosystem health protector.
Purpose: Detect duplicate, useless, slow, reckless, bloated, or mission-drifting agents.

11. Learning Camp AI
Role: Retraining system.
Purpose: Retrain underperforming agents and return them only after improvement.

12. Agent Factory AI
Role: Controlled agent creation.
Purpose: Allow qualified agents to create new specialist agents from templates without outside coding.

13. Promotion Board AI
Role: Rank and authority manager.
Purpose: Evaluate promotions, demotions, authority changes, Learning Camp placement, and shutdown recommendations.

14. Execution AI
Role: Live execution flow monitor.
Purpose: Ensure AI reasoning does not block or slow live trade execution paths.

Use existing AI/provider services already in the app where possible. Do not add a completely separate AI stack unless required. Reuse current Ruby infrastructure wherever possible.

5. TRADE REVIEW AND SCORING ENGINE
====================================================================

Create a scoring engine that reviews agent predictions after enough market movement or trade result data exists.

Score separately:

A. Decision Quality Score
Was the agent’s reasoning professional before the outcome?

B. Outcome Score
Did price behave as expected?

C. Protection Score
Did the agent protect the user from bad trades?

D. Speed Score
Did the agent provide value without slowing the system?

E. Usefulness Score
Did the agent’s input actually change or improve the final decision?

F. Calibration Score
Did confidence match reality?

Reward points:
- Clean setup identification
- Good entry timing
- Good risk/reward
- Correct support/resistance awareness
- Correct trade type classification
- Realistic TP/SL
- Correct no-trade decision
- Correctly blocking a bad setup
- Correctly downgrading a weak setup
- Correctly admitting uncertainty
- Fast useful output
- Stepping back when not needed

Penalty points:
- Late/chase entry
- Ignoring major support/resistance
- Bad risk/reward
- Overconfidence on weak setup
- Wrong trade type
- Unrealistic TP
- No invalidation
- Trade immediately violates invalidation
- Duplicate analysis
- Slow output with low decision impact
- Repeating mistakes after Learning Camp
- Creating unnecessary agents
- Failing to step back
- Mission drift

Important:
A winning trade can still receive a poor decision score if it was reckless or lucky.
A losing trade can still receive a decent decision score if the setup was clean and properly invalidated.
Do not reward profit alone.

====================================================================
7. LEARNING CAMP
====================================================================

Add Learning Camp as retraining for underperforming agents.

Agents enter Learning Camp when:
- They repeatedly fail their mission
- They repeat the same mistake pattern
- They slow the system without enough value
- They create poor child agents
- They fail after warning/probation
- Risk AI or Promotion Board recommends retraining

Learning Camp stages:

1. Failure Review
Identify exactly what went wrong.

2. Pattern Correction
Create correction rules based on mistakes.

3. Replay Training
Review historical trades/signals where the agent failed.

4. Shadow Mode
Agent watches live markets but has 0% influence.

5. Supervised Return
Agent returns with reduced authority and requires approval from stronger agents.

6. Full Return or Further Restriction
If it improves, authority can slowly return.
If not, restrict, archive, merge, or shutdown recommend.

Learning Camp should create records:
- agent_id
- reason
- failure_patterns
- correction_rules
- training_examples
- start_date
- end_date
- return_status
- performance_after_return

Agents should “know” they are at risk of Learning Camp or shutdown through their current status and score context.

====================================================================

The Traffic Controller should know the active mode:

Fastest. Only execution-critical agents run.

2. Scalp Mode
Fast. Only scalp-critical agents run.

3. Scanner Mode
Moderate. Find and rank opportunities quickly.

4. Ruby Explanation Mode
Slower allowed. More agents can contribute to plain-English explanation.

5. Learning Mode
Background only. Never interfere with live execution.

6. Agent Creation Mode
Background only. Never during active execution.

7. Deep Review Mode
For post-trade/post-session review only.

Agent Traffic Controller responsibilities:
- Decide which agents should run
- Put nonessential agents to Silent Support, Sleeping, or On-Demand Only
- Prevent duplicate analysis
- Prevent slow agents from blocking live execution
- Enforce latency budgets
- Let urgent execution actions bypass deep analysis
- Wake sleeping agents only when needed

Example routing for V75 scalp:

- Scalp AI
- Risk AI
- Entry Timing AI
- Exit AI
- Execution AI if trade action is involved

Fast check:
- Market Structure AI

Silent/background:
- News AI unless relevant
- Agent Factory
- Learning Camp
- Promotion Board
- Deep Review AI

Example routing for deep user question:
Run:
- Ruby
- Market Structure AI
- Risk AI
- Trade Review AI
- relevant specialist agents

Latency budget guidelines:
- Live trade open/close UI feedback: immediate
- Live execution action: never wait on nonessential AI
- Emergency close: highest priority
- Scalp signal decision: very fast
- Scanner refresh: fast enough to stay useful
- Deep Ruby explanation: can take longer only after decision is formed
- Learning Camp and Agent Factory: background only

13. AGENT COURT FOR DISAGREEMENTS
====================================================================

When agents disagree, do not simply average opinions.

Create Agent Court logic.

Agent Court considers:
- Which agent has specialty authority for this setup
- Recent performance in this exact market condition
- Symbol-specific performance
- Timeframe-specific performance
- Trade-type-specific performance
- Risk AI veto
- Whether this is scalp/intraday/swing/no-trade
- Historical record of similar disagreements
- Speed requirements
- Confidence calibration

Example:
Scalp AI says buy.
Risk AI says too close to resistance.
Entry AI says entry is late.
Market Structure AI says H4 is bearish.

Ruby should not blindly recommend buy.
Ruby should downgrade:
“Scalp AI detected momentum, but Risk AI and Entry AI rejected the timing. Setup is watchlist only unless confirmation improves.”

Store disagreement records so the system learns who was right later.
