We need to add an Account Routing Mode system to ARX AI.

Goal:
Allow admin to switch between:
1. Users trading through their own connected MT5 accounts.
2. Users trading through the same shared admin/master MT5 account.

This must work with the existing Trading Off / Demo Trading / Live Trading platform mode system.

Before changing code:
Inspect current Phase 3 trading implementation, admin trading controls, MT5 bridge, EA command routing, trade command queue, user permissions, risk limits, audit logs, assistant trade tools, and database schema.

Add this new concept:

accountRoutingMode:
- USER_OWNED_MT5
- SHARED_MASTER_MT5

Global admin controls:
1. Account Routing Mode:
   - User-owned MT5 accounts
   - Shared master MT5 account
2. Platform Trading Mode:
   - Trading Off
   - Demo Trading
   - Live Trading
3. Emergency Stop
4. Shared demo master account selector
5. Shared live master account selector
6. Per-user override:
   - follow global routing mode
   - force user-owned MT5
   - force shared master MT5
   - suspended

Core behavior:

USER_OWNED_MT5 mode:
- Each user trades only through their own connected MT5 account.
- User must own the MT5 connection.
- Demo orders require that user’s own connected demo account.
- Live orders require that user’s own connected live account.
- User’s orders, P&L, positions, journal, and dashboard come from their own MT5 connection.

SHARED_MASTER_MT5 mode:
- Users do not connect directly to the MT5 account.
- Users do not see or receive the master MT5 login, password, investor password, server, bridge token, or credentials.
- Admin connects one shared master MT5 demo account and/or one shared master MT5 live account.
- All user trade requests route to the selected shared master MT5 connection.
- The app must internally track:
  - user_id
  - virtual account id
  - user allocation
  - user order request
  - master MT5 order id
  - master MT5 position id
  - symbol
  - side
  - lot size
  - entry
  - stop loss
  - take profit
  - close price
  - P&L attribution
  - fees/spread/slippage attribution if available
  - status
  - rejection reason
  - audit trail

Routing decision logic:
For every trade request, determine:

effectiveRoutingMode =
- user override if not inherit
- otherwise global accountRoutingMode

Then:

If effectiveRoutingMode = USER_OWNED_MT5:
- route command only to the user’s own MT5 connection
- reject if user has no valid connection
- reject if account type does not match platform mode

If effectiveRoutingMode = SHARED_MASTER_MT5:
- route command only to selected shared master connection
- reject if no shared master connection is configured
- reject if platform mode is demo and no shared demo master exists
- reject if platform mode is live and no shared live master exists
- reject if selected master account type does not match platform mode
- create or update user virtual account
- write shared_trade_attribution row
- tag command with user_id, virtual_account_id, shared_master_account_id

Important mode behavior:
- Switching routing mode affects NEW orders only.
- Existing open positions must remain tied to the routing mode and connection they were opened under.
- Do not migrate or merge open positions automatically.
- Admin must close or manage old-route positions separately.

MT5 netting/hedging protection:
Detect whether the shared MT5 master account is hedging or netting if possible.

If hedging:
- allow separate user trade attribution by order/position ticket.

If netting:
- warn admin that same-symbol positions can merge.
- either block conflicting multi-user same-symbol trades or use an aggregation ledger.
- do not claim clean per-user ticket attribution if the broker account nets positions.
