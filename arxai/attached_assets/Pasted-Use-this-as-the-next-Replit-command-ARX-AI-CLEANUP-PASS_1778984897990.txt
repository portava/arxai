PHASE 2 — FIND DUPLICATES
==================================================
Scan for duplicate or near-duplicate code.
Look for:
1. Duplicate components
   - Multiple dashboard components doing the same thing
   - Multiple AI widgets
   - Multiple chat popups
   - Multiple trade cards
   - Multiple scanner cards
   - Multiple nav/sidebar/menu components
   - Multiple bottom nav implementations
   - Multiple modals/toasts/confirm prompts
2. Duplicate backend routes
   - Repeated MT5 status routes
   - Repeated account routes
   - Repeated open-trades routes
   - Repeated AI chat routes
   - Repeated scanner routes
   - Repeated risk routes
   - Repeated journal/history routes
3. Duplicate services/utilities
   - Multiple MT5 clients
   - Multiple OpenAI clients
   - Multiple market-data clients
   - Multiple scanner services
   - Multiple risk calculators
   - Multiple user/session helpers
   - Multiple fetch/api wrapper functions
   - Multiple polling systems
4. Duplicate mock/demo data
   - Old fake dashboards
   - Old forced trade cards
   - Old scanner samples
   - Old account samples
   - Old placeholder AI responses
   - Any mock data leaking into live mode
For every duplicate found:
- Identify which one is active.
- Identify which one is inactive.
- Identify which one is better/current.
- Merge only if safe.
- Remove only if proven unused.
- If both are needed, explain why and keep both.
- If one is broken but belongs to the current app, fix it instead of deleting.

==================================================
Find code that is dormant, abandoned, unreachable, or disconnected.
Check for:
1. Unused files
2. Unused exports
3. Unused imports
4. Dead routes
5. Dead pages
6. Dead components
7. Old UI versions no longer routed

14. Old scanner files not connected to current scanner

Use static analysis where available:

- ESLint
- Vite/Next/React build output
- import graph checks
- grep/search
- dependency graph
- package dependency checks
If tools like depcheck, ts-prune, knip, eslint, or dependency-cruiser are available, use them.
If they are not installed, do not permanently alter the project just to add heavy tooling unless necessary. Prefer npx one-time checks if safe.
IMPORTANT:
Some code may be dynamically loaded or referenced through routes/config.
Do not delete anything that may be used dynamically unless confirmed.
==================================================
PHASE 4 — CLASSIFY EVERYTHING BEFORE CLEANUP
==================================================
Create these categories:
A. KEEP
Code is active and part of the ecosystem.
B. FIX
Code is broken, disconnected, or incomplete but belongs to the ecosystem.
C. MERGE
Duplicate code where one clean shared version should replace multiple repeated versions.
D. ARCHIVE
Code appears obsolete or dormant but may still have historical value.
E. DELETE
Code is proven unused, broken, duplicated, obsolete, and has no role in the app.
Rules:
- Prefer FIX over DELETE if the feature belongs to ARX AI.
- Prefer ARCHIVE over DELETE if there is any uncertainty.
- Only DELETE when 100% proven safe.
- If removal breaks build/tests, restore immediately and fix instead.
- Do not delete MT5, AI, scanner, risk, auth, dashboard, journal, notification, or user-session code unless it is proven duplicate/dead and replaced by active working code.
==================================================
PHASE 5 — CLEANUP ACTIONS
==================================================
Perform safe cleanup only.
Allowed actions:
1. Remove unused imports.
2. Remove unused variables only if safe.
3. Remove unreachable code blocks.
4. Remove duplicate files only when active replacement exists.
5. Consolidate duplicate helpers/services into one shared helper if low risk.
6. Archive obsolete components/routes in an archive/deprecated folder if unsure.
7. Remove old mock data leaking into live app.
8. Rename nothing unless necessary.
9. Update imports after safe consolidation.
10. Fix broken references caused by cleanup.
Not allowed:
1. No full rebuild.
2. No UI redesign.
3. No feature removal.
4. No deleting current app pages.
5. No deleting ecosystem systems.
6. No changing brand direction.
7. No changing database schema unless required to fix breakage.
8. No changing auth/session behavior unless broken.
9. No replacing working services with new ones.
10. No hiding errors with placeholders.

==================================================
Treat these as protected unless proven duplicated/dead:

3. Market scanner

   - Missing API key is not dead code.
   - Fix graceful missing-key handling.
4. Risk engine
   - Do not delete risk rules.
   - If disconnected, wire it back into trade flow.
5. User sessions
   - Do not remove user-specific data handling.
   - Fix duplicate/demo leakage if found.
6. Demo/mock mode
   - Demo mode is allowed only if clearly separated from live mode.
   - Remove fake live data.
   - Keep labeled demo tools if intentionally used.
