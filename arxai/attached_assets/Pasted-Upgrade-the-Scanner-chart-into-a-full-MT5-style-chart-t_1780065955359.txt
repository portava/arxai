Upgrade the Scanner chart into a full MT5-style chart trading workstation inside ARX AI.

Goal:
The chart at the top of the Scanner page should not only display trades or allow SL/TP movement. Users should be able to trade from the chart the same way they expect to trade inside MT5: open trades, close trades, modify trades, place pending orders, cancel pending orders, move entry/SL/TP lines, manage risk, and see live trade status directly on the chart.

Important Architecture Rule:
Use TradingView or the existing chart library as the visual chart layer only.
Use MT5 bridge as the real execution engine and source of truth.
Use ARX backend as the permission, ownership, risk, and user-filtering layer.

Do not mirror the full MT5 account screen.
Do not expose the master MT5 account.
Do not send all master-account trades to the frontend.
Do not hide other users’ trades only with frontend filtering.
The backend must send only the logged-in user’s authorized trades, pending orders, and chart-trading controls.

Core Chart Placement:
1. Put the live chart at the very top of the Scanner page.
2. Scanner results, Broad Scan, Focus Scan, filters, and Ruby explanations should remain below or beside the chart depending on screen size.
3. The chart must load immediately when Scanner opens.
4. Do not wait for Ruby to finish before loading the chart.
5. Do not wait for full scanner results before loading the chart.
6. Use skeleton loading inside the chart panel only.

Chart Must Show:
1. Live candles or live price feed.
2. Current bid and ask.
3. Spread.
4. Selected symbol.
5. Timeframe selector.
6. Account mode label: DEMO or LIVE only.
7. User’s available allocated balance.
8. User’s margin/risk info if available.
9. User’s open positions on that symbol.
10. User’s pending orders on that symbol.
11. Entry line.
12. Stop Loss line.
13. Take Profit line.
14. Pending order line.
15. Current price line.
16. Floating P/L.
17. Lot size.
18. BUY/SELL direction.
19. Ticket/order ID shortened for display.
20. Trade status: Open, Pending, Updating, Closing, Closed, Rejected.

20. Cancel all pending orders for this symbol

Do not add fake functionality. If a feature is shown, it must either work or be clearly disabled with a clean explanation.

Chart Line Behavior:
1. Entry, SL, TP, and pending order lines must be draggable.
2. Dragging a pending order line should modify the pending order entry price.
3. Dragging SL should modify Stop Loss.
4. Dragging TP should modify Take Profit.
5. Dragging should show live price, pip distance, estimated dollar risk, and estimated reward while moving.
6. After drag release, show a compact action bar:
   - Confirm
   - Cancel
7. The button should say only “Confirm.”
8. Confirm is the final action before the trade update is sent.
9. Cancel should snap the line back to the last confirmed broker value.
10. If backend or MT5 rejects the change, snap the line back to the last confirmed broker value.

One-Click / Fast Trading UX:
1. Add a clean chart trading panel with lot size input.
2. Add quick lot buttons:
   - 0.01
   - 0.02
   - 0.05
   - 0.10
   - Custom
3. Add optional default SL/TP distance presets:
   - by pips
   - by price
   - by risk percent
   - by dollar risk
4. If user has one-click trading enabled and admin permission allows it, Buy/Sell should fire with one final Confirm only.
5. If one-click trading is disabled, use a compact confirmation drawer, not a full modal.
6. Do not show repeated warnings every time unless required by system rules.
7. This is a high-speed trading environment. Reduce unnecessary clicks without removing real backend safety validation.

When the user right-clicks, long-presses, or taps a price level on the chart, show a compact trade menu:
1. Buy Limit at this price
2. Sell Limit at this price
3. Buy Stop at this price
4. Sell Stop at this price
5. Set SL here for selected trade
6. Set TP here for selected trade
7. Alert/Ruby watch level

Use tap-and-hold instead of right-click.
Make all handles large enough for touch.

6. Show order type clearly: Buy Limit, Sell Limit, Buy Stop, Sell Stop.

The frontend must never receive trades that do not belong to the logged-in user unless the logged-in user is an admin viewing an admin-only mode.
