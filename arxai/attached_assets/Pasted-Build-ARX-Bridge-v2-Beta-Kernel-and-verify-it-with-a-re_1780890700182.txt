Build ARX Bridge v2 Beta Kernel and verify it with a real live broker test.

This is the launch-beta bridge foundation. It must replace snapshot-only behavior with broker-truth event flow, real-time account state, real-time position truth, phantom-position prevention, CopyRates candle sync, tick/quote freshness, UI truth, Ruby/Scanner/Risk/Governance integration, and admin trace.

This is not a fake test task. After the bridge is built and all preflight checks pass, run a real live micro-test through the connected live MT5/Deriv bridge. Do not use paper trading. Do not use demo. Do not use simulated fills. Do not use fake broker responses. Do not mark complete unless the test proves real broker communication.

Important:
- Preserve current live broker execution settings unless this task explicitly needs the bridge v2 feature flag enabled for the owner live test.
- Do not place any live trade until every preflight gate passes.
- Live test must use the smallest allowed safe live size for the connected account/symbol.
- If the broker/account rejects the trade, report the true rejection reason.
- If any required live condition is missing, stop and report the blocker instead of faking success.
- Never show queued as filled.
- Never show accepted as filled.
- Filled must mean broker-confirmed filled.
- Closed must mean broker-confirmed closed or reconciled through verified broker truth.

MAIN GOAL

Create the ARX Bridge v2 Beta Kernel:

1. One stable EA bridge architecture.
2. Remote config manifest so future settings/function behavior can be changed from ARX without replacing the EA.
3. Whitelisted command system so ARX can push approved bridge commands/settings to the EA.
4. OnTradeTransaction-based trade event push.
5. Real-time account, positions, pending orders, candle, and tick/quote updates.
6. Backend event ingest, validation, idempotency, sequence tracking, admin trace, and lifecycle mapping.
7. Phantom-position dry-run reconciliation.
8. UI truth contract across Dashboard, Trade, Positions, Admin, Ruby, Scanner, Risk, Governance, Flame Scalp, and Run-On Candle Momentum.
9. Real live micro-test proving the bridge works end-to-end.

PHASE 3 — EA BRIDGE V2 BETA KERNEL

Create or upgrade the EA into a stable Bridge v2 Beta Kernel.

The EA must:

1. Use OnTradeTransaction for broker transaction truth.
2. Use OnTrade as a backup consistency signal only.
3. Use OnTimer for:
   - heartbeat
   - account snapshot
   - positions snapshot
   - orders snapshot
   - config polling
   - command polling
   - candle sync
   - tick/quote sync
   - local retry queue flushing
4. Use WebRequest for beta transport.
5. Require the ARX backend URL to be configured/allowed in MT5.
6. Include bridge_id, account_login, EA version, terminal build, sequence, timestamps, and idempotency key in every message.
7. Maintain a local retry queue for failed sends where possible.
8. Preserve idempotency keys on retry.
9. Never duplicate broker effects because of a retry.
10. Report AutoTrading/trading allowed/server connection status.
11. Report setup errors clearly:
    - WebRequest URL missing
    - bridge token missing
    - server unreachable
    - payload rejected
    - sequence reset
    - AutoTrading off
    - broker disconnected
    - candle sync failed
    - account snapshot failed
    - command rejected
12. Fetch remote config from ARX.
13. Execute only whitelisted command types.
14. Reject unknown commands.
15. Send command results back to ARX.
16. Push CopyRates candles for watched symbols/timeframes.
17. Push bid/ask/spread ticks or quotes for watched symbols where safe.
18. Push account/positions/orders snapshots after trade events and on interval.

EA must not contain ARX AI decision intelligence. The EA is a broker-truth sensor and execution adapter. ARX intelligence remains server-side.

PHASE 6 — PHANTOM POSITION RECONCILER

Build/upgrade phantom-position prevention.

Rules:
- broker open positions are source of truth
- if ARX thinks a position is open but fresh broker snapshot does not contain it, mark suspect_absent, not closed immediately
- increment absence_streak only on fresh successful broker snapshots
- set first_absent_at only on first confirmed fresh absence
- do not increment absence_streak when bridge snapshot is stale, missing, failed, or sequence-gapped
- if position reappears, clear absence_streak and first_absent_at
- require repeated absence and elapsed time before eligible_for_reconciliation
- start in dry-run
- dry-run reports would-close rows without writing final close state
- add admin trace for each decision
- do not enable write reconciliation until dry-run proves accuracy

Statuses:
- broker_confirmed_open
- pending_confirmation
- suspect_absent
- broker_absent_recheck
- eligible_for_reconciliation
- reconciled_closed
- uncertain_bridge_stale
- manual_review_required
