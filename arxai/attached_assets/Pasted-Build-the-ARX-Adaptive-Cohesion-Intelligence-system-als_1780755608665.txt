Build the ARX Adaptive Cohesion Intelligence system, also called AACI 2.0.

AACI 2.0 is the master adaptive cohesion algorithm for ARX AI. Its job is to make sure the entire ARX ecosystem works as one connected intelligent trading system.

AACI must constantly check whether Ruby, Scanner, Smart Chart, Market Timing Brain, Economic Calendar, Critical News Alerts, Self-Trade AI, Risk Governor, MT5 Shared Bridge, Open Trades, My Alerts, Account Analytics, Wins & Losses, Agent Ledger, Audit Log, user permissions, and admin controls are all working from the same truth.

This is not a normal QA checker. This is an adaptive AI control layer that grows with the system.

AACI should:

* collect system state
* normalize it into a shared truth snapshot
* check freshness and speed
* check permissions and hard gates
* compare systems for agreement
* detect conflicts
* calculate cohesion score
* calculate market truth score
* calculate risk alignment
* calculate execution readiness
* calculate speed/latency edge
* calculate uncertainty

* calculate learning integrity
* recommend action
* block or allow actions based on thresholds
* reconcile after execution
* alert if something breaks
* learn from outcomes

* keep full audit records

CORE PURPOSE

AACI answers this question:

“Are all ARX systems aligned, fresh, fast, safe, explainable, and trustworthy enough to allow this action?”

Risk Governor answers:

“Is this trade safe?”

AACI answers:

“Are all systems working together correctly enough to trust this decision?”

Final trading logic:

Risk Governor PASS

* AACI PASS
* Bridge Ready
* Permission Valid
* Allocation Available
* Audit Ready
    = Action may proceed through existing execution route.

If Risk Governor passes but AACI fails, do not execute. Use one of:

* WATCH_ONLY
* PREPARE_ONLY
* WAIT_FOR_CONFIRMATION
* REDUCE_SIZE
* PROTECT_OPEN_TRADE
* RECONCILE_SYSTEM
* BLOCK
* ALERT_ADMIN

HARD SAFETY GATE

Create a hard gate function.

HARD_GATE = 1 only if all required hard gates pass.

Required hard gates:

* authenticated user/session valid
* user or agent permission valid
* user/agent has trading approval
* agent has allocated funds if self-trade
* agent is active if self-trade
* autonomy level allows requested action if self-trade
* Risk Governor hard checks pass
* daily loss limit not hit
* weekly loss limit not hit
* max drawdown not hit
* global kill switch off
* per-agent kill switch off if agent trade
* bridge is available
* bridge heartbeat fresh
* market feed fresh
* symbol is tradable
* selected symbol matches execution symbol
* lot size valid
* allocation sufficient
* margin check valid if available
* execution route available
* audit logger available
* action is role-permissioned

HARD_GATE formula:

H =
permission
× funded
× active
× autonomyAllowed
× riskPass
× lossLimitPass
× bridgeReady
× feedFresh
× symbolTradable
× allocationAvailable
× executionRouteReady
× auditReady

Each factor is 1 or 0.

If any is 0, block live action.

Return hardGateFailures as clean reason codes and user-facing messages.

Regular-user messages must be plain English.

Examples:

* Trading paused by risk controls.
* Bridge unavailable.
* Market data is refreshing.
* Agent has no allocated funds.
* This action is not available for your account.
* Audit logging unavailable, so autonomous trading is paused.

Do not show raw internal names like canPlaceTrades, LIVE_LOCKED, backend, command queue, or API route names to regular users.

LEARNED TRUST SCORE — L

Each module/agent/signal should have a trust score that changes over time.

Use Bayesian-style trust:

trust_i(t) = alpha_i / (alpha_i + beta_i)

Start with neutral priors:

alpha = 3
beta = 3
trust = 0.50

When a module is correct:

alpha_i += reward_quality

When a module is wrong:

beta_i += penalty_quality

Track trust for:

* Scanner
* Smart Chart
* Ruby
* Market Timing Brain
* Heat Map
* News Engine
* Broad Flow Engine
* Volatility Matrix
* Risk Governor soft-read
* Self-Trade Agent
* Strategy
* Symbol
* Session
* Timeframe
* Alert Engine
* Execution path

Examples:

Scanner predicted Buy and trade worked:
scanner_alpha += 1

Heat Map said dirty heat/avoid and market trapped:
heat_alpha += 1

Ruby said wait but waiting missed a clean move:
ruby_beta += 0.5

Agent Blaze entered exhausted heat and lost:
agent_blaze_beta += 1
late_entry_detector_alpha += 1

L = weighted_average(moduleTrustScores)

ADAPTIVE WEIGHT UPDATE

Weights should grow with the system but stay inside safety limits.

Formula:

W_k(t+1) = clip(
W_k(t)

* η × outcomeError × signalContribution_k

* λ × safetyViolation_k
* μ × staleDataPenalty_k,
    W_min,
    W_max
    )

Where:

η = learning rate
λ = safety penalty strength
μ = stale data penalty strength
outcomeError = actualOutcome - expectedOutcome
signalContribution_k = how much this signal influenced the decision

Use small learning rate:

η = 0.01 to 0.05

Safety penalties must be stronger than profit rewards.

λ > η

Do not allow adaptive weights to override hard gates.

AACI may not automatically make major risk changes unless admin-approved.

Major changes requiring admin approval:

* increase agent allocation
* increase max lot
* enable news trading
* enable more symbols
* raise daily max trades
* change daily/weekly loss limits
* promote agent to full autonomy
* disable safety cooldowns
* remove kill switch constraints

==================================================
BAD-LEARNING PREVENTION

Separate outcome from decision quality.

Classify every trade:

* Good outcome / Good decision
* Bad outcome / Good decision
* Good outcome / Bad decision
* Bad outcome / Bad decision

A good outcome from a bad decision should not be heavily rewarded.

Example:
A news chase won randomly but violated dirty heat rules.
Outcome good, decision bad.
Do not increase trust strongly.

==================================================
LUCK FILTER

Every closed trade should ask:

* Did the trade follow thesis?
* Was entry on time?
* Was risk controlled?
* Was broad flow supportive?
* Was exit planned?
* Did it win because of plan or random volatility?

If likely luck:
Limit learning reward.

==================================================
CONFIDENCE QUARANTINE

If a module becomes unreliable, quarantine it.

Examples:

* Heat Map confidence unreliable today
* Volatility Matrix stale
* News feed disconnected
* Scanner signals late
* Agent Blaze miscalibrated

Quarantine means:
Do not use this signal for execution decisions until repaired/recalibrated.

Still allow display as informational if clearly labeled, unless data is dangerous.

==================================================
MINIMUM EVIDENCE RULE

Do not change major behavior from small samples.

Suggested rules:

* minimum 20 similar decisions before changing strategy weight
* minimum 5 trading days before promoting an agent
* minimum 10 news events before changing news playbook behavior
* minimum 30 heat alerts before changing heat alert scoring
* minimum 15 closed trades before trusting a new agent strategy

If insufficient evidence:
Recommendation only, no auto-change.

==================================================
REGIME RESET

If market regime changes sharply:

* reduce reliance on old learned weights
* lower confidence
* require new evidence
* alert admin if severe
* use safer defaults

Example:
Market regime changed.
Old V75 flame scalp performance may not apply.
Ruby reduces risk until new evidence forms.

==================================================
CROSS-AGENT CONTAMINATION CONTROL

Agents may learn from each other only through validated patterns.

No agent may copy another agent’s strategy into full live mode without validation.

If Agent Blaze finds a winning pattern:
Titan can test in shadow/low-risk mode first before full live use.

What makes money.

What protects the account.

Safety learning always outranks profit learning.

A risky pattern that made money twice should not become trusted if it violates drawdown, slippage, news, exposure, or execution rules.
