Do not rebuild blindly. Inspect the current:

Goal:
Create a central safety, compliance, permissions, and audit control layer so ARX AI can safely support approved private users in demo/live trading.

Important:
This is not legal advice and should not claim to make the app legally compliant by itself.
Do not enable live trading automatically.
Do not bypass Risk Governor.
Do not bypass readiness checks.
Do not expose secrets.
Do not weaken trade confirmation.
Do not allow users to access another user’s trading data.
Live trading must still require approval, disclosure, verified routing/account, and explicit confirmation.

PART 1 — Role-Based Access Control

Create or improve roles:

- Owner
- Admin
- Risk Manager
- Support
- Tester
- Trader/User

Permissions should control:
- view admin dashboard
- change platform trading mode
- enable demo trading
- enable live trading
- approve live users
- suspend users
- change risk limits
- assign shared-master allocation
- view audit logs
- view user readiness
- view trade actions
- send system alerts
- export reports

Owner-only actions:
- enable/disable Live Trading globally
- select shared live master account
- disable emergency stop
- change admin roles
- export full audit logs
- delete/disable users
- change production safety settings

Support users should never see secrets, bridge tokens, raw credentials, or full account credentials.

PART 8 — Live Trading Final Gate

Before any live order can queue, require:

1. platform mode = Live Trading
2. emergency stop = false
3. user live enabled
4. user not suspended
5. account/routing live verified
6. readiness status = READY_FOR_LIVE
7. compliance status = COMPLETE
8. current Live Trading Disclosure accepted
9. current AI Disclaimer accepted
10. Risk Governor pass
11. broker symbol rules pass
12. explicit live confirmation
13. audit log write

If any gate fails:
- reject action
- show exact blocker
- write audit/risk log
- do not queue command
