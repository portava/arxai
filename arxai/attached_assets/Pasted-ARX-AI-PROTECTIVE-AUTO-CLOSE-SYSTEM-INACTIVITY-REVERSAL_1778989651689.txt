ARX AI PROTECTIVE AUTO-CLOSE SYSTEM — INACTIVITY + REVERSAL DETECTION + PRE-AUTHORIZED EXIT ONLY

Add a protected AI auto-close feature for open trades.

Important:
This is NOT permission for the AI to freely trade.
This is NOT permission to open trades.
This is NOT permission to increase risk.
This is only for closing or partially closing an already-open position when the user has pre-authorized protective exit rules.

Do NOT rebuild.
Do NOT redesign.
Do NOT bypass paper-only lock.
Do NOT bypass live-trading lock.
Do NOT bypass risk governor.
Do NOT bypass explicit user opt-in.
Do NOT bypass Shared Master attribution.
Do NOT fake live data.
Do NOT promise profit.
Do NOT enable live execution by default.

Current app safety rules must stay intact.

==================================================

Protective Auto-Close

Settings should include:

2. Inactivity threshold:
   - 5 minutes
   - 10 minutes
   - 15 minutes
   - 30 minutes
   - custom if already supported
3. Auto-close mode:

   - close if reversal risk appears after trade reaches profit threshold

10. Emergency disable / kill switch

No user should inherit this as enabled.

No live account should have this enabled by default.

2. No recent voice command.

4. No recent AI chat interaction.

PHASE 4 — REVERSAL DETECTION ENGINE
==================================================

Add or connect a reversal detection module.

Name it something like:

protectiveExitEngine
or
aiProtectiveCloseEngine

It should analyze only available data.

Signals may include:

1. Price approaching strong support/resistance.
2. Rejection candle near key level.
3. Break of structure against the trade.
4. Liquidity sweep against the position.
5. Failed breakout.
6. Momentum divergence if indicator data exists.
7. ATR exhaustion / overextension.
8. Higher-timeframe reversal level.
9. Session high/low rejection.
10. Previous day high/low rejection.
11. Scanner/radar reversal warning.
12. News/event warning only if real news data exists.
13. Spread/liquidity abnormality if available.
14. Existing TP/SL proximity.
15. Profit giving back rapidly from peak.
16. Risk/reward no longer favorable.
17. Trade invalidation level reached or nearly reached.

Do not invent signals.
Do not fake research.
Do not claim “crucial research” unless there is actual data supporting it.

If data is incomplete, return:
INSUFFICIENT_DATA

PHASE 5 — PROTECTIVE CLOSE DECISION MODEL
==================================================

Create a decision object:

{
  decision: "NO_ACTION" | "ALERT_ONLY" | "RECOMMEND_CLOSE" | "RECOMMEND_PARTIAL_CLOSE" | "AUTO_CLOSE_ELIGIBLE" | "BLOCKED",
  reason,
  confidence,
  dataStatus,
  reversalSignals,
  invalidationLevel,
  currentProfitLoss,
  peakProfit,
  givebackPercent,
  suggestedClosePercent,
  suggestedAction,
  userInactive,
  userOptedIn,
  guardsPassed,
  blockedReason
}

Auto-close is only eligible if ALL are true:

1. User opted into Protective Auto-Close.
2. User is inactive beyond chosen threshold.
3. Position is open and belongs to the user/session.
4. Reversal confidence meets user threshold.
5. At least two strong reversal/risk signals confirm.
6. Data status is live or reliable enough.
7. Risk governor allows protective close.
8. Close action guard allows it.
9. Shared Master attribution allows it.
10. Paper/live lock permits the action.
11. MT5 bridge supports close command.
12. No recent duplicate close attempt.
13. No active user confirmation window is pending.
14. Trade has not already been closed.
15. The action reduces risk, never increases risk.

If any condition fails, return alert/recommendation only.

==================================================
PHASE 6 — SAFETY RULES
==================================================

Protective Auto-Close must obey these rules:

1. AI can never open a new trade.
2. AI can never add to a trade.
3. AI can never increase lot size.
4. AI can never remove stop loss.
5. AI can never widen risk without confirmation.
6. AI can only close, partially close, or tighten protection if supported.
7. If user is active, ask for confirmation instead of auto-closing.
8. If user is inactive, auto-close only if pre-authorized.
9. If paper-only lock blocks execution, return BLOCKED_BY_PAPER_LOCK.
10. If live trading lock blocks execution, return LIVE_LOCKED.
11. If bridge is disconnected, send alert only.
12. If data is stale, send alert only.
13. If confidence is not high enough, send alert only.
14. If no opt-in exists, send alert only.
15. If Shared Master attribution is unclear, block.

PHASE 12 — SHARED MASTER MODE
==================================================

Shared Master safety:

1. Auto-close can only affect the user-attributed position/share.
2. If the platform cannot safely close only the user’s attributed exposure, block auto-close.
3. If master trade attribution is unclear, block.
4. If closing would affect other users without proper routing, block.
5. Use alert-only when attribution is uncertain.
6. Audit all shared-master protective decisions.

Do not close a shared master trade globally unless the system is explicitly designed to do that safely.
