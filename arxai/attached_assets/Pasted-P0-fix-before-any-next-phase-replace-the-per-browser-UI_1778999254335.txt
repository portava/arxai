Implement and verify real per-user backend isolation across the app.

Required fixes:

2. Backend-authenticated user ownership
All user-owned backend routes must derive userId from authenticated backend session only, not from frontend payload.

Apply this to:
- ledgers
- portfolio
- trades
- orders
- pending orders
- SL/TP edits
- manual close requests
- audit trail
- AI assistant context
- AI portfolio tools
- AI bridge/reconciliation tools
- activity ping
- protective auto-close settings
- notifications
- risk settings
- command queue
- reconciliation
- shared MT5 virtual account records

Rules:
- Frontend must never be trusted to provide userId for ownership.
- Any userId sent from frontend must be ignored or rejected.
- Every read/write must filter by authenticated userId.
- Missing auth must return 401.
- Wrong ownership must return 403 or 404.
- No user can read, edit, close, analyze, or audit another user’s data.

3. Database/query protection
For every user-owned table/query:
- Add or verify userId ownership column.
- Add or verify eq(table.userId, req.authUser.id) on reads/writes.
- For updates/deletes, include both id and userId in WHERE conditions.
- For command queue records, require userId + auditId + tradeId/orderId attribution.
- For shared MT5 virtual records, require virtualSubAccountId + userId ownership.
- Broker/master account records may exist globally, but user-facing reads must only expose safe scoped summaries.

4. Frontend behavior
- Replace the “per-browser UI gate” note with a real status only after backend isolation passes tests.
- If user is not authenticated, show sign-in/locked state.
- Do not show another user’s dashboard, trades, ledger, AI context, or audit data.
- AI assistant must use backend-authenticated user context only.

5. AI assistant isolation
AI must only access:
- the logged-in user’s ledger
- the logged-in user’s trades/orders
- the logged-in user’s portfolio/risk settings
- the logged-in user’s activity status
- scoped bridge/reconciliation summaries only

AI must not access or summarize another user’s data.
