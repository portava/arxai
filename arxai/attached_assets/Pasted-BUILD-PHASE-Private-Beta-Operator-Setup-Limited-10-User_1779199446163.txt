BUILD PHASE — Private Beta Operator Setup + Limited 10-User Test Plan

Use the current codebase. Do not rebuild unrelated systems.

Goal:
Prepare ARX AI for a controlled private beta with exactly 10 invited users. The beta should test onboarding, demo mode, Ruby, scanner, trade ticket flow, privacy isolation, mobile usability, admin controls, safety gates, and optional operator-approved shared master readiness without turning on public live trading.

Important:
Do not open public registration.
Do not enable public live trading.
Do not create real live bridge commands.
Do not bypass safety gates.
Private beta should default to demo/testing unless the operator explicitly approves a user, allocation, disclosure, compliance flag, bridge mapping, and full live safety stack.

- allocations/risk profiles
- feature flags
- audit logs
- user feedback/support
- rate limits
- production readiness
- no-live-command evidence

Only build missing pieces.

2. 10-user beta cohort
Create an admin-only beta cohort system:

- beta cohort name: ARX_PRIVATE_BETA_10
- max users: 10
- invite-only access
- registration closed after 10 accepted users
- waitlist state after limit is reached
- admin can invite, revoke, pause, or remove a beta user
- every beta user is tied to authenticated userId
- no duplicate accounts from the same invite
- audit every invite and acceptance

3. Beta user modes
Each beta user should be assigned one of these safe modes:

A. Demo Tester
- default for all beta users
- private demo balance
- no live commands
- test scanner, Ruby, trade tickets, chart, P/L calendar

B. Personal MT5 Setup Tester
- only if selected by admin
- tests connection/setup/read-only status
- live disabled unless all safety/disclosure gates pass

C. Shared Master Review Tester
- only if selected by admin
- can request access
- cannot trade live unless admin approval, allocation, risk profile, disclosure, compliance approval, bridge mapping, and all live safety gates pass

4. 10-user capacity and isolation test
Add a beta QA routine that creates or simulates 10 users:

- User 1 through User 10
- each has private onboarding
- each has private dashboard
- each has private Ruby memory
- each has private scanner state
- each has private trades/history/P/L
- each has private notifications
- each cannot see any other user’s data

Also test:
- all 10 users logging in
- multiple users scanning same symbol
- multiple users opening demo tickets
- two users trading same symbol in demo
- one user double-clicking submit
- one user logging out and another logging in on same browser

5. Beta safety limits
Add or verify beta-wide defaults:

- live execution OFF by default
- one-click live OFF by default
- shared master live OFF unless all approvals pass
- demo mode enabled
- max beta users = 10
- beta user risk profile required
- default max lot size conservative
- daily loss limit required
- allowed symbols configurable
- close-only and kill switch available
- force-review available
- admin can pause all beta users instantly
