Audit the ARX AI admin/operator system first, then add or expose the missing admin controls for pushing settings to users and approving specific users.

Do not create a separate admin login page. Keep admin access role-based through the existing login system. Regular users must never see admin/operator controls.

GOAL:
Add a clear Admin User Control Center where an admin/operator can:
1. View all users.
2. Search/filter users by name, email, invite code, role, status, trading mode, live approval, bridge access, and risk profile.
3. Approve or deny a specific user.
4. Enable/disable a specific user.
5. Assign user role: user, admin, operator, read-only tester.
6. Set user trading access: paper, demo, live disabled, live approved.
7. Toggle shared/master MT5 bridge access per user.
8. Toggle personal MT5 bridge mode per user if supported.
9. Push settings to one user, selected users, or all users.
10. Save reusable settings templates.

ADMIN NAVIGATION:
Add this under the existing admin/dashboard area as:
- Admin
  - User Approvals
  - User Permissions
  - Push Settings
  - Trading Access
  - Audit Log

If an admin dashboard already exists, upgrade it. If these controls already exist in backend but are not exposed in UI, wire them into the admin UI. If partial controls exist, repair and complete them.

- Push to all users
- Preview changes before applying
- Confirm dangerous changes before applying, especially live trading or shared bridge access

SAFETY REQUIREMENTS:
- Do not automatically approve live trading for any user unless the admin explicitly clicks/sets it.
- Live trading must require admin approval AND user-level permission.
- Shared/master bridge access must require admin approval per user.
- Include confirmation modals for live access, shared bridge access, bulk setting pushes, and disabling users.
- Add an emergency revoke button per user.
- Add a global operator kill switch if not already present.
- All admin changes must be logged.
