MAIN GOAL:

2. HANDLE MOBILE SAFARI AUTOPLAY PROPERLY
Mobile browsers may block audio until the user interacts once.

Implement an audio unlock flow:
- When user opens Ruby chat, taps mic, toggles Ruby voice, or sends a message, treat that as the audio unlock interaction.
- After that first interaction, Ruby should auto-speak every response.
- If browser blocks autoplay, show “Tap to hear Ruby” only for that blocked response.
- After the user taps “Tap to hear Ruby,” future Ruby responses should auto-play without needing play every time.
