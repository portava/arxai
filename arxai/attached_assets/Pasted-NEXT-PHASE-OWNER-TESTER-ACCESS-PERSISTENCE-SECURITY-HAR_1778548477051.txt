NEXT PHASE: OWNER TESTER ACCESS + PERSISTENCE + SECURITY HARDENING

Goal:
Secure the app without restricting the owner/tester experience.

The user wants full tester access:
- all pages open
- all demo systems open
- all live tester workflows open
- live chart active
- AI tools active
- MT5 deferred until later

Now add:
- owner/tester role control
- persistent settings
- persistent simulator/tester data
- safer API protection
- backup/export tools
- session restore
- security audit
- full tester mode protected from public access

Important:
Do not block the owner/tester from accessing the full app.
Do not hide tester workflows from owner/admin.
Do not fake MT5 connection.
Do not place real broker orders.
Do not claim real broker execution.
Do not remove full tester access.
Do not remove risk governor or kill switch UI.

==================================================
1. CREATE USER ACCESS ROLES
==================================================

Create role system:

- OWNER
- ADMIN
- TESTER
- VIEWER
- LOCKED

Role meanings:

OWNER:
- full access to everything
- can enable full tester access
- can reset data
- can manage risk settings
- can export reports
- can configure MT5 later

ADMIN:
- full testing access
- cannot expose secrets
- cannot disable audit logs

TESTER:
- can use simulator/demo/live-intent workflows
- cannot change secrets
- cannot bypass risk governor
- cannot enable real broker execution

VIEWER:
- read-only access
- can view dashboard, chart, journal, reports

LOCKED:
- no trading access
- show access required screen

Default current user should be OWNER in development/test mode.

==================================================
2. PROTECT FULL TESTER ACCESS
==================================================

Create setting:

fullTesterAccessEnabled = true

But only OWNER / ADMIN can activate it.

Full tester access should allow:
- all routes visible
- all tester workflows open
- live manual tester mode
- live AI assist tester mode
- live AI auto tester mode
- live intent queue
- simulator trading
- AI scanner
- autopilot simulator
- shadow mode
- forward testing

But it should not mean:
- real broker execution
- MT5 fake connection
- bypassed risk governor
- disabled kill switch
- hidden audit logs

Show global banner:

“OWNER TESTER ACCESS ACTIVE — all workflows are open for testing. Real broker execution requires MT5 bridge connection.”

==================================================
3. ADD AUTH / SESSION LAYER
==================================================

Use existing auth if already present.

If no auth exists, add a simple development-safe owner session system that can later be replaced with production auth.

Required behavior:
- user session persists across refresh
- role loads on app start
- frontend and backend agree on role
- unauthorized users cannot call protected mutation endpoints
- owner cannot accidentally be locked out in development mode

Create endpoints:

GET /api/auth/session
POST /api/auth/dev-owner-login
POST /api/auth/logout
GET /api/auth/permissions

Do not expose secrets.
Do not store private tokens in frontend localStorage.
