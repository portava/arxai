Goal:
Make every broker execution result flow back into ARX AI accurately so users and admins can see what actually happened after a trade action was confirmed.

Important:
Do not auto-open trades.
Do not auto-close trades.
Do not bypass backend guards.
Do not expose secrets.
Do not fake execution results.
Live actions must still require explicit confirmation before they are queued.

PART 1 — Execution Result API

Add or verify an EA callback endpoint:

POST /api/mt5/execution-result

It should accept execution result updates from the EA, including:
- command_id
- action_request_id if available
- connection_id
- user_id if safely included or resolved backend-side
- status: executed | rejected | failed | partial | pending
- mt5_order_ticket
- mt5_position_ticket
- symbol
- side
- lot_size_requested
- lot_size_filled
- requested_price
- fill_price
- slippage
- stop_loss
- take_profit
- broker_message
- error_code
- error_message
- executed_at

Security:
- Validate bridge token.
- Validate command belongs to that connection.
- Validate user/connection/routing relationship.
- Reject unknown command_id.
- Reject duplicated final results unless idempotent.
- Never expose full token or secrets in logs.

PART 2 — Command/Action Status Reconciliation

When execution result arrives, update:

1. trade_action_requests
- status
- mt5_ticket
- rejection_reason
- guard_result
- updated_at

2. trade_command_audit_log
- status
- mt5 ticket
- broker result
- rejection/failure reason
- timestamps

3. open trades / positions
- create or update open position if executed
- mark closed if close executed
- update partial close if partial executed
- update SL/TP if modify executed

4. shared_trade_attribution
For shared-master routing:
- attach mt5_order_ticket
- attach mt5_position_ticket
- update fill price
- update filled lot size
- update status
- update P&L attribution if available

5. trade timeline
Add timeline events:
- command sent to MT5
- execution accepted
- execution rejected
- execution failed
- order filled
- partial close filled
- stop modified
- position closed

PART 3 — Broker Rejection Handling

If MT5/broker rejects the command, show a clear user-friendly reason.

Examples:
- invalid volume
- market closed
- symbol not available
- insufficient margin
- trade disabled
- off quotes
- invalid stops
- price changed
- requote
- account type mismatch
- auto trading disabled
- EA execution disabled

User UI should show:
- “Rejected by broker”
- reason
- what user can fix if known

Do not leave actions stuck as queued forever.

PART 4 — Stuck Command Watchdog

Create a watchdog that finds commands stuck too long in:
- queued
- sent_to_mt5
- pending execution
- awaiting result

If stuck past timeout:
- mark as stale or failed
- notify user
- write audit log
- keep MT5 sync active
- do not resend automatically unless idempotency is proven safe
