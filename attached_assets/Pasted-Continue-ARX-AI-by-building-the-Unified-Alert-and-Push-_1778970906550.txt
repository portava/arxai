Continue ARX AI by building the Unified Alert and Push Notification System.

Do not rebuild blindly. Inspect the current:
- Sniper Exit Alerts
- Live Trade Intelligence alerts
- Trade Decision Orchestrator alerts
- Smart Exit Plan alerts
- Economic Calendar/Event Risk alerts
- Risk Governor alerts
- Trade Action Center notifications
- MT5 Execution Reconciliation notifications
- existing notification center
- user alert preferences
- push notification setup if any
- mobile/iPhone Safari behavior
- admin trading controls

Goal:
Create one unified alert system that receives alerts from every trading subsystem, prioritizes them, prevents spam, delivers them in-app and by push when supported, and tracks whether the user saw or acted on them.

Important:
Do not auto-close trades.
Do not auto-open trades.
Do not execute from notifications.
Do not bypass backend guards.
Do not expose secrets.
Live trade actions still require explicit confirmation.

PART 2 — Alert Priority Engine

Build priority logic.

Critical examples:
- live trade close urgency high
- trade invalidated
- MT5 disconnected while live trades are open
- emergency stop activated
- broker rejected close request
- command stuck/stale
- high-impact news window for open live trade

Urgent examples:
- profit giveback threshold hit
- close review recommended
- risk limit near breach
- spread/volatility dangerous
- invalidation level near

Warning examples:
- market context weakening
- event risk upcoming
- stale data
- symbol rules issue

The alert system should prioritize:
1. live trade risk
2. close/protect-profit alerts
3. execution failures
4. MT5 connection problems
5. event/news risk
6. general info

PART 4 — Push Notification Support

If push notification infrastructure exists:
- connect unified alerts to push delivery
- respect user preferences
- respect quiet hours
- respect severity thresholds
- include safe message only
- no account numbers
- no MT5 credentials
- no tokens
- no sensitive shared master info

If push notification infrastructure does not exist:
- create clean push-ready architecture/stub
- show push status as “not configured”
- keep in-app alerts fully working

Push notification examples:
- “ARX AI: Your EURUSD trade needs review.”
- “ARX AI: Profit is fading on an open trade.”
- “ARX AI: MT5 connection issue detected.”
- “ARX AI: Broker rejected your action. Tap to review.”

PART 5 — Alert Cooldown and Anti-Spam

Add cooldown rules:
- same trade + same reason should not alert repeatedly
- severity escalation can break cooldown
- critical alerts can repeat after a safer interval
- user dismissal should pause same alert type temporarily
- acknowledged alerts should not keep firing unless the condition worsens

Track:
- last alert time
- last severity
- last condition value
- user response
- ignored count
