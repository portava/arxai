Build EE = Paper Execution Engine.

Goal:
Allow approved Build AA trade decisions to create simulated/paper trades only, using the read-only market data layer from Build DD.

Important:
Build EE must NOT place live trades.
Build EE must NOT call MT5 live execution.
Build EE must NOT enable canPlaceTrades.
Build EE must NOT bypass Build AA safety.
Build EE must NOT execute real broker orders.
Build EE only creates and manages simulated paper trades.

Current system:
- Build AA = central trade decision orchestrator.
- Build BB = closed-trade auto-debrief.
- Build CC = learning feedback engine.
- Build DD = read-only market data layer.
- Build EE must now create safe paper trades from valid AA decisions.

Core requirement:
When Build AA returns a valid trade decision with shouldTrade: true, Build EE can convert that decision into a paper trade record with simulated entry, stop loss, take profit, position size, and lifecycle tracking.

3. Paper execution eligibility rules

Only create a paper trade if all are true:

- decision.shouldTrade === true
- decision.action is BUY or SELL
- decision.action is not HOLD
- decision.decision_id exists
- tradeWindow.status is GOOD
- confidence meets minimum threshold
- riskScore is below max threshold
- marketDataSummary exists
- marketDataSummary.dataQualityStatus is GOOD or acceptable
- spread is not too wide
- volatility is not EXTREME unless strategy explicitly allows it
- stopLoss exists
- takeProfit exists
- positionSize exists and is greater than zero
- no critical warnings exist
- no duplicate paper trade already exists for the same decision_id
- no conflicting open paper position exists for same symbol/action unless allowed by settings

If any rule fails, return PAPER_REJECTED with clear rejection_reason.

4. Idempotency

The same Build AA decision_id must never create multiple paper trades.

If execute is called twice with the same decision_id:
- return the existing paper trade
- do not create a duplicate
- do not duplicate analytics
- do not duplicate logs

5. Simulated fill logic

Use Build DD market data.

For BUY:
- simulated entry should use ask or mid + spread/slippage logic.

For SELL:
- simulated entry should use bid or mid - spread/slippage logic.

Apply small configurable simulated slippage.

Return:
- requested entry
- simulated filled entry
- spread applied
- slippage applied
- timestamp

7. Add paper trade monitor

Create a safe paper trade monitor that can evaluate open paper trades against current market data.

For each open paper trade:
- fetch current market data from DD
- check if stop loss was hit
- check if take profit was hit
- calculate unrealized P&L
- update max favorable excursion
- update max adverse excursion
- if SL/TP hit, close paper trade
- trigger Build BB auto-debrief after close

This should be safe and manually callable through an endpoint or script.
Do not run an uncontrolled infinite loop.
