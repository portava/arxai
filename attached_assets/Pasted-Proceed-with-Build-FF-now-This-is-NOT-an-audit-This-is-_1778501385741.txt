4. Create sniper-entry filter

Build FF should not paper-execute every AA approval.

Create an additional sniper filter that scores:

- spread quality
- volatility stability
- liquidity/session quality
- candle confirmation
- risk/reward quality
- distance to stop loss
- distance to take profit
- recent loss/revenge-trade cooldown
- same-symbol conflict
- learning/mistake warnings from CC
- trade window status from AA
- market data quality from DD

Return:

{
  sniperEntryScore,
  status: "PASS" | "WAIT" | "REJECT",
  reasons,
  blockers,
  warnings
}

Only PASS can execute through EE.

- if decision passes sniper filter, call Build EE paper execution endpoint/service
- never auto-execute live
- never call broker order functions
