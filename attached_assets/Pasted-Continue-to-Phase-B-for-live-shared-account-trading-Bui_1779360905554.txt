Important architecture:
This system is EA-pull, not server-push. Do not add MT5 login/password/server secrets to Replit. The live broker credentials stay on the operator’s MT5 Windows VPS where EA v1.27 runs. The backend should queue validated live commands for the EA to poll.

Goal:
Create the full validation and execution pipeline for approved users trading through the shared live master account, while preserving all gates and hard blocks.

Validation endpoint requirements:

POST /api/trades/live-shared/validate should accept:
- symbol
- side: buy / sell
- orderType: market / buy_limit / sell_limit / buy_stop / sell_stop / buy_stop_limit / sell_stop_limit
- lotSize
- entryPrice if pending order
- stopLoss
- takeProfit
- riskAmount
- riskPercent
- source: manual / scanner / ruby
- confirmationIntent optional
- notes / reason optional

The endpoint must validate:
- Authenticated user session
- User has live shared-account approval
- User has allowed symbol permission
- User has allowed order type permission
- User max lot limit
- User max open trade limit
- User daily loss limit
- Global shared live mode
- Master bridge pinned
- Master bridge heartbeat not stale
- Platform mode is LIVE
- Shared routing is LIVE
- Master bridge mode is LIVE
- Kill switch is not active
- ARX_LIVE_BROKER_EXECUTION_ENABLED is true only for execution readiness
- Symbol exists in bridge-supported symbol list if available
- Lot size is valid
- Stop loss is valid
- Take profit is valid
- Broker stop-level distance is respected if bridge data exists
- Spread/slippage warning if available
- Margin/free margin estimate if available
- Risk/reward ratio
- Duplicate submission protection
- Missing SL/TP warning or block according to current risk rules

Validation response should return:
- approved true/false
- blocked true/false
- primaryReason
- errors[]
- warnings[]

- estimatedReward

Execution endpoint requirements:

POST /api/trades/live-shared/execute should:
- Require authenticated session
- Require confirmationIntent from the user
- Re-run validation server-side immediately before execution
- Never trust frontend validation alone
- Block if validation fails
- Block if kill switch is active
- Block if bridge heartbeat is stale
- Block if user approval is missing
- Block if ARX_LIVE_BROKER_EXECUTION_ENABLED is not true
- Block if platform/master/shared routing is not fully LIVE
- Block if user exceeds risk limits
- Block if symbol/order type/lot size is not allowed
- Queue a live command into arx_live_commands for EA v1.27 to poll
- Create internal ARX trade ID
- Create shared_trade_attribution row tied to userId
- Write full audit log
- Return commandId, internalTradeId, status, and queuedAt
