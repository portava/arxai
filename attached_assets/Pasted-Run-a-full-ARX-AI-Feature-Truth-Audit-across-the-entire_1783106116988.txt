Run a full ARX AI Feature Truth Audit across the entire app.

Goal:
Audit every visible and hidden feature individually and classify what is genuinely built, what is only a shell, what is wired but unreachable from the UI, what is disconnected from the central AI/brain/execution systems, what is still using mock/demo/simulation/paper behavior, and what is misleading users by displaying fake or stale success states.

Do not rebuild the app. Do not redesign features. Do not delete anything yet. First produce a precise truth map with file/path proof, then apply only safe fixes for confirmed misleading or broken behavior.

Core ARX rules:
- ARX AI is live-first.
- No paper/demo/simulator mode should be exposed as if it is live.
- Backtesting may use historical testing, but must never execute live trades.
- Scanner, chart, Auto Pilot, Profit Mission, manual trade buttons, Eleanor chat, and live dashboard must all connect to the same central truth systems where appropriate.
- Any feature that can trade must go through the approved live execution queue/pipeline/gates.
- No feature should display fake “connected,” “running,” “success,” “profit,” “trade sent,” or “AI active” states unless backend truth confirms it.
- No user-facing shell should pretend to be functional.

Definitions:

REAL:
Feature has reachable UI, real backend/data source, honest loading/error states, and tests.

PARTIAL:
Some real wiring exists, but missing important UI, backend, tests, or state sync.

SHELL:
Looks like a feature but has placeholder UI, TODO handlers, fake local-only state, mock values, no backend, or dead buttons.

HIDDEN:
Backend/service/store exists but no reachable UI call or no navigation entry.

DUPLICATE:
Feature overlaps another working feature and causes confusion or state divergence.

MISLEADING:
Shows live/success/running/connected/profit/AI-active/trade-ready state without backend proof.

USELESS:
Feature has no clear purpose, no real workflow, no central connection, and does not support ARX’s core trading mission.

Subdue criteria:
Mark a feature as “subdue” if it is not worth deleting yet but should be visually de-emphasized, hidden behind an advanced/dev/admin section, renamed as experimental, or removed from primary navigation because it distracts from live trading.

- Profit Mission → same lifecycle/execution/progress truth

For every feature not connected to the central brain, classify whether it:

- should stay independent
- should be hidden/subdued
- should be deleted later
