SCANNER LIVE DATA + MOBILE LAYOUT FIX — historical-only mode is still misleading and the chart overflows on mobile

The latest scanner screenshots show GBPUSD on the Scanner page. The app now labels the chart as stale/historical, but several truth and UI problems remain.

Observed current behavior:
- Top status badge says: “LIVE · Shared MT5”
- Scanner says:
  - DATA: Historical only
  - Data is incomplete — historical context only, not valid for a live entry.
  - RUBY: Limited read
  - Live feed unavailable · Analysis only
- Chart shows candles for 1m, 5m, 15m, 1h, 4h, 1D but all are last-known/historical.
- Last-known price shown around 1.33814 / 1.33815.
- No live price marker.
- Some badges say:
  - Stale · last-known
  - Delayed market data
  - Provider free tier has no older-than...
- The chart/card horizontally overflows on mobile. The user can slide the page sideways and the right side of the chart/badges gets cut off.
- “Plan Buy” and “Plan Sell” still appear strongly active even though the chart is not valid for live entry.

This must be fixed as a truth-layer + UI-layer issue.

PART 1 — Separate execution status from market-data status

Do not let the top badge “LIVE · Shared MT5” imply the scanner has live market data.

Create separate status concepts everywhere:
1. Execution status:
   - Shared MT5 connected
   - Live trading permission
   - Bridge heartbeat
   - Trade command path available

2. Market-data status:
   - Quote feed fresh/stale/unavailable
   - Candle feed fresh/stale/unavailable
   - Historical depth available/limited
   - Provider/source
   - Last updated time
   - Whether scanner/Ruby can use it for live-entry decisions

The scanner header should show something like:
- Execution: LIVE · Shared MT5
- Market data: STALE / HISTORICAL ONLY / LIVE

Acceptance:
If execution is live but candles are stale, do NOT show one combined badge that makes everything look live.
The user must instantly understand:
“Trading bridge is live, but this chart data is not live.”

PART 2 — Build a canonical market data truth object

Create or repair one server-side function for scanner/chart market truth, for example:

buildMarketDataTruth(symbol, timeframe, userId)

Return a canonical object like:

{
  symbol: "GBPUSD",
  timeframe: "1m",
  provider: "polygon" | "twelvedata" | "mt5" | "deriv" | "finnhub" | "unknown",
  quote: {
    price: number | null,
    bid: number | null,
    ask: number | null,
    timestamp: string | null,
    ageSeconds: number | null,
    status: "fresh" | "delayed" | "stale" | "unavailable"
  },
  candles: {
    count: number,
    newestCandleTime: string | null,
    oldestCandleTime: string | null,
    ageSeconds: number | null,
    status: "fresh" | "delayed" | "stale" | "historical_only" | "unavailable",
    depthStatus: "ok" | "limited" | "insufficient",
    source: string
  },
  liveUsable: boolean,
  rubyCanGiveLiveEntry: boolean,
  scannerCanRankLiveSetup: boolean,
  chartMode: "live" | "delayed" | "stale_last_known" | "historical_only" | "unavailable",
  warnings: []
}

Rules:
- liveUsable can only be true when quote is fresh AND candles are fresh enough for that timeframe.
- If candles are stale, chartMode = stale_last_known or historical_only.
- If quote exists but no fresh candle stream exists, do not show live price marker.
- If chartMode is historical_only, Ruby must not give live-entry advice.
- If data is not liveUsable, scanner confidence must be blocked from presenting as live-tradable.

PART 7 — Fix mobile horizontal overflow

The scanner page is overflowing horizontally on iPhone.

Screenshots show the chart card and badges extend off the right side. The page can slide sideways. This is unacceptable.

Fix CSS/layout:
- body, html, app root: max-width: 100%; overflow-x: hidden only as backup
- scanner page container: width: 100%; max-width: 100vw
- chart card: width: 100%; max-width: calc(100vw - safe padding)
- chart canvas/container: width: 100%; min-width: 0
- badges row: flex-wrap: wrap; min-width: 0
- long badges must wrap, truncate, or move to second row
- timeframe buttons must wrap or use horizontal scroll inside their own contained row, not force the whole page wider
- chart must resize with ResizeObserver on mobile orientation/viewport changes
- no fixed pixel width that exceeds viewport
- floating Ruby orb must not increase layout width
- bottom nav must remain fixed and not create horizontal overflow

Search for and fix:
- width: 800px / 900px / 1000px
- min-width on chart cards
- absolute-positioned badges extending beyond container
- chart canvas not being resized after render
- overflow-visible parent containers
- transform/translate causing right overflow

Acceptance:

- Chart card fully contained.
- Badges visible or wrapped.
- Plan buttons fit.
- Overlay chips fit.
- Bottom nav does not cover important controls.
- Screenshot at 390px and 430px wide must pass.
