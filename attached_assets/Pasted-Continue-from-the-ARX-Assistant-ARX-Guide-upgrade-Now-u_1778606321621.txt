Continue from the ARX Assistant / ARX Guide upgrade.

Now upgrade the assistant from “answering questions” into a safe in-app action guide.

Main goal:
The ARX Assistant should be able to guide the user through the app, open the correct pages, run safe diagnostics, explain setup problems, and recommend the next app step — without touching live trade execution, broker order flow, MT5 execution logic, or risk locks.

This is a safe navigation + diagnostics upgrade only.

Phase 1 — Add a safe assistant action router
Create a controlled action system for the assistant.

Allowed assistant actions:
- open a route/page
- explain a page
- explain current badges
- run blocker diagnosis
- run readiness diagnosis
- open Help Center
- open Risk page
- open Trade page
- open AI page
- open MT5 Bridge page if it exists
- open Broker Settings if it exists
- open Replay if it exists
- open Data if it exists
- open More menu if route-based
- open Report Issue flow
- start guided walkthrough
- show safest next step
- show setup checklist

Forbidden assistant actions:
- place live trades
- place paper trades without explicit user action
- enable live trading
- disable Emergency Stop
- bypass risk controls
- force MT5 execution
- change broker credentials
- reveal secrets/API keys
- change user role
- override readiness
- fake heartbeat
- fake broker connection
- fake account safety status

If the user asks for a forbidden action, assistant should explain why it cannot do it and offer a safe alternative.

Phase 2 — Create an ARX Setup Checklist
Add a guided setup checklist that the assistant can open and explain.

Checklist sections:
1. App status verified
2. Paper-only mode understood
3. Simulator mode understood
4. Risk page reviewed
5. Readiness reviewed
6. MT5 bridge status checked
7. Heartbeat checked
8. Broker read-only/execution state understood
9. Emergency Stop understood
10. Paper session requirements reviewed
11. Replay/coach/data features understood
12. Report issue path confirmed

Each checklist item should have:
- status: complete / incomplete / blocked / unavailable
- explanation
- related page link
- safe next action
- blocker reason when applicable

Do not mark items complete unless app state supports it.

Phase 3 — Add “Safest Next Step” engine
Create a function that ranks the safest next action based on current state.

Priority logic:
- If Emergency Stop is active, explain Emergency Stop first.
- If live trading is disabled, explain that live trading is unavailable.
- If MT5 heartbeat is missing, recommend checking MT5 Bridge/heartbeat.
- If broker is read-only, explain broker connection limitations.
- If paper session is blocked, explain paper requirements.
- If readiness is incomplete, recommend Readiness page.
- If user is confused on a page, recommend “What am I looking at?”
- If no blockers, recommend paper/simulator practice, not live trading.

Output should include:
- safest next step
- why this is safest
- page to open
- what not to do
- whether live trading remains unavailable

Phase 10 — Mobile UI hardening
The assistant must not block the bottom nav or Help Center chips.

Requirements:
- collapsed button above bottom nav
- expanded panel max height based on viewport
- panel scrolls internally
- input remains visible when keyboard opens
- close button always visible
- bottom offset respects iPhone safe area
- does not cover More menu when collapsed
- does not cover Emergency Stop
- pointer-events-none on wrapper
- pointer-events-auto on panel/button

Use:
bottom: calc(env(safe-area-inset-bottom) + 96px)
