NEXT PHASE: REAL-TIME MARKET DATA LAYER + NEWS RISK FILTER + SESSION CLOCK

Goal:
Upgrade the trading app so the AI scanner, strategy brain, backtesting, trade tickets, alerts, and command room all use a centralized market data layer.

The app currently has:
- full tester access
- live chart embed
- simulator market engine
- strategy lab
- backtesting
- trade grader
- market scanner
- command room
- alerts
- watchlist
- MT5 deferred

Now build the data foundation so the system can operate like a real trading platform even before MT5 is connected.

Important:
- Do not fake MT5 connection.
- Do not claim broker execution is live.
- Do not place real trades.
- Do not remove simulator mode.
- Do not break TradingView chart embed.
- MT5 remains deferred until the user connects desktop/VPS bridge later.

==================================================
1. CREATE MARKET DATA PROVIDER LAYER
==================================================

Create a provider abstraction:

MarketDataProvider

Supported providers:

- SimulatorMarketDataProvider
- TradingViewChartOnlyProvider
- MT5BridgeMarketDataProvider, future
- ExternalMarketDataProvider, placeholder

The app should clearly distinguish:

- chart visualization data
- simulator data
- broker/MT5 data
- external quote data

Do not assume the chart embed provides executable broker data.

Create shared response format:

{
  "symbol": "XAUUSD",
  "provider": "SIMULATOR" | "MT5_BRIDGE" | "EXTERNAL" | "CHART_ONLY",
  "bid": number,
  "ask": number,
  "mid": number,
  "spread": number,
  "timestamp": "ISO",
  "isLive": boolean,
  "isExecutable": boolean,
  "environment": "SIMULATOR" | "DEMO" | "LIVE" | "UNKNOWN"
}

5. ADD NEWS RISK FILTER
==================================================

Create a news risk module.

Page:

/news-risk

For now, because no external calendar API may be connected yet, create:

- manual high-impact news input
- simulated news events
- future external calendar provider placeholder

News event fields:

- eventName
- currency
- impact: low / medium / high
- eventTime
- affectedSymbols
- avoidBeforeMinutes
- avoidAfterMinutes
- notes

AI should use news risk to:

- reject trades close to high-impact news
- warn tester before live intent
- add alert if trade is near event time
- mark scanner card as NEWS_RISK
- reduce opportunity score if affected

Create endpoints:

GET /api/news-risk/events
POST /api/news-risk/events
PATCH /api/news-risk/events/:id
DELETE /api/news-risk/events/:id
