ARX AI TRADE TICKET UPGRADE — SL/TP + MARKET ORDERS + PENDING ORDERS

Add full Stop Loss, Take Profit, market order, and pending order support to the ARX AI trading app.

Do NOT rebuild the app.
Do NOT redesign the app.
Do NOT replace the current trade system.
Do NOT bypass existing confirmation, risk, Shared Master, MT5, AI, trade routing, or trade action guards.
Inspect the current trade placement and trade action flow first, then patch only what is needed.

Goal:
Users must be able to:

1. Place market Buy and Sell trades.
2. Place pending orders:
   - Buy Limit
   - Sell Limit
   - Buy Stop
   - Sell Stop
   - Buy Stop Limit
   - Sell Stop Limit
3. Enter Stop Loss and Take Profit when placing any supported trade/order.
4. Edit Stop Loss and Take Profit while a trade is open.
5. Edit Stop Loss and Take Profit on pending orders before they are triggered.
6. Edit saved/default Stop Loss and Take Profit settings outside of an active trade.
7. Cancel pending orders if pending-order cancellation is supported by the bridge.
8. See validation, estimated risk, reward, risk/reward ratio, mode status, and confirmation before anything is submitted.

PHASE 3 — PENDING ORDER VALIDATION RULES
==================================================

Validate all order types before submission.

Use current Bid/Ask where available.

Market Buy:
- Stop Loss must be below current ask/entry.
- Take Profit must be above current ask/entry.

Market Sell:
- Stop Loss must be above current bid/entry.
- Take Profit must be below current bid/entry.

Buy Limit:
- Entry price should be below current market/ask.
- Stop Loss must be below entry price.
- Take Profit must be above entry price.

Sell Limit:
- Entry price should be above current market/bid.
- Stop Loss must be above entry price.
- Take Profit must be below entry price.

Buy Stop:
- Entry price should be above current market/ask.
- Stop Loss must be below entry price.
- Take Profit must be above entry price.

Sell Stop:
- Entry price should be below current market/bid.
- Stop Loss must be above entry price.
- Take Profit must be below entry price.

Buy Stop Limit:
- Stop trigger price should be above current ask.
- Stop-limit price should be at or below the stop trigger price unless MT5 symbol rules require otherwise.
- Stop Loss must be below the eventual limit entry price.
- Take Profit must be above the eventual limit entry price.

Sell Stop Limit:
- Stop trigger price should be below current bid.
- Stop-limit price should be at or above the stop trigger price unless MT5 symbol rules require otherwise.
- Stop Loss must be above the eventual limit entry price.
- Take Profit must be below the eventual limit entry price.

Also validate:
- Numeric input only
- Correct symbol digits/precision
- Minimum stop distance if available from MT5/symbol info
- Minimum pending order distance if available
- Lot size rules
- Margin availability if available
- Do not allow impossible SL/TP placement
- Allow empty SL or TP only if risk rules permit it
- If risk rules require Stop Loss, block trade/order until SL is entered

If MT5/symbol data is unavailable, fail gracefully or preview honestly. Do not fake live validation.

PHASE 7 — MT5 BRIDGE SUPPORT
==================================================

Inspect the current MT5 bridge command format.

If trade placement already sends order commands to MT5, include SL/TP and pending-order fields in that command.

For market orders:
- Send Stop Loss and Take Profit at order open if bridge supports it.
- If bridge only supports opening first and modifying after, implement the safest supported flow and report it.

For pending orders:
- Send correct MT5 pending order type:
  - BUY_LIMIT
  - SELL_LIMIT
  - BUY_STOP
  - SELL_STOP
  - BUY_STOP_LIMIT
  - SELL_STOP_LIMIT

For stop-limit orders:
- Pass both trigger price and stop-limit price in the format the bridge/EA expects.

For open trade modification:
- Add/connect modifyPositionProtection.
- Payload:
  - positionId / ticket
  - symbol
  - stopLoss
  - takeProfit
  - confirmedByUser

For pending order modification:
- Add/connect modifyPendingOrderProtection.
- Payload:
  - orderId / ticket
  - symbol
  - entryPrice if editable
  - stopTriggerPrice if stop-limit
  - stopLimitPrice if stop-limit
  - stopLoss
  - takeProfit
  - expiration if supported
  - confirmedByUser

If the EA/bridge does not currently support pending orders or SL/TP modification:
- Add backend/UI support safely.
- Return a clear unsupported message.
- Do not fake success.
- Report exactly what EA/bridge action still needs to be added.

PHASE 10 — RISK GOVERNOR INTEGRATION
==================================================

SL/TP and pending order prices must feed into risk logic.

Risk governor should calculate or validate:

1. Estimated loss if SL is hit.
2. Risk percentage of account.
3. Estimated reward if TP is hit.
4. Risk/reward ratio.
5. Whether SL is required for this user/mode.
6. Whether max risk per trade is exceeded.
7. Whether daily loss guard would be violated.
8. Whether prop firm mode rules are violated, if present.
9. Whether minimum stop distance is invalid.
10. Whether pending order price is invalid.
11. Whether stop-limit trigger/limit relationship is invalid.
12. Whether Shared Master routing/attribution allows this action.

If unsafe:
- Block the trade/order.
- Show the reason clearly.
- Do not hide the reason.
- Do not allow AI or frontend to bypass this.
