4. Live Trading Arming Flow

Create:

POST /api/live-trading/arm

Required body:

{
  confirmationPhrase: "I ACCEPT REAL MONEY RISK",
  requestedMode: "LIVE_MANUAL" | "LIVE_AI_ASSIST" | "LIVE_AI_AUTO_TEST",
  maxLossPerTradeUsd: number,
  maxDailyLossUsd: number,
  maxLotSize: number,
  maxOpenPositions: number
}

Rules:

Allow live test arming if:

- user is admin
- confirmation phrase is exact
- broker connection is healthy
- broker account is detected
- account equity can be read
- 0 unacknowledged CRITICAL alerts
- emergency kill switch is inactive
- risk limits are set
- audit logging is active
- order guard is active
- stop-loss requirement is active

Do not require another paper session before allowing live testing if the user explicitly chooses live test mode.

But show this warning in the UI:

“Live testing uses real money. Paper testing is recommended first, but admin override has enabled controlled live testing.”

8. Guarded Live Order Router

Create one protected live execution function:

placeLiveOrderGuarded(order)

Every live order, manual or AI, must go through it.

Checks required:

- live trading armed
- current mode allows live execution
- emergency stop inactive
- broker healthy
- account equity readable
- order idempotency key exists
- duplicate order not found
- symbol allowed
- lot size within cap
- max open position rule passed
- max daily loss rule passed
- max per-trade loss rule passed
- stop loss exists
- take profit or exit logic exists
- spread acceptable
- risk governor approves
- audit logger active

If any check fails:
- reject order
- log exact reason
- show frontend error
- do not submit to broker

9. Kill Switch

When pressed:

- cancel pending orders if broker supports it
- block new live orders
- stop AI autopilot

- return system to READ_ONLY
- log everything

Create:

This should safely stop live testing and return the app to READ_ONLY or DEMO mode.
