We are upgrading ARX AI from paper-only into admin-controlled broker-routed DEMO and LIVE trading support.

Important:
Do not blindly remove safety. First inspect the existing trading mode, safetyCore.ts, MT5 bridge, assistant safety envelope, user settings, admin controls, database schema, EA command polling, order command model, and current route guards.

Goal:
Replace the current forced paper-only behavior with a controlled trading-mode system that supports:
1. DISABLED
2. SIMULATED / PAPER for internal testing only
3. DEMO broker trading
4. LIVE broker trading

The admin must be able to control trading mode by user and globally.

Hard rules:
1. Do not enable live trading by default.
2. Do not turn every user live automatically.
3. Do not allow live trading unless:
   - global live trading is enabled by admin
   - user is individually live-approved
   - user has accepted live trading risk disclosure
   - user has a connected broker/MT5 live account
   - bridge token is valid
   - account type is verified as live
   - emergency kill switch is off
   - per-user trading limits exist
4. Demo trading may be enabled separately from live trading.
5. All order execution must be broker-routed through the user’s own connected account.
6. Do not expose MT5_BRIDGE_TOKEN, per-user bridge tokens, SESSION_SECRET, apiKeyHash, OpenAI key, Finnhub key, or any secret.
7. Add full audit logs for every admin mode change and every trade command.
8. Add emergency kill switch that instantly blocks all new orders while still allowing dashboard/MT5 data sync.
9. Add per-user kill switch.
10. Add max-risk controls:
   - max lots per trade
   - max trades per day
   - max daily loss
   - allowed symbols
   - allowed account type
   - allowed trade direction if needed
11. Add trade confirmation rules:
   - demo trades can be one-click if admin allows
   - live trades require explicit user confirmation before order submission
12. AI assistant must never silently place a live trade.
13. AI assistant must distinguish between:
   - market analysis
   - trade idea
   - demo order request
   - live order request
14. Live order requests must require clear user confirmation such as:
   “Confirm live trade”
15. All trading responses must include current mode:
   tradingMode: "disabled" | "simulated" | "demo" | "live"
   globalLiveEnabled: true/false
   userLiveApproved: true/false
   emergencyKillSwitch: true/false
   accountType: "demo" | "live" | "unknown"
