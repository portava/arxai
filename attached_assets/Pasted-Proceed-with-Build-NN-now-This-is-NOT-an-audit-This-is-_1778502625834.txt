Build NN = Security, Roles, Permissions, and Data Protection.

Goal:
Create a security layer that protects the entire trading app, controls access to sensitive systems, prevents unauthorized actions, protects user/account data, masks secrets, logs security events, and makes sure every build from AA through MM remains safe.

The system should answer:
- Who is allowed to access each feature?
- Which actions are admin-only?
- Which actions are read-only?
- Are secrets protected?
- Are broker/account values masked?
- Are security events being logged?
- Are dangerous actions blocked?
- Are demo/test systems separated from real data?
- Are live-trading actions still impossible?
- Are all API endpoints protected consistently?

Important:
Build NN must NOT place trades.
Build NN must NOT enable live trading.
Build NN must NOT call MT5 live execution.
Build NN must NOT modify canPlaceTrades.
Build NN must NOT expose API secrets.
Build NN must NOT recommend live trading.
Build NN is security, roles, permissions, privacy, audit, and data protection only.

Current system:
- Build AA = trade decision orchestrator
- Build BB = auto-debrief
- Build CC = learning feedback engine
- Build DD = read-only market data
- Build EE = paper execution engine
- Build FF = paper autopilot loop
- Build GG = trading calendar + AI command center
- Build HH = risk governor
- Build II = trader coach + playbook
- Build JJ = replay simulator + strategy lab
- Build KK = data import + broker read-only connector
- Build LL = notification center
- Build MM = system health, audit, and admin control
- Build NN = security, roles, permissions, and data protection

Core requirement:
Create one central security and permission system that every future endpoint/action can check before doing anything sensitive.

3. Create roles

If the app does not already have roles, create safe role structure:

OWNER:
- full access to paper-only/admin/reporting features
- can manage users/roles
- can run health checks
- can stop autopilot
- can emergency WATCH_ONLY
- cannot enable live trading

ADMIN:
- can manage paper-only operations
- can run health/admin actions
- can view logs
- cannot manage owner role
- cannot enable live trading

TRADER:
- can run AA decisions
- can create paper trades if HH allows
- can run paper autopilot if allowed
- can view own reports/playbook
- cannot manage security/admin settings

ANALYST:
- read-only access to reports, calendar, replay, coach, playbook
- cannot create paper trades
- cannot run autopilot
- cannot change settings

VIEWER:
- limited read-only dashboard access
- cannot access broker snapshots unless masked
- cannot change anything

SYSTEM:
- internal service role for AA-MM service-to-service calls
- cannot place live trades
- must be logged when used
