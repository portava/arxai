PHASE 3 — FIX AUTH_REQUIRED BUG
============================================================

The screenshot shows:
Failed to load: AUTH_REQUIRED

Investigate exactly why this appears.

Check:
- is the user actually authenticated?
- is the route requiring admin/operator permission?
- is the page API returning AUTH_REQUIRED incorrectly?
- is the frontend calling an admin endpoint from a non-admin page?
- is session token missing from fetch credentials?
- is cookie/auth header not included?
- did route loader call /api/admin/* while user is not admin?
- did menu route point to Operator Command Center by mistake?
- is the selected menu item not matching the rendered page?
- is an API response not handled with permission fallback?

Fix expected behavior:
- If user is not logged in: redirect to login.
- If user is logged in but lacks role: render permission page, not raw AUTH_REQUIRED.
- If user is logged in and has permission: page loads.
- If only one widget/API on page lacks permission: show that widget as restricted, do not crash whole page if possible.
- If admin-only menu item is visible to non-admin by mistake: hide or disable it with clear reason based on product rules.

Do not bypass auth. Fix the auth routing/permission handling.
