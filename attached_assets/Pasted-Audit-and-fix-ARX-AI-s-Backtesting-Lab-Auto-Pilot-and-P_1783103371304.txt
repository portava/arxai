Audit and fix ARX AI’s Backtesting Lab, Auto Pilot, and Profit Mission so each one is fully live, reachable, wired to real data, and doing its intended job. Do not rebuild the app or replace working systems. First inspect what already exists, then patch only confirmed gaps.

Core rule:
ARX AI is live-first. No fake simulator, no paper mode, no placeholder UI pretending to work. However, Backtesting Lab must not execute live trades. It should test strategies against real historical market data and clearly label results as historical/backtest results. Auto Pilot and Profit Mission may interact with live execution only through the existing approved live queue, user approval, one-click/autopilot consent, kill switch, entitlement, bridge freshness, and audit systems.

Scope:
1. Backtesting Lab
2. Auto Pilot
3. Profit Mission

For each feature, verify:
- The route/page is reachable from the correct navigation.
- The UI is not a dead placeholder.
- All buttons have real handlers.
- Loading, empty, success, and error states are honest.
- It uses real backend/API/data paths.
- It does not rely on mock data unless explicitly marked as fixture/test-only.
- It has tests proving the intended behavior.
- It shows clear user-facing status when data is missing, stale, blocked, or unavailable.

Backtesting Lab intended job:
- Let the user select symbol/market, timeframe, date range, strategy or setup, risk assumptions, and starting balance/equity assumptions.
- Pull real historical candle data from the app’s real market-data source, preferably MT5 CopyRates/bridge-fed bars or the existing historical data provider.
- Run deterministic backtests on historical bars only.
- Display results such as total trades, wins/losses, win rate, net P/L, max drawdown, profit factor if available, average R/R, best/worst trade, and equity curve.
- Show trade-by-trade breakdown with entry, exit, reason, timestamp, direction, SL/TP if applicable, and result.
- Clearly label results as “Historical backtest — not live execution.”
- Never send orders, drafts, live ops, or queue commands from Backtesting Lab.
- Add guards/tests proving Backtesting Lab cannot call live execution endpoints.
- Handle missing history honestly: “Not enough historical data for this range/timeframe,” not fake results.
- Make sure limited-market config is respected, but allow direct symbol search if the app already supports it.

Auto Pilot intended job:
- Confirm Auto Pilot is a real live-trading control surface, not just a visual toggle.
- It should show whether Auto Pilot is OFF, ARMED, RUNNING, BLOCKED, or PAUSED.
- It must respect existing live approval/entitlement, bridge freshness, kill switch, account/market availability, user consent, and risk/governance settings.
- It must not silently place trades unless the user/admin has the required live approval and Auto Pilot consent/state is active.
- It should connect to the existing AI decision engine or trading planner, not an isolated mock.
- It should explain what it is watching, what conditions it needs, and why it did or did not act.
- It should publish honest status/events into the UI: waiting for setup, blocked by stale bridge, blocked by kill switch, no approved live bridge, trade submitted, trade rejected, trade filled, trade failed, etc.
- It must log decisions and live actions to the existing audit/event system.
- It must not bypass the live queue, safety gates, or bridge-command pipeline.
- If Auto Pilot is expected to place trades, prove the path ends at the same live execution pipeline used by manual trades.

Profit Mission intended job:
- Confirm Profit Mission is not just a static goal screen.
- User/admin should be able to define a mission: profit target, max loss/drawdown limit, market scope, trading style/mode, timeframe, session window, and whether Auto Pilot can participate.
- It should track real progress using live account/position/order data, not fake numbers.
- It should show mission status: NOT_STARTED, ACTIVE, PAUSED, COMPLETED, FAILED, BLOCKED.
- It should update based on realized/unrealized P/L according to the existing app conventions.
- It should stop/pause/flag itself when the profit target is hit, max loss is hit, bridge is stale, kill switch is active, approval is missing, or market data is unavailable.
- It should integrate with Auto Pilot where intended, but not duplicate Auto Pilot logic.
- It should show a mission timeline/log: created, started, trade opened, trade closed, profit updated, target hit, failed, paused, resumed.
- It should not fake completed missions or invented P/L.
- It should not allow Profit Mission to bypass live execution gates.

Important integration checks:
- Verify all three features use shared source-of-truth stores/services where possible.
- Make sure dashboard/header/status cards reflect the same state as the chart, scanner, bridge, and live execution panels.
- If a button says Start, Stop, Pause, Run Backtest, Enable Auto Pilot, Launch Mission, or Close Mission, the visible state must immediately and honestly reflect what happened.
- No stale “success” UI after backend rejection.
- No green/live-looking state when the feature is blocked.
- No orphan local-only state that disagrees with backend truth.
- Make sure mobile and desktop layouts remain usable.
