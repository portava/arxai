Required architecture:
Create or repair one unified Market Data Router.

The router should choose the correct feed source by market type:

A. MT5-connected tradable symbols:
- If the symbol is available from the connected MT5 broker/account, MT5 should be the primary live quote source.
- Use MT5/EA bridge quotes for tradable broker symbols when available.
- This ensures the price shown in ARX matches what can actually be traded.

B. Deriv synthetic/volatility markets:
- Volatility 10, 25, 50, 75, 100
- Volatility 10 (1s), 25 (1s), 50 (1s), 75 (1s), 100 (1s)
- Boom/Crash if supported later
- Step Index if supported later
- These should route to Deriv/MT5 broker feed, not TwelveData.
- If Deriv API/WebSocket is configured, connect the Deriv feed properly.
- If the connected MT5 broker provides these symbols, map them from MT5 symbols instead.

C. Forex/crypto/stocks/indices:
- Use TwelveData only where TwelveData is the correct provider.
- Use other configured providers when better suited.
- Add fallback provider logic instead of failing immediately.

D. News/economic/event data:
- Route through the relevant attached news/economic APIs, not TwelveData candles.

Provider priority:
1. For tradable symbols: connected broker/MT5 feed first.
2. For Deriv synthetic/volatility symbols: Deriv or broker MT5 feed.
3. For normal market symbols: best configured provider by asset type.
4. Fallback providers if primary fails.
5. Only show “no feed” if all valid providers fail or symbol is unsupported.
