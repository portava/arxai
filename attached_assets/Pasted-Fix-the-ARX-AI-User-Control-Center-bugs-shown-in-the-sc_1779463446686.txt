Fix the ARX AI User Control Center bugs shown in the screenshots.

CURRENT PROBLEMS:
- The admin tabs overlap each other on mobile.
- User Control Center is unorganized and hard to use.
- Searching for Andraie / andraie.co@gmail.com does not find the account.
- The User Approvals tab only shows pending/invited users, so active users are hidden from search.
- The Permissions tab is showing generated/test/seed users such as armgate, demogate, qa-symex, arx.local, and arx.test accounts.
- Admin should only see real users who signed up or were invited outside the app, not accounts created internally for testing.
- The controls for giving users access are too complicated. Admin should be able to approve users and give access in the easiest possible way.

REQUIREMENTS:

1. FIX MOBILE TAB LAYOUT
Redesign the User Control Center tabs so they do not overlap on mobile.
Use one of these clean layouts:
- Horizontal scrollable pill tabs, one row only, no wrapping
OR
- A compact dropdown selector on mobile
OR
- A clean 2-column grid with proper spacing and no overlap

Tabs must remain:
- User Approvals
- Permissions
- Push Settings
- Trading Access
- Risk Templates
- Audit Log

Do not let tab labels sit on top of card titles. Add proper spacing between tabs and content.

2. MAKE ADMIN ACCESS CONTROLS SIMPLE
Giving users access to anything should not be complicated.

Create the easiest possible admin workflow:
- Admin searches for a user.
- Admin taps/clicks one clear “Manage Access” button.
- A simple access panel opens.
- Admin can approve, disable, assign role, set trading mode, approve demo/live, enable shared bridge, and assign risk settings from one place.

The admin should not have to jump across multiple confusing tabs just to give one user access.

Each real user row/card should include simple quick actions:
- Manage Access
- Approve User
- Enable Demo
- Request/Approve Live
- Enable Shared Bridge
- Disable User

Inside “Manage Access,” organize controls into simple sections:
- Account Access
- Trading Access
- Bridge Access
- Ruby / AI Access
- Scanner Access
- Risk Limits
- Templates
- Notes / Audit History

Use friendly labels, not backend labels.
Examples:
- “Approve User” instead of accountStatus update
- “Enable Live Trading” instead of liveTradingApproved
- “Enable Shared Bridge” instead of sharedBridgeApproved
- “Max Lot Size” instead of maxLotSize
- “Require Stop Loss” instead of stopLossRequired

Add quick presets/templates for admin:
- Paper Only
- Demo Tester
- Demo + Scanner
- Live Pending Review
- Live Approved Conservative
- Live Approved Standard
- Disable Trading
- Emergency Lockdown

Admin should be able to apply a preset in one click, preview what changes, then confirm.

For dangerous access changes, keep it safe but still simple:
- Live trading approval requires clear confirmation.
- Shared/master bridge approval requires clear confirmation.
- Raising max lot size or max daily loss requires confirmation.
- Bulk live access requires per-user confirmation.
- Normal lower-risk settings should not require too many steps.

The goal is:
simple for admin, hidden from users, safe for live trading.

- Pending Users
