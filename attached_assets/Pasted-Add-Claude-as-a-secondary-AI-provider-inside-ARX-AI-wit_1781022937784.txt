Add Claude as a secondary AI provider inside ARX AI without replacing the existing Ruby/OpenAI flow.

GOAL:
ARX AI should support a multi-model AI router where Ruby can use OpenAI as the primary front-facing assistant and Claude as a secondary deep-reasoning/audit provider. Claude should be available for deeper code/system audits, scanner/feed/candle-history diagnosis, long-context market reasoning, and fallback responses when OpenAI is unavailable. Do not break existing Ruby chat, scanner, MT5 bridge, risk engine, admin permissions, live trade wiring, or existing AI endpoints.

IMPORTANT:
This is not a visual redesign.
This is not a rebuild.
Do not remove OpenAI.
Do not rename Ruby.
Do not let Claude bypass the ARX risk engine.
Do not let Claude place trades directly.
All live trade execution must still go through the existing backend trade intent, risk contract, admin approval, MT5 bridge, and execution pipeline.

Before adding anything, inspect the existing app and produce a short internal report in code comments or logs showing:

1. Existing Ruby chat endpoints.
2. Existing OpenAI client/service files.
3. Existing scanner AI explanation files.
4. Existing market analysis files.
5. Existing trade plan / risk explanation files.
6. Existing MT5 execution path.
7. Existing live trading approval gates.
8. Existing environment variable pattern.
9. Existing frontend hooks/components that call Ruby.
10. Existing backend AI response schema.

Do not guess. Reuse current architecture.

Add safe missing-key handling.

If ANTHROPIC_API_KEY is missing, Claude features should show a clean unavailable state instead of crashing the app.

Create a backend AI provider adapter layer if one does not already exist.

Suggested structure, but adapt to current project:

server/ai/providers/openaiProvider.ts
server/ai/providers/claudeProvider.ts
server/ai/aiRouter.ts

The shared provider interface should support:

- maxContextNotes
- supportsVision flag
- supportsTools flag
- supportsLongContext flag

The app should be able to call AI through one shared router instead of hardcoding OpenAI everywhere.

Do not rewrite every endpoint unless necessary. Wrap the existing OpenAI logic safely.

PHASE 4 — CLAUDE PROVIDER

Install the official Anthropic SDK if missing.

Implement Claude provider using ANTHROPIC_API_KEY.

Claude should support:

1. Deep audit prompts.
2. Long-context scanner/feed diagnosis.
3. Code/system reasoning.
4. Market reasoning backup.
5. Explanation rewriting.
6. Fallback response if OpenAI fails.

Claude responses must be normalized into the same response shape Ruby already uses.

No Claude-specific raw response should leak into the frontend.

PHASE 5 — AI ROUTER RULES

Create a routing layer with these rules:

1. Normal Ruby chat:
   - Primary: OpenAI
   - Fallback: Claude only if OpenAI fails or user/admin explicitly selects Claude

2. Scanner explanation:
   - Primary: OpenAI
   - Optional second opinion: Claude
   - Final response must clearly show if it is Ruby’s primary read or Claude-assisted review

3. Deep scanner/candle/feed audit:
   - Primary: Claude
   - Secondary: OpenAI fallback

4. Code/system audit:
   - Primary: Claude
   - Secondary: OpenAI fallback

5. Long trade lesson / education content:
   - Use router setting, default OpenAI unless Claude is selected

6. Live trade decision:
   - AI may explain and suggest
   - AI may not execute directly
   - Execution must still pass ARX risk engine and existing MT5 command path

PHASE 6 — FRONTEND MODEL CONTROL FOR ADMIN ONLY

Add an admin-only AI provider control panel.

Use an existing admin/settings/system area. Do not clutter the user trading interface.

Admin controls:

- Deep Audit Provider: Claude / OpenAI

PHASE 9 — CLAUDE DEEP AUDIT MODE

Add a Claude-powered deep audit action for admin.

Admin should be able to run:

1. Scanner audit
2. Candle history audit
3. Feed freshness audit
4. MT5 bridge audit
5. Open trades / P&L truth audit
6. Frontend wiring audit
7. AI response truth audit

Each audit should return:

- What was checked
- Files/functions involved
- Expected truth contract
- Actual result
- Pass/fail
- Severity
- Suspected cause
- Recommended fix
- Whether fix was applied
- Whether retest passed

Do not produce fake passes. If something cannot be verified, mark it as “UNVERIFIED”, not passed.

PHASE 10 — PROVIDER FALLBACK SAFETY

If OpenAI fails during normal Ruby chat:

- Retry once if safe.
- If still failing, use Claude if enabled.
- Response should still appear from Ruby.
- Add admin/debug metadata only for admin.

If Claude fails during deep audit:

- Retry once if safe.
- If still failing, fallback to OpenAI if enabled.
- Mark audit provider fallback clearly in admin/debug output.

No provider failure should crash the app.
