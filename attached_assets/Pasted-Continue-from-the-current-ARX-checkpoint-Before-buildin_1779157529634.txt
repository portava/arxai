PART 8 — MULTI-USER PERFORMANCE + CONCURRENCY

Design and implement smooth performance for multiple users trading at the same time.

Important scenario:
What happens if 10 users place a trade at the same time, or the same trade at the same time?

Build server-side concurrency controls:

1. Command queue
All trade requests become queued commands before EA dispatch.

2. Idempotency
Every trade submit must have idempotency key.
Duplicate taps or repeated requests must not create duplicate trades.

3. Per-user locks
Prevent one user from accidentally submitting the same trade multiple times at once.

4. Master bridge dispatch lock
Only one dispatch worker should send commands to a single MT5 bridge at a time, or use safe ordered batching if supported.

5. Risk reservation
Before sending to MT5, reserve exposure/margin/risk for that user.
If the trade fails/rejects, release reservation.
If filled, convert reservation into real allocation.

6. Exposure checks must be atomic
If 10 users try the same EURUSD trade at once, the app must:
- check master exposure limit atomically
- allow only the trades that fit limits
- block the rest with:
  MASTER_ACCOUNT_EXPOSURE_LIMIT_REACHED

7. Queue statuses
Show:
- Queued
- Waiting for bridge
- Sent to MT5
- Filled
- Rejected
- Failed
- Blocked

8. Rate limits
Add:
- per-user submit rate limit
- per-symbol cooldown
- bridge command throughput limit
- admin-configurable limits

9. Scaling
Use efficient polling or websocket/SSE updates so UI does not constantly spam the server.

10. Multi-user safety
If two users place the same trade:
- each gets their own ARX command
- each gets their own allocation if filled
- broker side may produce separate tickets on hedging accounts
- on netting accounts, app must allocate internally

11. Failure handling
If bridge disconnects:
- queue pauses
- no new commands dispatch
- UI says bridge disconnected
- commands remain pending or fail safely based on timeout policy

12. Performance dashboard
Admin dashboard should show:
- queue depth
- pending commands
- dispatch rate
- average fill time
- rejected count
- failed count
- bridge latency
- heartbeat age
- active users
- commands per minute
