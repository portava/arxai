Goal:
Build the account/portfolio layer that lets each logged-in user have their own visible trading account state inside the app, even if the backend later routes through one shared MT5 account. This must be paper-safe today and live-gated for the future.

A. Per-User Virtual Account Ledger
Create or verify a per-user account ledger that tracks:
- userId
- accountMode: PAPER, DEMO, SHARED_MT5_VIRTUAL, or LIVE_LOCKED
- startingBalance
- currentBalance
- availableBalance
- usedMargin if available
- equity if available
- realizedPnL
- unrealizedPnL
- totalFees/commission if available
- openTradeCount
- pendingOrderCount
- lastUpdatedAt

Rules:
- Every user must see only their own ledger.
- No cross-user balance, trade, order, or P&L leakage.

- Do not fake live broker balance.
- If MT5 bridge is offline or locked, show “Broker balance unavailable” instead of inventing.

Add/verify a safety model with:

- virtualSubAccountId
- userId ownership

- order allocation records
- per-user virtual balance
- per-user realized/unrealized P&L
- per-user risk limits
- per-user max open trades
- per-user max daily loss
- per-user max position size
- per-user lockout status

Rules:
- Shared MT5 routing must remain disabled/locked today.
- No user can affect another user’s virtual allocation.
- Every trade/order must be attributable to one user.
- Every future MT5 command must carry userId, virtualSubAccountId, tradeId/orderId, and auditId.
- If attribution is missing, command must be BLOCKED.
- If master/shared account routing is not explicitly enabled, status must be BLOCKED.
