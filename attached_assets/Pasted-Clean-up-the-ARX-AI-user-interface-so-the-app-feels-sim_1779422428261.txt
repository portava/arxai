Clean up the ARX AI user interface so the app feels simpler, calmer, and less confusing while keeping every existing feature.

Important:
Do not remove features.
Do not remove backend logic.
Do not remove live trading safety gates.
Do not remove scanner, Ruby, symbols, chart, risk, admin, or advanced controls.
Only reorganize the UI so normal users see a simple surface first, while advanced tools remain available behind tabs, drawers, filters, and collapsible sections.

Goal:
Create a simple-first interface with a power-user layer underneath.

Core design principle:
Every main page should quickly answer:
1. What am I looking at?
2. What does Ruby think?
3. What can I do next?

Everything else should remain available but not crowd the first screen.

6. Status badge cleanup

Current top area has too many loud badges.

Replace with one compact status row:
- Mode: Demo / Live / Ready / Blocked
- Market: selected symbol
- Ruby: Active
- Account: Approved / Not Approved

Tapping the status row opens a detailed status drawer.

Detailed drawer should include:
- live broker execution status
- sim engine status
- tester/admin access
- EA heartbeat
- bridge mode
- account approval
- server dispatch status
- kill switch state
- feed status
- current symbol
- intents count if still useful

Do not remove status data. Just collapse it.

7. Warning and alert cleanup

Remove repeated large warning blocks from normal user flow where they are duplicative.

Use compact status cards/badges instead:
- ACCOUNT NOT APPROVED
- READY TO ARM
- LIVE READY
- KILL SWITCH ACTIVE
- SIMULATOR DATA
- FEED NOT CONFIGURED

Detailed warning text should live inside expandable “Details” sections, not dominate every page.

Do not remove required backend safety logic.
Do not hide critical account-blocked state completely.
Just make warnings compact and readable.

8. Collapsible advanced areas

Any section that takes too much vertical space should become collapsible:
- scan universe
- full symbol groups
- advanced filters
- raw scanner metrics
- feed setup notes
- debug output
- admin-only diagnostics
- bridge heartbeat debug
- audit logs
- detailed readiness checklist
- long Ruby explanations
- old repeated help text

Default collapsed state should be remembered locally per user.

9. Mobile layout requirements

On iPhone Safari:
- no horizontal scrolling
- no cramped chip walls on first view
- no giant sections pushing important controls off-screen
- bottom nav must not cover content
- Ruby floating button must not cover action buttons or checklist rows
- buttons should be thumb-friendly
- cards should use consistent spacing
- important actions should stay visible near the top
- long content should collapse behind clear labels
