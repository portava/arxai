PHASE 5 — DISAGREEMENT COURT AUTO-WIRING

The prior report said resolveDisagreement is tested but not auto-called at runtime.

Fix this.

Agent Court should be automatically invoked when real multi-agent conflicts occur.

Create/verify a detector:

detectAgentDisagreement(agentOutputs)

Trigger Agent Court when:

* One or more agents approve and one or more reject.
* Risk AI vetoes another agent’s approval.
* Scalp AI approves but Entry AI flags late/chase.
* Market Structure AI conflicts with Scalp AI.
* Exit/TP AI says target is unrealistic while another agent approves.
* Confidence spread between agents exceeds threshold.
* A shadow/low-authority agent attempts to influence decision.
* Agent authority weights conflict with raw majority.

Agent Court must not just average votes.

It should consider:

* Risk veto
* Agent authority weight
* Agent specialty relevance to the current setup
* Recent performance in symbol/timeframe/setup type
* Whether the action is scalp/intraday/swing/no-trade
* Current mode and speed requirement
* Confidence calibration
* Whether the agent is Active, Shadow, Learning Camp, Restricted, Sleeping, or On-Demand
* Whether an agent is allowed to influence live recommendations

Agent Court output:

* final decision: approve / caution / reject / no-trade / watchlist
* winning rationale
* losing rationale
* which agents were overridden
* whether Risk veto was used
* whether Ruby should mention the disagreement
* whether prediction journal should lock the disagreement
* whether a disagreement record should be stored

Wire Agent Court into:

* Scanner ranking
* Scalp opportunity scan
* Ruby trade analysis
* Trade modal analysis
* No-trade recommendation flow

Do not wire Agent Court into urgent live execution after the user has already submitted/closed a live action if it can slow execution.
For live execution, only record/bypass nonessential governance.
