Build the ARX Broker-Side Close Reconciliation Guardrail.

This task fixes the broker-side close persistence gap.

Current reality:
Positions closed manually at the broker, closed by SL, closed by TP, margin stop-out, or otherwise closed entirely broker-side do not produce an ARX-initiated LIVE_FILLED CLOSE command. Because the current persistence reconciler only stamps closed_at when it can match an ARX-initiated LIVE_FILLED close command, broker-side closes can remain in arx_live_positions with closed_at IS NULL indefinitely.

The display layer may already hide these rows once they are brokerConfirmedAbsent from a reliable snapshot, but the database row remains open forever. That creates phantoms for any system reading raw arx_live_positions: risk/exposure, analytics, reconciliation center, admin tools, agent logic, and future reports.

This is not a bug in the current ARX-initiated close reconciler. It is a real design gap for broker-side closes.

Do not implement naive one-snapshot auto-close.

Auto-closing based on one missing snapshot is dangerous because an unreliable EA snapshot, dropped symbol, Market Watch issue, stale bridge, or incomplete sweep could make a real open position look absent. The fix must be conservative, multi-snapshot, audited, reversible/traceable, and never touch the broker.

==================================================
PRIMARY GOAL
==================================================

Add a safe broker-absence reconciliation path that can stamp closed_at on arx_live_positions only when a position is confirmed absent from the broker across multiple reliable snapshots.

This should convert the current manual admin repair into an automated, conservative, auditable sweep.

The reconciler must distinguish:

1. ARX-initiated close
   Existing path.
   Requires matching ARX LIVE_FILLED CLOSE command.
   Keep this unchanged.

2. Broker-side close
   New path.
   No ARX close command exists.
   Position is absent from reliable broker snapshots across N consecutive reliable sweeps.
   Stamp closed_at with reconcile_state such as RECONCILED_BROKER_ABSENT.
   Emit audit/reconciliation event.
   Never send a broker command.

==================================================
STEP 3 — SAFETY CONDITIONS FOR AUTO-STAMPING CLOSED_AT
==================================================

Only stamp closed_at when ALL are true:

1. Position row is currently open in ARX:
   closed_at IS NULL

2. Position belongs to the same authenticated / bridge / account scope:
   no cross-user or cross-bridge reconciliation

3. Latest snapshot is reliable:
   snapshotReliable === true or equivalent existing reliability contract

4. Snapshot was a complete sweep:
   not partial, not stale, not degraded, not symbol-limited unless symbol coverage is verified

5. Position is absent from broker snapshot:
   broker ticket / MT5 position ticket not present in reliable snapshot

6. Position has been absent across N consecutive reliable snapshots:
   suggested default N = 3
   configurable constant/policy

7. Absence window is old enough:
   suggested minimum age: 60–180 seconds depending existing heartbeat/snapshot cadence
   configurable constant/policy

8. No active ARX close command is pending for this position:
   do not race existing ARX close flow

9. No unresolved snapshot/mapping conflict:
   if symbol mapping, ticket mapping, bridge binding, or account mode is uncertain, do not auto-stamp

10. Reconciliation center does not mark this as unsafe:
   if detector flags partial snapshot, bridge stale, source mismatch, or suspicious state, keep ALERT_ONLY

If any condition fails:
- do not stamp closed_at
- keep current alert/manual reconciliation behavior
- record safe diagnostic if admin-only
- preserve row

==================================================
STEP 4 — RECONCILE STATE AND AUDIT TRAIL
==================================================

When a broker-side close is confirmed and stamped, use a distinct reconcile state.

Suggested value:
RECONCILED_BROKER_ABSENT

or if existing enum naming uses another convention:
BROKER_ABSENCE_RECONCILED

Do not reuse ARX-initiated close state.

Stamp:
- closed_at
- reconcile_state
- reconciled_at if column exists
- reconcile_reason if column exists
- last_broker_absent_at if column exists/future-ready
- broker_absent_snapshot_count if column exists/future-ready
- updated_at

Closed_at selection:
Prefer the safest available timestamp:
1. last reliable snapshot timestamp when position was confirmed absent, or
2. first absent timestamp after last seen broker present, or
3. current server time if no better timestamp exists

Do not pretend to know exact broker close time if unavailable.
Use audit metadata to distinguish estimated reconciliation close time from broker actual close time.

Audit event required:
- event type: BROKER_SIDE_CLOSE_RECONCILED or similar
- positionId
- userId
- bridgeConnectionId
- brokerTicket/mt5PositionTicket if safe
- symbol
- absentSnapshotCount
- firstAbsentAt
- lastAbsentAt
- lastReliableSnapshotAt
- reconcileState
- actor: system
- source: broker_absence_reconciler
- no secrets
- no raw sensitive payloads

If vault/state transition conventions apply, follow them.

==================================================
STEP 5 — CONSECUTIVE ABSENCE TRACKING
==================================================

Implement consecutive reliable absence tracking safely.

Options:
A. If schema already has fields for absence tracking, use them.
B. If not, add a small future-safe tracking table or state table if migrations are standard.
C. If schema changes are risky, compute from recent reliable snapshot logs if already persisted.
D. If none exists, implement the pure helper and dry-run/report first, then mark DB-write follow-up.

Do not add fragile in-memory-only absence counters for production reconciliation, because process restarts would reset evidence.

The absence counter must reset if:
- position appears in a reliable snapshot again
- snapshot is unreliable or partial
- bridge/account context changes
- symbol/ticket mapping becomes uncertain
- position is manually reconciled by admin
- ARX close command fills

ROLLOUT GUIDANCE
==================================================

Recommended rollout:

1. Land pure helper and tests.
2. Land dry-run mode.
3. Run dry-run against current data.
4. Review candidates.
5. Enable DB-write mode only after confirming snapshotReliable logic and reconciliation detector agree.
6. Monitor audit events and reconciliation center.
7. Keep manual admin repair as fallback.

Final rule:
Broker-side closes must not stay phantom-open forever, but ARX must never stamp a real live position closed from a single unreliable absence. Use multiple reliable snapshots, explicit reconcile_state, audit events, and no broker-side commands.
