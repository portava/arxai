Goal:
Allow users to test, replay, and validate trading strategies before using them in demo/live trading.

Important:
Do not present backtest results as guaranteed future performance.
Do not fake historical data.
Do not auto-place trades from backtests.
Do not bypass Risk Governor.
Do not expose secrets or broker credentials.
Live trading still requires explicit confirmation.

- timeframe

PART 4 — Forward Validation Mode

Add a “Forward Validation” mode.

This lets users run a strategy in real time without placing trades.

It should:
- watch live/scanner data
- detect strategy setups
- create simulated signal records
- track whether the signal would have won/lost
- compare to actual user trades if they took one
- show whether the setup is improving before allowing real usage

Statuses:
- observing
- signal detected
- simulated entry
- simulated exit
- validated
- failed
- data insufficient

PART 8 — Risk Governor Integration

Risk Governor should be aware of strategy validation.

Admin/user settings:
- warn if strategy has no validation
- block live trades from unvalidated strategies if enabled
- require minimum setup score for live trades if enabled
- require minimum forward validation sample size if enabled
- allow demo trades even if unvalidated
- allow manual override by admin

Do not block by default unless admin enables strict validation rules.
