ARX AI — Approved Trader Live Bridge Activation + Admin Hub Cleanup

Current problem:
Approved traders attached to the shared bridge are still seeing their accounts as DEMO instead of LIVE. This makes the app look and behave like they are not connected to live trading, even after approval.

Mission:
Make every approved human trader assigned to the live shared bridge show and operate as LIVE-ready, simplify the Admin Hub approval flow, and move approved bots/AI agents to a separate list so admins do not have to scroll through bots to find new human users.

Important:
Do NOT remove risk checks.
Do NOT bypass emergency stop.
Do NOT bypass broker/bridge execution checks.
Do NOT give bots live permission just because human traders are approved.
Do NOT mix demo bridge state with live shared bridge state.
Do NOT leave approved users stuck in demo display mode.

The target result:
Approved human traders on the live bridge should show:
- Account mode: LIVE
- Bridge: connected/shared live bridge
- Trading readiness: trade ready
- Manual trading: enabled if their approved trader permissions allow it
- Scanner/Trade Ticket/Manual Ticket: live account context
- Dashboard/Cockpit/Account: live account context

============================================================
PART 1 — DEFINE ONE APPROVED TRADER LIVE STATE
============================================================

Create or fix one shared resolver:

buildApprovedTraderLiveState(userId)

It should return:

{
  userId,
  isHumanUser: true,
  isBotOrAgent: false,
  approvalStatus: "approved",
  traderStatus: "approved_trader",
  assignedBridgeId,
  bridgeMode: "live",
  accountMode: "live",
  displayMode: "LIVE",
  canUseLiveBridge: true,
  canViewLiveAccount: true,
  canPlaceManualTrades: boolean,
  canQueueLiveTrades: boolean,
  canExecuteLiveTrades: boolean,
  riskProfileReady: boolean,
  emergencyStopActive: boolean,
  blockingReasons: [],
  warnings: []
}

Approved human traders should be live-ready when:
- user is approved as trader
- user is assigned to an active live shared bridge
- bridge is connected/fresh enough
- account is not disabled/suspended
- emergency stop is not active
- user is not bot/agent/system user
- required risk profile exists or safe default risk profile exists

If all checks pass:
accountMode/displayMode must be LIVE.

If any check fails:
show exact blocking reason.

Do not leave the user in DEMO just because the app default is demo.
