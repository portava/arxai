PHASE 2 — Add Per-User Trading Readiness Engine

1. user_authenticated
2. profile_complete
3. risk_profile_complete
4. trading_disclaimer_accepted
5. paper_only_guard_active
6. paper_session_available
7. mt5_bridge_connected
8. mt5_heartbeat_recent
9. account_mode_selected
10. user_owned_mt5_ready
11. shared_master_mt5_ready
12. demo_trading_ready
13. live_account_verified
14. admin_live_approval_granted

Each status should return:
- id
- label
- status: pass | fail | warning | blocked | not_required
- requiredFor: paper | demo | live | user_owned_mt5 | shared_master_mt5
- blockerReason
- userFriendlyExplanation
- nextStep
- adminOnly boolean if needed
- lastCheckedAt

The engine must support two routing modes:

A) USER_OWNED_MT5
- User connects their own MT5 account/bridge.
- Demo readiness requires user bridge heartbeat and demo account validation.
- Live readiness requires live disclosure, verified live account, admin approval, and valid routing.

B) SHARED_MASTER_MT5
- Users do not connect their own MT5.
- System allocates or maps the user to a shared master/demo/paper allocation.
- Demo readiness requires virtual_trading_account or shared allocation readiness.
- Live readiness still requires disclosure + admin approval + live-account gating.
- No user should affect another user’s readiness.
