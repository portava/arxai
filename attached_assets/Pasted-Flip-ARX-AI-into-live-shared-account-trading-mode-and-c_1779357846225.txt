Flip ARX AI into live shared-account trading mode and connect the operator live MT5 account through the existing bridge.

Do not rebuild the app from scratch. First inspect what already exists for:
- MT5 bridge
- Demo/live/paper mode
- Master/shared account mode
- User approval toggles
- Admin/operator dashboard
- Invite users
- Kill switches
- Trade execution
- Ruby trade assistant
- Scanner trade buttons
- SL/TP manager
- Risk/reward logic
- Trade ledger
- Audit logs
- Existing environment variables / secrets

Goal:
Switch the app from individual MT5-account dependency into shared live-account mode where one operator-connected MT5 live account powers execution, while every approved user trades through the app with isolated user-level permissions, logs, balances, allocations, and risk controls.

Important:
Do not hardcode live account credentials anywhere.
Use Replit Secrets / environment variables only.

Expected live shared-account environment variables:
- ARX_TRADING_MODE=live
- ARX_ACCOUNT_MODE=shared
- ARX_SHARED_LIVE_ENABLED=true
- ARX_MASTER_BRIDGE_ENABLED=true
- ARX_MASTER_BRIDGE_MODE=live
- MT5_SHARED_BRIDGE_BASE_URL=
- MT5_SHARED_LIVE_LOGIN=
- MT5_SHARED_LIVE_PASSWORD=
- MT5_SHARED_LIVE_SERVER=
- MT5_SHARED_LIVE_ACCOUNT_NAME=
- MT5_SHARED_LIVE_BROKER=
- MT5_SHARED_LIVE_CURRENCY=
- MT5_SHARED_LIVE_MAX_TOTAL_EXPOSURE=
- MT5_SHARED_LIVE_MAX_USER_EXPOSURE=
- MT5_SHARED_LIVE_MAX_DAILY_LOSS=
- MT5_SHARED_LIVE_MAX_OPEN_TRADES_PER_USER=

If these secrets do not exist, create clear missing-secret status messages in the admin/operator dashboard, but do not crash the app.

Live shared-account mode requirements:

1. Global mode
Set the app’s active trading mode to:
- Live trading
- Shared account
- Master bridge execution

The app should no longer require each user to connect their own MT5 account when shared-account mode is enabled.

2. Live account connection
Update the backend bridge connection layer so the live shared MT5 account is loaded from environment secrets.

Create or update a service similar to:
- sharedLiveAccountService
- masterBridgeService
- mt5LiveBridgeService

It should:
- Connect to the existing MT5 bridge using the shared live account credentials.
- Verify heartbeat.
- Verify account info.
- Verify balance/equity/margin/free margin.
- Verify trading permissions.
- Verify broker/server name.
- Verify symbol availability.
- Verify order placement endpoint availability.
- Verify order close/modify endpoint availability.
- Show connection status in admin dashboard.

Keep admin access role-based through the existing login system. Do not create a separate admin login page.

9. Ruby live trading
Update Ruby so she understands live shared-account mode.

Ruby should be able to answer:
- Are we connected to live?
- Is the shared account active?
- Which users are approved?
- What trades are open?
- What is my current P/L?
- Should I close this trade?
- Is this a pullback, retracement, continuation, or fakeout?
- Where should SL/TP be based on the current market?
- What is the risk/reward?
- Is the bridge healthy?

Ruby can suggest live trades only if:

14. Order dry-validation endpoint
Create or update:

POST /api/trades/live-shared/validate

This validates a live order before sending it.

Return:
- approved true/false
- errors
- warnings
- adjustedStopLoss if broker stop-level requires more distance
- marginEstimate
- riskEstimate
- rewardEstimate
- finalOrderPayload

- user approval passes
- global shared live enabled
- master bridge enabled
- kill switch off
- confirmation included
- bridge connected
