Run a dedicated end-to-end governance and AI-layer involvement test for the ARX AI Agent Ecosystem.

This is not a visual-only QA. The purpose is to prove the new AI governance layer is actually active, purposeful, connected to app actions, and influencing decisions where appropriate.

Do not just confirm that agent records, pages, or database tables exist. Prove that the agents are involved in real app workflows and that their outputs affect scanner decisions, Ruby responses, risk downgrades, trade/no-trade recommendations, speed routing, learning records, and admin visibility.

Do not rebuild the app. Do not remove existing features. Do not introduce paper trading or simulation as a product feature. Do not block the existing live-trading mission. This is a test, repair, and integration pass for the new governance/AI layer.

============================================================
PRIMARY OBJECTIVE

Verify that the AI governance layer is not decorative.

Confirm that each governance component has a real purpose and is called during the correct app actions:

1. Ruby
2. Market Structure AI
3. Scalp AI
4. Risk AI
5. Entry Timing AI
6. Exit / TP AI
7. Scanner AI
8. Trade Review AI
9. Agent Traffic Controller AI
10. Agent Immune System AI
11. Learning Camp AI
12. Agent Factory AI
13. Promotion Board AI
14. Execution AI
15. Agent Court
16. Truth-locked prediction journal
17. No-trade reward system
18. Agent speed/step-back system
19. Daily Household Report
20. Admin governance controls

Every agent must either:

* actively participate in the correct workflow,
* step back intentionally because it is not needed,
* run in background mode when appropriate,
* or be marked as unavailable/not yet implemented with a specific fix plan.

No agent should exist with no purpose, no route, no service call, no logs, no database activity, and no effect on the app.

============================================================
ABSOLUTE RULES

1. Do not claim an agent is functional just because it exists in the database.
2. Do not claim a page works if it uses hardcoded/fake data.
3. Do not claim governance works unless it changes routing, scoring, Ruby wording, scanner ranking, risk decisions, admin state, or stored records.
4. Do not allow every agent to run on every action.
5. Do not let deep governance slow live execution.
6. Do not let new or shadow agents influence live trade recommendations.
7. Do not allow Agent Factory, Learning Camp, Promotion Board, or Household Reports to run during live execution actions.
8. Do not ignore broken or missing integrations.
9. If an agent exists but is not connected, connect it or mark it clearly as not built.
10. If an agent slows the app without value, make it step back and log why.
11. Ruby must remain the clean user-facing voice.

    Slow agent steps back and scanner/Ruby gets faster or avoids extra delay.

If the governance layer does not change any decisions, routing, scoring, state, or logs, it is not functional. Fix it.
