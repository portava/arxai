PHASE 2 — ADD TAKE PROFIT OUTPUT MODEL
==================================================

Add a consistent Take Profit target model.

Each recommendation should support:

takeProfitTargets: [
  {
    label: "TP1",
    price: number,
    reason: string,
    rr: number,
    distancePoints: number,
    distancePips: number,
    suggestedAction: "partial" | "full" | "runner",
    confidence: "low" | "medium" | "high"
  }
]

Recommended structure:

TP1:
- Conservative target
- Nearest liquidity, structure level, support/resistance, VWAP/EMA reaction, or 1R area
- Usually suggested for partial profit or risk reduction

TP2:
- Main target
- Stronger structure/liquidity zone or 2R area
- Usually suggested as primary take-profit target

TP3:
- Extended/runner target
- Higher-risk target based on continuation, trend extension, ATR projection, or liquidity sweep
- Should be optional and clearly marked as lower certainty if appropriate

If only one reliable target exists, return only one.
If no reliable target exists, return:
“Take Profit unavailable — insufficient market structure/data.”

Do not invent prices.

==================================================
PHASE 4 — TAKE PROFIT CALCULATION LOGIC
==================================================

Use available data only.

Take Profit targets may be calculated from:

1. Support/resistance
2. Recent swing high / swing low
3. Liquidity zones
4. ATR projection
5. Risk multiples:
   - 1R
   - 1.5R
   - 2R
   - 3R
6. Fibonacci levels if already available
7. Session high/low if already available
8. Previous day high/low if already available
9. Scanner/radar levels if already available
10. Order book/liquidity data only if actually available

If live data is missing:
- Do not fake levels.
- Use preview-only estimates only if clearly labeled.
- Otherwise return “insufficient data.”

For BUY:
- TP levels must be above entry.
- SL must be below entry.

For SELL:
- TP levels must be below entry.
- SL must be above entry.

Backend must validate TP direction before showing/applying recommendation.

==================================================
PHASE 5 — RISK / REWARD INTEGRATION
==================================================

Every recommended TP should include risk/reward.

Calculate:

- Risk per unit = abs(entry - stopLoss)
- Reward per target = abs(takeProfit - entry)
- RR = reward / risk

If SL is missing, do not calculate RR.
Instead return:
“Risk/reward unavailable because Stop Loss/invalidation is missing.”

If RR is below the user’s minimum risk/reward setting:
- Warn clearly.
- Do not label it as a strong setup.

Risk governor should remain the authority before any trade is placed.
