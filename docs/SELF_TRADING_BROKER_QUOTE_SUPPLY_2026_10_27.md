# Do the supported EAs supply the entry claim's broker-quote facts? — 2026-10-27

The final entry claim (`SELF_TRADING_FRESH_FACTS_2026_10_27.md`) needs, for the command's symbol, a per-symbol broker quote not older than 5 s and the broker's `SYMBOL_POINT`. The owner asked whether the EAs the server treats as supported actually supply those two facts. This document records what the EA sources and the server ingest path say, what was wrong on the server side, what changed, and what still has to be done by an operator. Trading stays disabled; no EA file, broker, worker, schema or existing database was touched. Every cite was re-read on the merged base `444e726` plus this slice.

## Server-side writers and readers (re-verified on the merged base)

- The only live writer of the `mt5_broker` quote store is bridge v2 TICK: `routes/bridgeV2.ts:44-51` (`bridgeAuthPerUserOnly`, `userId = conn.userId`, `bridgeConnectionId = conn.id`) → `lib/bridgeV2/ingest.ts` → `feedMarketDataStore` after the trace row commits (`:229-236`). `/api/mt5/sync-quotes` (`routes/mt5.ts`) has no EA caller.
- Spec writers: `/mt5/sync-symbol-specs` (`routes/mt5.ts:2068-2101`, v1.28–1.31) and the `ENUMERATE_SYMBOLS` result (`routes/mt5.ts:1171-1239`, v1.50+). Both key by the broker-native name; the reader is an exact `(user_id, symbol)` match (`lib/mt5/brokerSymbolSpec.ts:57`, `point` at `:68`).

## What was wrong before this slice, and what changed

## What an operator must do for agent entries on a v1.54 bridge

1. Set the EA input `CandleSymbols` to the **broker-native** names of every symbol the agent may trade (e.g. `EURUSD.r,XAUUSD.r`), at most 40. The default streams the chart symbol only.
2. Keep `StreamLiveBrokerData` and `EnableLiveTickStream` at their defaults (true).
3. Run symbol sync (the `ENUMERATE_SYMBOLS` command from the symbol-sync UI) once per account so `arx_symbol_specs` holds `point` under the same broker-native names. Nothing on the server does this automatically.
4. Make sure the `symbols` registry maps each ARX-internal command symbol to that broker name (`brokerSymbol`), otherwise the resolver passes the internal name through verbatim and both reads miss.

On a v1.31 bridge no configuration makes agent entries pass; the kit does not stream quotes. Every refusal is recorded with the EA version and the reason.

## Not verified

- The actual trade-server offsets of the production broker accounts, and whether any operator has set `CandleSymbols`. Both default to the refusing side; the offset is now recorded per claim as `brokerClockOffsetMs`.
- `TimeGMT()` depends on the terminal PC's clock. A PC more than 5 s fast refuses `ENTRY_FRESH_QUOTE_FUTURE_DATED`; more than 5 s slow refuses `_QUOTE_STALE`. That is a real clock problem and is left as a refusal.
- `eaCreatedAtEpochMs` has 1 s resolution (`TimeGMT()*1000`), so a quote can appear up to 1 s older than the tick, and the recorded offset jitters by up to 1 s. Inside the 5 s window; not corrected.
- No live or demo EA was run; everything above is from the EA sources and offline/disposable tests.
