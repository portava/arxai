# Do the supported EAs supply the entry claim's broker-quote facts? — 2026-10-27

The final entry claim (`SELF_TRADING_FRESH_FACTS_2026_10_27.md`) needs, for the command's symbol, a per-symbol broker quote not older than 5 s and the broker's `SYMBOL_POINT`. The owner asked whether the EAs the server treats as supported actually supply those two facts. This document records what the EA sources and the server ingest path say, what was wrong on the server side, what changed, and what still has to be done by an operator. Trading stays disabled; no EA file, broker, worker, schema or existing database was touched. Every cite was re-read on the merged base `444e726` plus this slice.

## Server-side writers and readers (re-verified on the merged base)

- The only live writer of the `mt5_broker` quote store is bridge v2 TICK: `routes/bridgeV2.ts:44-51` (`bridgeAuthPerUserOnly`, `userId = conn.userId`, `bridgeConnectionId = conn.id`) → `lib/bridgeV2/ingest.ts` → `feedMarketDataStore` after the trace row commits (`:229-236`). `/api/mt5/sync-quotes` (`routes/mt5.ts`) has no EA caller.
- Spec writers: `/mt5/sync-symbol-specs` (`routes/mt5.ts:2068-2101`, v1.28–1.31) and the `ENUMERATE_SYMBOLS` result (`routes/mt5.ts:1171-1239`, v1.50+). Both key by the broker-native name **under the pushing bridge's owner** (`connUserId` at `:2077`, `conn.userId` at `:1223`); the reader is an exact `(user_id, symbol)` match (`lib/mt5/brokerSymbolSpec.ts:57`, `point` at `:68`). The observer therefore reads the spec under the dispatch bridge's owner (`bridge.userId`), which in `SHARED_MASTER_MT5` mode is the master account, not the follower whose command it is (finding 6 below).
- The quote store stamps a tick at the EA time it was **first seen** in the pushing bridge's partition and keeps that stamp across identical re-posts (`mt5Provider.ts recordMt5Tick`); the EA's previous post is recorded as the bound on when the tick can have occurred (finding 5 below).
- Still writing the unattributed partition: bridge v2 CANDLE (`ingest.ts` calls `mergeCandleFromMT5(symbol, candle, timeframe)` without the bridge it has in hand — pre-existing, outside this slice, recorded under "Open") and the legacy `/api/mt5/sync-quotes` route (no EA caller). Neither is served to a bridge-scoped read.

## Open (verified, not changed here)

- **Forming-bar "market frozen" indicator judges the broker-local tick clock against server wall time** (`lib/data/chart/formingBarComposer.ts getFeedFreshness`, `brokerStaleMs = max(0, nowWallMs − brokerTimeMs)`): on a GMT+3 server it clamps to 0 so `marketFrozen` can never be true; on a negative-offset server it is true while ticks arrive. Pre-existing; display/telemetry only (never a gate); the composer keeps the broker clock on purpose so the forming bar buckets with the stored bars. Fixing it needs a separate UTC observation time threaded into the composer. Other unscoped `quote.timestamp` readers (`scannerInputIntegrity.ts`, `executionPreviewService.ts`, `marketDataService.ts`, `tradeEngine/marketQuote.ts`) now get the first-sight UTC stamp, which also stops a re-posted frozen tick from reading as fresh to them.
- **Bridge v2 CANDLE still lands in the unattributed candle partition** (`ingest.ts` passes no bridge to `mergeCandleFromMT5` although it has one): pre-existing, outside the quote slice; attributing it would change what `marketDataRouter`'s bridge-scoped candle read serves and needs its own test.
- **The `TimeGMT()` → `TimeCurrent()` fallback in `V2NowEpochMs`** cannot be fixed or detected server-side (EA file owned by another team). It fails closed on every non-GMT+0 server (refusal inside the existing window) and is now stated in `ingest.ts` and above.

## What an operator must do for agent entries on a v1.54 bridge

1. Set the EA input `CandleSymbols` to the **broker-native** names of every symbol the agent may trade (e.g. `EURUSD.r,XAUUSD.r`), at most 40. The default streams the chart symbol only.
2. Keep `StreamLiveBrokerData` and `EnableLiveTickStream` at their defaults (true).
3. Run symbol sync (the `ENUMERATE_SYMBOLS` command from the symbol-sync UI) once per account so `arx_symbol_specs` holds `point` under the same broker-native names. Nothing on the server does this automatically.
4. Make sure the `symbols` registry maps each ARX-internal command symbol to that broker name (`brokerSymbol`), otherwise the resolver passes the internal name through verbatim and both reads miss.

On a v1.31 bridge no configuration makes agent entries pass; the kit does not stream quotes. Every refusal is recorded with the EA version and the reason.

## Not verified

- The actual trade-server offsets of the production broker accounts, and whether any operator has set `CandleSymbols`. Both default to the refusing side; the offset is now recorded per claim as `brokerClockOffsetMs`.
- `TimeGMT()` depends on the terminal PC's clock. A PC more than 5 s fast refuses `ENTRY_FRESH_QUOTE_FUTURE_DATED`; more than 5 s slow refuses `_QUOTE_STALE`. That is a real clock problem and is left as a refusal.
- `eaCreatedAtEpochMs` has 1 s resolution (`TimeGMT()*1000`), so a quote can appear up to 1 s older than the tick, and the recorded offset jitters by up to 1 s. Inside the 5 s window; not corrected.
- The first-sight time under-states a tick's true age by at most the feed gap before it (bounded to 5 s), so an accepted tick is at most `quoteAgeMs + quoteFeedGapMs` ≤ 10 s old, typically within one 2 s sweep of `quoteAgeMs`. The server cannot do better without estimating the broker's UTC offset, which it deliberately does not.
- Whether `TimeGMT()` ever returns 0 on a production terminal (the `TimeCurrent()` fallback) — not observable from the server; it refuses in that state on non-GMT+0 servers.
- Whether the master account in `SHARED_MASTER_MT5` deployments has run symbol sync (its spec rows are now the ones followers' entries read).
- No live or demo EA was run; everything above is from the EA sources and offline/disposable tests.
