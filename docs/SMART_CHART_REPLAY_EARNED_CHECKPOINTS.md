# Replay earned study checkpoints

This slice reuses only study checkpoints that this active Replay session has already calculated. It never passes unrevealed candles to a study, the reader or the chart. Initial visits still calculate the revealed prefix; an earned return to the same prefix can restore exact existing values.

The explicit Replay context includes owner, session, source, opaque source identity, instrument and timeframe. Each study also compares a serialized configuration and private copies of every used input field: time, open, high, low and close. A changed input discards all descendants. A changed context or configuration starts over. The current 17 OHLC studies opt in explicitly; a future volume-dependent study must extend the identity contract before reuse is allowed.

Only the active prefix appears in public points or active calculation states. The packed successor stores private Float64 copies of time/OHLC inputs and normalized output channels, preserving signed zero and representing null output channels with NaN. It creates immutable cached point objects on the first rewind, after truncating active points and states. Initial public point mutation cannot change those private numeric records. A correction clears discarded numeric records before reusing capacity. The renderer, inspection API and reader do not enumerate the private suffix. Rewinding removes future price/study time coordinates using the existing whitespace-safe chart reconciliation. No live/native calculation uses this cache. Native no-op reads, source changes, streaming updates, reset, study removal and chart destruction discard it.

Retention is bounded by the active Replay session and existing limits of 12 studies and 5,000 candles. A local Node V8 heap-plus-ArrayBuffer probe using 12 MACD studies (three average states and three output channels) measured 37.88 MiB for the packed first reveal versus 33.29 MiB for native full-prefix state. First rewind retained 39.42 MiB privately; native clearing and disposal returned within 19 KiB of the module baseline. This includes numeric backing stores but excludes browser/canvas/GPU memory and is not a universal memory bound.

The earlier cache checkpoint passed 1,636 frontend tests with nine optional live checks skipped, four typecheck units, 87 guards and seven structural guard assertions. The packed successor passes its focused suite, UI typecheck and production build; the installed Lightweight Charts 5.2 library passes 384 series/channel comparisons and 272 time-axis/future-inspection cases across all 17 studies. Exact full-recomputation tests cover warmup whitespace, empty prefixes, signed zero/null/nonfinite channels, same-close high/low/open/time changes, repeated corrections after rewind and subsequent growth, prepends, mutable caller inputs/outputs, configuration and every context field. These scopes are recorded separately in the external evidence receipt.

The earlier object-copy/freeze cache is held, not approved for integration: forty fresh sessions showed CPU4 first-reveal second-frame p95 worsening from 162.7 ms to 217.2 ms. Its two warm trials also missed the 100 ms following-display target. All raw samples and failed acceptance remain frozen in the earned-checkpoints receipt. Performance acceptance of this packed successor is pending on the same full combined 65-name catalogue/descriptive-reader workload. Cold first reveal, the first rewind that prepares immutable objects, and earned warm visits must be measured separately. There is no current claim of 100 ms completion, physical-paint timing, 60 fps or competitor parity.
