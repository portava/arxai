# Smart Chart candle catalogue v4: four- and five-candle continuation shapes

This document records the frozen v4 checkpoint. For the next version see [v5 definitions and evidence](SMART_CHART_CANDLE_CATALOGUE_V5.md).

`arx-candle-geometry-v4` adds 9 named observations to the v3 checkpoint. There are now 71 catalogue definitions in 19 shared geometry families. With three preserved initial-core names, 74 of the owner's 104 entries have implementations and focused fixtures; the other 30 remain in `SMART_CHART_CANDLE_COVERAGE.json`. These are named coverage counts, not independent signals, predictive reliability, application completion or parity with another chart product. No competitive scorecard row changes status; the scorecard has no candlestick-detection row.

All new findings remain **observed**, with the ending candle's actual close time. They keep the existing source/symbol/timeframe/opaque-identity validation, explicit finality, chronological unique bars, interval checks, causal observation time, the 600-bar model cap and 12 recent endpoints. The scanner gains a 4-candle window (`contiguous(closed,i-3,i)`) and a 5-candle window (`contiguous(closed,i-4,i)`); neither reads before index 0 or across a missing interval. Prior trends use the existing five-close guard and exclude the entire formation. No confidence percentage, inferred future candle, prediction, execution instruction or confirmation status is added.

## Definitions and differences

ARX applies explicit versioned conventions rather than claiming TA-Lib numerical parity. Means use the prior ten closed bars excluding the candle being evaluated. "Long" is a body above that mean (TA-Lib BodyLong). "Short" reuses the existing ARX short-body rule: a positive body below **half** the prior-10 mean body, stricter than TA-Lib BodyShort (below the 10-bar mean). The ARX "near" analogue is 0.25 × the prior-10 mean range and the "equal" analogue is 0.05 × the prior-10 mean range, as in the existing Tasuki Gap, Matching Low and Separating Lines rules; TA-Lib uses 0.2 and 0.05 × the 5-bar mean. ARX colour is strict (close above or below open); TA-Lib counts close ≥ open as white. Every ARX name here requires a measured prior trend by ARX convention; no TA-Lib file checks trend. Relative `1e-12` comparisons keep boundaries scale-invariant.

### Three-Line Strike and the core Engulfing label

The core Engulfing detector can fire on the same strike candle with the opposite direction label. In the bullish fixture, the final two candles also form a core Bearish Engulfing (status **confirmed**), because the strike body covers the third body and the third close is above the close just before the formation (the core four-bar prior-rise rule). Both findings share an observation time, and summary ranking orders ties on one bar by status, then scale, then id. If Three-Line Strike shared the `engulfing` family, the confirmed core finding would always take that slot and the strike would never appear in the summary. Three-Line Strike therefore has its own `three_line_strike` family, and both findings can appear side by side. The integration test records the fixture summary as `trendline_break`, the core Engulfing, then the strike.

The same tie-break can still push a strike into details. If the strike candle is also a Marubozu or Belt Hold, an alphabetically earlier same-bar id (for example `bearish_belt_hold` before `bullish_three_line_strike`) can take the last slot, as for any catalogue name. A variant test records this: the bullish marubozu-strike variant is in details only, while its mirror stays in the summary. The global ranking is unchanged, because changing it would reorder every existing summary.

### Why each family

- `three_methods` (new): Rising/Falling Three Methods and Mat Hold share the long-body, short-reaction, resumption outline.
- `three_line_strike` (new): kept separate so the same-bar core Engulfing, which carries the opposite label, cannot hide it.
- `tasuki_gap`: Gap Three Methods shares the body-gap-then-opposite-candle outline. It cannot co-match Tasuki, which requires the close to stay inside the gap.
- `side_by_side` (new): the two white lines are a distinct paired-after-gap outline.

## Validation and timing

Each new name has a positive fixture, a flat negative control, tiny/large price-scale checks, incomplete-candle and future-prefix controls, a trend-context control, and an internal-gap control. Near misses check reaction containment, strict final closes, strike engulfment, the near-open tolerance, gap fill and colour, the side-by-side open and length tolerances, and Mat Hold versus Rising Three Methods in both directions. Every near-miss fixture is asserted to be valid closed evidence, so a rejection never comes from an unavailable scan. A bookkeeping test computes every coverage count from the JSON and the code.

The v5 document's review follow-up lists the one-predicate near misses and window tests later added for these nine shapes, and the corrected Three Methods wording. Its correction paragraph records that the first follow-up did not pin every criterion. Its section "What the mutation runs cover" states which mutation classes were run, what each enumerated, the counts and the mutants known to pass; nothing beyond that is claimed here. For the nine v4 shapes, these operand deletions still pass `test:candlestick-catalogue`, one at a time:
- the `isShortAt` mean null check, which feeds the Three Methods and Mat Hold short-reaction rule;
- the six Gap Three Methods colour checks;
- the Three-Line Strike strike colour, on each side;
- the window guards `i>=3` and `i>=4`;
- the rising-shape check inside Rising Three Methods;
- the Three-Line Strike `n2` null check.

All but the last are equivalent, for the reasons v5 gives. The `n2` deletion is not: v5 records a subnormal-price input on which it emits a strike that the shipped rule does not. Operand deletion is only one mutation class. Comparison flips at exact ties, constant changes and window shifts are covered only where v5 says so. Of those, all four Three-Line Strike open-tolerance comparisons can be made strict without a test failing, and the .25 × prior-10 mean range on the second open can be raised by 10% on both bounds. "(inclusive)" in the table above is the shipped rule, but no test holds it at an exact tie. The Side-by-Side "both later candles white" rule (TA-Lib column) is now pinned on the third line as well as the middle line.

The CI-wired `test:candlestick-catalogue`, `test:smart-chart-analysis` and `test:smart-chart-reader` scripts and the workspace typecheck pass for this commit (results in the commit message).

The paired computation harness now snapshots the previous **model and 62-definition catalogue** from `e90081e`. Its `smartChartAnalysis.ts` predates `4d7d3b3`, so the old side also runs the older model; a second run with this commit's parent as `argv[2]` isolates the catalogue change. The budgets stay at model and bind-plus-model p95 ≤10 ms and p99 ≤20 ms. The fixture-batch operation is now `all_positive_fixtures_one_batch` and reports `fixtureCount`; at 71 fixtures its absolute time is not comparable to the 62-fixture row in `SMART_CHART_CANDLE_CATALOGUE_V3.md`.

**Timing has not been measured for v4.** The shared host was running a separate latency benchmark when this commit was made, so a trial would have disturbed that run and given unreliable numbers. When the benchmark runs on a quiet host, it must record the host, the Node version and the UTC window, and compare against the timing table in `SMART_CHART_CANDLE_CATALOGUE_V3.md` without any speedup claim. Until then, no v4 latency figure exists.
