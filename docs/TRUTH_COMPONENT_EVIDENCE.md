# Truth component evidence

## Problem and result

A fresh Truth snapshot previously accepted a Ruby setup whose lifecycle was already `EXPIRED`, and timing could label yesterday's fallback candles and quote as real merely because it had just recalculated. With a current chart, either could yield `BUY`. A third path allowed a directional timing vote to produce `BUY` when every entry/stop/target was absent.

The production-composer replay in `scripts/qa/truth-evidence-benchmark.mjs` reproduces all three on base `cc8f6727`. With this change, all three produce `WATCH_ONLY`; expired/mismatched components cannot donate levels or evidence. These are advisory reads. Execution, arm, kill, broker and account permission gates remain independent.

## Contract

`marketEvidence` is additive on chart, Ruby, timing and scalp results. It records the canonical symbol, requested timeframe, identified source, an opaque digest of observed router provenance and the newest accepted closed bar's close time. Ruby/scalp also identify the user whose account-dependent evaluation ran. The digest binds provider, sub-provider, series, observed bridge/owner, environment and native-symbol facts; it does not contain raw identifiers or guess absent facts.

The actual producer validates and normalizes its own candles before dropping their timestamps. Forming bars are excluded from analysis and sufficiency. Scanner inputs reused by Ruby/scalp must share the actual source digest and the existing feature snapshot's closed-bar observation, plus symbol/timeframe and a current calculation time. A separately routed quote must match all observed attribution fields, have a current timestamp and carry a real positive spread. No price or spread is synthesized.

The Truth composer accepts a component only when its symbol/timeframe/source identity/closed observation match the chart evidence. Account-dependent components must match the requesting user. Expired, invalid or stale Ruby lifecycle evidence cannot vote. Component `asOf` now describes its confirmed bar; `generatedAt` separately describes computation.

A component calculation has at most 30 seconds of advice lifetime, matching the UI's existing two normal 15-second polls. This is a bounded advice policy, not a quote freshness threshold. Existing quote freshness remains separate. The last closed observation must still be within its timeframe's current interval. Closed-market bars remain chart/history context; they cannot become current votes because a response was rebuilt.

Scalp/flame genuinely use M5. They are not votes on an M15/H1/etc. snapshot, and they are not supplied as same-timeframe corroboration to those Ruby builds. The snapshot labels the withheld M5 context explicitly. On M5, matching valid inputs can still vote.

Entry advice requires finite positive, complete entry/stop/target geometry. Stops and supplied invalidation must be on the protective side of the entire entry zone; targets must be on the reward side. Missing, reversed, nonfinite or inconsistent geometry is withheld. Directional context can remain visible with `WATCH_ONLY`.

`validUntil` is the earliest accepted component expiry, build-time horizon or next expected closed-bar boundary. A post-cache cap withdraws expired evidence without refetch fan-out or timestamp refresh. The frontend uses the earlier of this validated deadline and its existing 30-second horizon; malformed supplied deadlines withdraw advice. Older servers without the optional field retain the existing client cap. The existing deadline timer handles expiry and focus/visibility resumption; no interval polling loop was added.

A direction is not an edge (2026-10-27): the Ruby market-edge component sets `belowEvidenceFloor` when its own minimum-evidence rule failed (fail closed when the evidence ledger is missing) and its label says "Bullish lean · Setup forming". `composeVerdict` sets `verdict.biasQualifier: "LEAN"` when every present voter for the bias is below its rule; flame/timing/scalp have no such rule, so a second independent voter clears it. The vote and stage are unchanged. The scanner header renders "Bullish lean" in a secondary tone; an older server without the field renders unqualified. Follow-up not changed here: `biasToActionDirection(verdict.bias)` in `ScannerHeaderSummary.tsx` and `ScannerChartPanel.tsx` still names a plan direction for a LEAN read when actionability is wait-for-confirmation.

A provider's current bar can have a scheduled future `closeTime`. That is not rejected as a future observation or counted as final. `feedStatus.lastCandleTime` keeps its existing wire meaning, while `marketEvidence.lastClosedCandleAt` explicitly describes the preceding accepted closed bar.

## Review corrections: patterns and durable continuity

The scalp focus producer now takes pattern impact only from the same scanner row that passed source/bar checks. Downgrade-only pattern evidence is still a factual claim about a market; a rejected provider's pattern must not change the selected market's quality or labels through an independent engine input.

Ruby's prior `signal_memory` lookup was scoped by user/symbol/timeframe but had no provider identity. That allowed a different source's old `firstSeenAt` to control the current lifecycle and what-changed diff. The service now waits for actual routed provenance, then looks up a private storage key: `source-v1:[canonical timeframe, provider, opaque source identity]`. The existing `timeframe` database column is unrestricted text and is used only by this service; the schema comment documents its private key meaning. Public responses keep the canonical timeframe. The composite user/symbol/key constraint isolates provider, bridge, environment and native-symbol context durably across processes. Legacy bare-timeframe rows are preserved as history and never reused as source-bound lifecycle evidence. No migration runs.

Same-source reads retain persisted age, including expired age when returning after a source switch. Invalid/future memory dates cannot establish continuity. A new context's first observation is not proof of when a setup formed. The additive `continuity` metadata distinguishes source-bound prior memory from the current observation and reports whether this request actually saved it. Read-only Truth polls and failed writes never claim a saved observation. Persistence remains best effort; this patch does not invent durable continuity where none exists.

Review acceptance: a rejected source's pattern cannot reach the scalp engine, no user/provider/bridge/symbol/timeframe switch inherits the old lifecycle, same-source expiry survives real PostgreSQL reads, legacy history remains unchanged, and read-only/failed persistence reports no save. The comparative local Ruby-service plus PostgreSQL fixture has a completed-service p95 budget of 10 ms and an added p95 budget of 3 ms. It measures the new sequential dependency explicitly; provider lookup latency and competitor broker latency remain unmeasured. Actual producer baseline probes, disposable-database tests and timing results are saved in the review supplement receipt.

The follow-up's actual Ruby service plus local PostgreSQL benchmark used 80 bars, 50 warmups and 500 samples per version. Previous completed-service median/p95/p99 was **0.576/0.783/1.081 ms**; updated was **0.491/0.636/0.773 ms**. Invocation return was **0.027/0.047/0.068 ms** versus **0.009/0.017/0.032 ms**. Both meet the local budget. These sequential in-process samples with immediate provider stand-ins do not establish a speed improvement; in production the new source-scoped database lookup necessarily waits for routing. The initial PostgreSQL runner passed assertions but retained imported background handles; adding the existing test-force-exit discipline produced a clean 10/10 run and removed the disposable cluster.

## Research and comparison

Checked official documentation on 2026-10-26:

- [TradingView repainting](https://www.tradingview.com/pine-script-docs/concepts/repainting/) distinguishes changing realtime-bar calculations from confirmed historical evidence. ARX now excludes unfinished bars from the component evidence used here; this is a correctness comparison, not a claim that all TradingView studies behave identically.
- [TradingView other timeframes and data](https://www.tradingview.com/pine-script-docs/concepts/other-timeframes-and-data/) makes requested symbol/timeframe context explicit and explains unconfirmed higher-timeframe behavior. ARX binds component context instead of recasting an M5 scalp as an M15 vote.
- [MQL5 CopyRates](https://www.mql5.com/en/docs/series/copyrates) specifies symbol/period and identifies position zero as the current unfinished bar. ARX's observation contract likewise distinguishes a scheduled close from confirmed completion.
- [MQL5 SymbolInfoTick](https://www.mql5.com/en/docs/marketinformation/symbolinfotick) carries the symbol's tick time. [MQL5 TimeCurrent](https://www.mql5.com/en/docs/dateandtime/timecurrent) explains that general server time can be the last quote time across Market Watch. ARX never substitutes calculation time or general activity for a component's observed bar or quote timestamp.

No TradingView/MT5 latency benchmark was run, and no speed or feature parity is claimed.

Source/bridge/user/timeframe/bar mismatch, missing provenance, malformed input, future/stale calculation time, forming bars and deadline boundaries must fail conservatively. Existing scanner/scalp/chart behavior outside those cases must retain passing regression coverage.

## Remaining limits

- Quote attribution (2026-10-27): the MT5 quote store is now partitioned by the authenticated bridge like candle series, and every authenticated MT5 producer threads its writer identity (`/mt5/sync-quotes`, `/mt5/sync-candles`, `/mt5/sync-candle-history` and bridge v2 TICK/CANDLE with a bridge connection; `/mt5/candles/ingest` already did). `routeQuote` therefore reports the serving writer's bridge/user, and a same-bridge quote can satisfy the existing Ruby/scalp/timing quote match. `MarketQuoteResult.tickTimeObserved` is additive: true only for a producer tick time (MT5 EA timestamp or v2 `brokerTimeEpochMs`, Deriv tick epoch, provider `asOf`). An MT5 v1 quote pushed without a timestamp is stored with receive time and `tickTimeObserved: false`; `matchedMarketQuote` refuses it and any result without the flag. Proven locally: real store → router → `matchedMarketQuote` and the real timing producer (`quoteAttribution.test.ts`), plus in-process endpoint and bridge v2 ingest assertions against a disposable PostgreSQL.
- Still open for quotes: broker-native symbol and account environment are not observed on the quote or live candle push paths and stay null/`unknown`. MT5 tick times are compared with server time as supplied by the EA; an EA that sends broker-server-local time will read as future/stale and be withheld. Legacy unattributed writers stay unattributed and cannot price an attributed series.
- Quote pinning (review follow-up, 2026-10-27): with several v1 EAs on one symbol, candle and quote reads used to pick writers independently. Candles came from the most recent candle writer and the quote from the most recent quote writer, so the quote match was usually null. Truth consumers now route the quote after the candles and pin it to the served series' MT5 writer with `routeQuote(symbol, quotePinForSeries(candles))`. The consumers are the timing brain, scalp focus inputs, Ruby `buildSignal`, scanner `analyzeViaRouter` and opportunity-map lateness. `bridgeConnectionId: null` pins to the unattributed partition. A pinned read serves only that writer's quote. It never falls back to another bridge or another provider, and a miss reports `MT5_WRITER_QUOTE_MISSING`. Durable-mirror and non-MT5 series stay unpinned, and the existing identity checks still refuse any mismatch. Candle and quote lookups for these consumers are now sequential, not parallel. Tests are in `quoteAttribution.test.ts`: multi-bridge pairing, pinned miss, unattributed pin, and the real timing and scalp producers. The `MULTI_BRIDGE_CONTENTION` warn is quieter, because several users on one symbol is now a normal state. It fires when a symbol's contending bridge set is first seen or changes (at most hourly), and repeats for an unchanged set at most once a day. The per-read flag and router note are unchanged.
- v1 candle window merge (review follow-up, 2026-10-27): attributing `/mt5/sync-candles` put its rolling window into the same per-bridge partition that `/mt5/candles/ingest`, v2 CANDLE and `/mt5/sync-candle-history` merge deeper bars into. `updateCandlesFromMT5` replaced the whole partition, so a short v1 push wiped that history. An attributed window now merges by bar instant: an upsert where the newer push wins, sorted ascending and capped at 1,500 bars like the other merge paths. Bars are validated by the route as before. Unattributed (legacy) writers keep replace semantics. Tests are in `bridgeScopedCandleServing.test.ts`, covering the merge, no truncation, no cross-bridge merge and unattributed replace. The DB-backed `mt5SyncCandlesEndpointTest` now expects the merged count. Limit: a bar the EA stops sending is not retracted from an attributed partition by a later window. For example, an EA whose time stamping changed leaves its old-stamped bars until they age out of the cap or the server restarts.
- This slice hardens scalp focus, the shared Ruby service and the Truth composition path. Legacy protective management input loaders and broad scalp ranking are not redesigned, and no terminal/session identity guarantee is added.
- A digest binds observed identity, not historical provenance that the serving layer does not know. Durable-mirror/unknown facts remain unknown. No execution feed is promoted from Deriv public analysis data.
- Local tests do not prove production feed availability, terminal behavior, provider latency, order execution or a completed Tier 1 score.
