# Profit Mission evidence boundary — 2026-10-26

Status: this bounded correction passed local validation and independent review. No competitor parity, profitability, live readiness, or overall completion claim.

## Baseline defects

At `cc8f67271b2d97e4d4e7cab8928f9980ca27942b`, the mission backtest runner generates prices from a seed and fixed January 2024 timestamp. A minimum sample plus positive gross expectancy/profit factor can mark this record verified and promotion-eligible. Reads trust stored labels and booleans. No observed-market provenance, costs or chronological holdout supports that claim. Forward aggregation accepts arbitrary display labels while aggregating all mission outcomes, does not prove execution mode/net costs, and can average R from only the subset with R. The current mission execution mode cannot prove historical execution mode.

End-of-run simulated exits are also converted to planned target R or a full stop even when the actual exit moved only partway. Drawdown uses the wrong denominator: starting capital for simulations and the final global peak for forward results.

## Acceptance for this bounded correction

1. No current generated-price, unknown legacy, or unreconciled-draft record can be marked verified, count toward promotion, or enter a strategy-drift baseline. Supported data producers are explicitly diagnostic; a future verified producer requires its own validated evidence contract. Existing mission levels are not silently changed by a read. Already-promoted missions and their stored live-auto opt-ins are not retroactively demoted by this patch; historical promotion-state remediation remains unresolved.
2. Preserve append-only stored history. Rebuild labels, sample counts and eligibility on read; ignore historical verified/eligible booleans. Invalid metrics remain unavailable as evidence.
3. Save deterministic run inputs, source classification, cost/holdout limitations and R coverage with new records. Incomplete R is labelled as an observed subset, with its numerator/denominator; no observations means unavailable, never an inferred zero. Do not infer live/demo history from the mission's present mode.
4. Exact forward selectors filter actual strategy, symbol and timeframe. Unfiltered mixed contexts are labelled Mixed. Preserve per-user/mission isolation.
5. Realised R uses actual exit P/L divided by initial stop risk. Maximum realised drawdown uses each contemporaneous peak. Generated P/L remains gross price units, not account money.
6. UI shows diagnostic records and reasons but withholds unverified comparison deltas, currency comparisons and baseline/trend claims. No empty-state instruction suggests generated prices will unlock verified evidence.
7. Real disposable PostgreSQL covers producer, persistence and consumer reads. Pure regressions cover malformed/legacy data and partial exits. Component tests cover visible disclosures. Types, guards and relevant builds pass.
8. Same-host baseline/current processing checks report median/p95/p99 with local processing p95 below100ms. These are CPU/service checks, not UI acknowledgement, hardware paint, broker execution latency or competitive speed proof. Keep failed runs.

## R expectancy sample interval — 2026-10-28

Scope: owner brief :43 (robustness; never claim proven returns) and the uncertainty item above. This section makes no profitability, edge or competitor claim. Whether TradingView or MT5 report expectancy intervals is unverified; the Smart Chart scorecard row for strategy testing is unchanged.

- Method: two-sided 95% Student t interval on observed R values, mean ± t(0.975, n−1)·s/√n (`summarizeRObservations`, `lib/domain/src/profit-mission/missionTestingLab.ts`). The quantile table is embedded (df 1–30, 40, 50, 60, 80, 100, 120, 200, 500, 1000); other degrees of freedom step down to the nearest tabulated row, which widens the interval. The fixed vector [1, −1, 2, −1, 1] gives mean 0.4, SD 1.341641, SE 0.6, t(4) 2.776445 and [−1.265867, 2.065867].
- Assumption: independent, identically distributed trade outcomes. Trade sequences are often serially correlated, so the interval can be too narrow. Every interval note says it is a sample interval, not a forecast; an interval that excludes 0R is explicitly not validation of an edge. Backtest notes say "(gross, before costs)"; forward notes say "(costs unverified)". No note uses "confidence" or "breakeven".
- Deliberate spec deviation: the item-9 spec says the interval is available for every n ≥ 2, but it also forbids a zero-width interval. Identical observed values (for example every trade at exactly +1R, reason `no_variation`, decided by value equality so that three 0.1R trades, whose float mean is off by an ulp, still read "all 3 observed R values equal 0.10R") and variation below the stored 6-decimal precision (reason `interval_below_precision`, including float-noise ties such as [1, 1+2⁻⁵², 1] and a standard deviation that rounds to 0) are therefore reported as unavailable. The record also carries `version`, `status`, `degreesOfFreedom`, `quantile` and `excludedCount` beyond the spec's keys. Non-finite inputs are rejected, never coerced to 0.
- Producers: the generated-price backtest passes only trades with finite positive initial stop risk and finite P/L; `excludedCount` covers both conditions. The closed-draft aggregate passes exactly the drafts with a finite recorded R. Both store `metricsJson.experiment.rStatistics`. `MissionTestMetrics`, the DTO keys and the OpenAPI schema are unchanged.
- Backtest headline: `expectancyR` still counts excluded trades as 0R (in tension with acceptance item 3 above; a separate follow-up). When trades are excluded, the note discloses "mean over N observed trades; K trades without positive stop distance excluded" and that the headline can differ from the interval mean.
- Reads: legacy rows, rows with unsupported provenance or invalid metrics, and records inconsistent with their own quantile, standard error, bounds, includesZero flag, engine, R coverage count or headline expectancy read "R uncertainty unavailable". A forward interval appears only when the R coverage count is valid and equals the record's n, so the coverage and uncertainty notes cannot disagree. These checks catch incoherent or edited records; they cannot detect a forged record that is fully self-consistent, because raw R values are not stored. If reading a stored record throws, that row reads the invalid-record note and the rest of `listMissionTestResults` is unaffected. The only writer of `mission_test_results` is `persistTestResult`.
- Pins (2026-10-28, corrected in the final round): earlier wording here and the commit title of 6a89c20 claimed that every named read check had a fixture only that check rejects. That was not true, and it is still not true for every check; the mutation summary below lists what is and is not covered. Tamper cases assert the exact invalid-record note rather than the shared "R uncertainty unavailable" prefix. Fixtures that only the named check rejects: forward n ≠ coverage with a correct excludedCount and the reverse; each of the five available statistics left unrounded, and an unrounded no_variation value; an SE consistent with the bounds but not with sampleSd/√n; the low bound and the high bound each shifted by 0.001; a mean below the low bound and a mean above the high bound; a sampleSd of 0 with an SE and bounds coherent with it; available records with n 1 and n 0 (the reader returns null without throwing, and a read that throws for any other reason gives that row the invalid note instead of failing the projection; in PostgreSQL a DB-edited n = 1 forward row is read next to a valid one); a forward headline 0.65R away from the record mean and one just outside the 1e-4 tolerance (+1.1e-4), with +9e-5 still available; a backtest mean that disagrees with the headline; and the reason/n mismatches insufficient with n 5 and interval_below_precision with n 1. The (2+q)·1e-6 bound tolerance is pinned from below only, by 400 seeded producer records (n 2–5, 7-decimal values), about a quarter of which deviate by more than a flat 2e-6 and must still read available. Every row of the t(0.975) table is compared with an independently computed reference list in the test (bisection on the t CDF via the regularized incomplete beta function; df 1 and 2 also against closed forms). Note text: the exact forward note is asserted in the unit and PostgreSQL forward tests, so the backtest-only "without positive stop distance … counts those trades as 0R" disclosure cannot appear on forward rows; the no_variation note prints 0.123457R for a stored 0.123457. Other fixtures pin an SD that rounds to 0 while the rounded bounds differ ([0, 4.9e-7]), rounded bounds that are equal although the SD is non-zero, and a bound exactly at 0R counting as including 0R. The PostgreSQL suite runs the real generated-price runner with exclusions (every second opened signal of the strategy gets an infinite stop on the correct side, which the simulator accepts; the note's "without positive stop distance" wording is loose for an infinite distance) and checks excludedCount > 0 and the disclosure.
